# 预览、验收与交付

## 按改动范围验证

先运行工程类型检查，再出受影响镜头的入场、稳定、退出和重叠帧。检查后生成完整预览；只看静帧不能证明连续运动自然。短片可完整观看，长片至少完整解码并观看所有改动段、接缝及声音变动处。没有实际听看就不要写“完整复听／观看通过”。

| 层次 | 检查内容 | 记录 |
|---|---|---|
| 文件与时基 | 实际宽高、fps、帧数、时长、音轨，完整解码 | ffprobe JSON、ffmpeg 错误日志 |
| 时间线 | 半开区间覆盖、转场占用、视频可用范围、音频尾部 | 起止帧及路由核查 |
| 文字 | 主次层级、对比、长英文换行、来源、字幕和主体互不遮挡 | 入／中／出帧及最拥挤帧 |
| 连续性 | 接缝位置、速度、动作相位、曝光；是否黑帧、重复和漏帧 | 接缝前后至少 0.5 秒，正常速度观看 |
| 机制 | 图形、公式、数据与旁白一致，实验状态真正更新 | 固定种子数据及对应帧 |
| 声音 | 专名、句尾、时序、配乐压低、AAC 真峰值 | 复听记录、最终 MP4 响度 |
| 证据 | 原论文页与目标、来源类型、年份、许可记录 | 原文 URL、哈希及定位检查图 |
| 品牌与论文 | 标志与片名同组，页面有清晰停留，淡出不露旧场景 | 连续帧及实际预览 |

| 公式与数学 | LaTeX 编译资产、维度／数值审计、结果先于口播 cue、项高亮与输出对应 | 编译日志、数学审计、公式导航、最终帧 |

缩略灰度检测只是筛查。128×72 的量化可能把静稳阅读时的微小变化判为重复；对候选回到原生分辨率 RGB 检查。重复也可能是有意停留，结合镜头设计判断，不能靠人为加噪声“通过测试”。亮度差或端点 RGB 相近不证明动作连贯。

## 随附检查工具

```powershell
python <skill>/scripts/inspect_preview.py --video <preview.mp4> --times 4 165.67 180 --seams 182.067 188.4 --out-dir <project>/output/review --decode --loudness
```

`--times` 为重点时刻（秒），`--seams` 自动展开接缝前后各 0.5、0.2 秒及中心。输出 `contact-sheet.jpg`、抽帧图和 `inspection.json`。工具检查可解码性和响度，不自动判定审美或口型，不伪造通过项。默认抽取均匀分布的八个时刻；输出目录已存在报告时需显式 `--overwrite`。

### 长片抽样边界

正式长片至少执行一次固定抽样：51 个内容／机制样帧和 30 个接缝样帧。内容样帧应覆盖公式阶段、最长字幕、论文聚焦、实验结果、片头与片尾；接缝样帧包含每处接缝的前后约 0.5 秒和中心帧。抽样结果须包含最终视频 SHA、帧号、时间、检查者和处理结论。若只做了机器抽样或局部观看，要如实写明范围；不能用抽样报告声称完整人工观看或完整复听。

最终成片发生任何时间修正后，不能沿用旧版 SHA 作为交付证据。可复用未变化的样本，但需写出新旧帧哈希对照；变化样本必须重新观看并重新绑定新 SHA。公式镜头尤其要复核 `resultCompleteFrame` 与实际口播 cue，避免“画面在算、声音已经报出结果”。

## 预览版本与 4K

每轮独立命名，保留上一个可回看的版本。当前系列先交付 1080p，由用户确认当前版本后生成 4K；这源于用户的预览偏好，不要求新项目都额外审批。只确认了旧版不等于批准新修改版。

4K 应重新渲染程序图形与文字；1080p 生成镜头放入 4K 合成不能称为全部原生 4K。实测输出帧数等于时间线总帧数；最终 AAC 编码后复测约 −14 LUFS、真峰值不高于 −1 dBTP。不要把无声局部 patch 误交成完整成片。

## 交付结构

以实际产物为准，不承诺未生成文件：

```text
project/
  src/                 Remotion 时间线、场景、主题数据
  manim/               使用过的技术动画源码
  scripts/             TTS、实验、素材处理、渲染、核验入口
  public/              字体、声音、视频、品牌、真实论文页
  research/            来源、PDF、实验数据、生成任务与费用记录
  docs/                旁白、分镜、六章目录、说明和重渲染方法
  output/              版本化预览／成片、字幕、实际检查结果
```

交付包排除 node_modules、虚拟环境、缓存、临时下载、凭据及不属于本任务的资产。保留 package-lock 和环境／模型版本说明，引用用户已有 TTS 环境而非擅自打包个人声音。对于可重新下载的大文件可给明确获取脚本与哈希，但不要假称素材已包含。

最终回复给出预览、核心改动和限制；说明 4K 是否待确认。机器检查通过与用户审美认可分开记录。若采用外部模型返回的部分代码或混合生成／程序桥接，交付记录写明真实采用范围，不写“外部模型独立完成”或“全 AI 生成”。

## 正式教学的分阶段完成条件

这些是内部质量检查，不另设用户审批关卡。

| 时机 | 必查项 | 发现问题后的处理 |
|---|---|---|
| 正式配音前 | 开场明确章名、计算机任务和核心技术；段落有因果；无制作思考口吻；实验结论由产物支持 | 先改稿，不先合成全片再修故事 |
| 批量动画前 | 一个机制样片有真实输入输出；字号、源标注、字幕、角标不互挡；关键节点读音已试听 | 修正通用组件或语音配置，再复制到其他镜头 |
| 每段渲染前 | 每句旁白对应对象和动作；场景分支实际命中；图片、概率和样本 ID 一致 | 逐句修阶段锚点，不能只对齐字幕 |
| 合成长片前 | 所有受影响接缝正常速度检查；长字幕和复合层最坏帧检查；片头尾无空等；句尾完整 | 修改后重渲染受影响段及过渡依赖 |
| 交付前 | 完整文件音画可解码、帧数和音轨尾部正确；局部预览含上下文；输出名和版本明确 | 不把“渲染完成”当全部内容／审美验收 |

高风险回归项：任务引言误用全章总览、视频尾帧假运动、数值每次更新闪动、棋子与树分支错位、双行字幕遮挡来源、背景露出重复标题、Logo 突然补贴、旧作者文字配新论文、句尾被静音剪切截断。只检查与修改有关的项；整章制作需覆盖这些类型。

## 长片局部修复与可复现性

1. 确认当前基线和音轨版本。保留用户指定可恢复版本，例如第一章 V8；“V9”在预告与第一章不能混为同一工程。
2. 先渲染局部样帧和带前后文的有声预览。受影响范围包含上一段退出、下一段入场，不能只按用户给出的整数秒裁切。
3. 按明确帧区间补渲染静音画面。若原音轨未变，复用原 master 或压缩音轨；字幕仍按全片时间，不在 patch 内从零误排。
4. 只有切点确在可独立解码的关键帧、编码参数与时基兼容时才做流复制拼接。否则对边界重编码或扩大 patch，不能用任意 `-ss -c copy` 声称逐帧精确。
5. H.264 的 PTS／DTS 与 B 帧可能让 segment 切到下一个 GOP；拼接前逐段断言预期帧数，拼接后检查总帧数、start_time、连续时间戳。不要仅看 duration 看起来相近。
6. 固定时长局部修复可核对接缝前后不变区的解码帧哈希；音轨原样复用可比较音频包哈希。哈希通过只证明相应技术不变量，不证明观感。
7. 完整视频和局部预览分别命名；附源码、范围、真实采用的转场方式和复现命令。不得把未运行的生成任务、未复听的音频写成完成。

## 清理中间文件

生成／渲染缓存可大于成片。按依赖清单保留当前可用源代码、锁文件、字体、选中素材、论文原文件及页面、真实实验数据和 checkpoint、正式音轨、字幕、完整预览、重渲染脚本。删除失败候选、可重建 bundle、临时无声分段前确认不被当前时间线或复现脚本当作唯一输入。

用户要求删除某版本时，区分该版本独有源码、输出和持久笔记，保护其他版本共享素材；不要清除费用事实台账。不能以“优化 skill”为由清理视频工程。仅在有清理任务或本轮明确临时产物范围内执行；不自动递归删整个 output。

## 新版本完成后的收尾触发

当新版完整成片已输出、技术 QA 通过、实际成片哈希和依赖清单已经落盘，才可进入自动清理。`partial` 预览、失败／未知状态生成任务、仍运行的渲染进程和未完成的清理计划都阻止删除。新版本“存在文件”不等于“完成”。

清理前将候选写入项目 `research` 或 `docs` 的清理记录：绝对路径、类型、字节数、重复／可重建依据、当前引用、保护原因和删除动作。清理脚本应支持 plan/apply 两阶段，拒绝路径逃逸和 reparse 点；默认只处理用户授权项目范围。执行后记录实际删除列表、失败项和释放空间，再核对最新 MP4 的 SHA、字幕／音频、字体、论文、实验数据、选中媒体与渲染入口。删除任何旧版本 bundle/public 副本前，必须证明源文件仍保留且没有活跃依赖；junction 只按链接本身处理，不能遍历目标。

保留最新可交付成片、至少一个有用回退成片、源码／配置／锁文件、实验数据和 checkpoint、实际使用的素材、正式音轨与句源、字幕、来源与费用台账。旧版唯一成片是否保留按用户目标决定；“释放空间”默认针对重复 bundle、失败候选、可重建帧缓存和无依赖无声分段，不能凭版本号一锅端。清理不创建系统定时任务；它是完成流程中的一次受控收尾。
