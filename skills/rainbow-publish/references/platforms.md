# 四平台发布字段与核验

本文件是浏览器操作清单，不是固定 selector 或平台接口契约。先按 ego-browser 技能读取当前页面，核对账号、功能权限与实际限制；入口重定向、字段名称及开放能力可能变化。只操作本次任务已有的页面，保存 TaskSpace 与页面 ID。

## 通用顺序

1. 核对当前账号与任务目标，读取发布清单、视频、文案和封面。记录视频 SHA256、平台与账号身份，查找已有发布记录；同一内容已经提交则核对回执，不重复上传投稿。
2. 上传正确视频，等待上传完成及页面显示转码／处理完成。仅进度条走满不足以证明可提交；读取页面错误和剩余处理状态。
3. 按平台填写标题、正文／简介与话题。优先沿用该平台源文案；若规范化字段缺失但源文案明确包含对应内容，可以提取并记录来源。不能从文件名猜正文、将多个候选标题一起粘贴，或将首评混入正文。
4. 以当前页面的字数、格式和文件限制为准。需要压缩长文时保存原文、最终文本与调整原因，保留科学结论的条件、范围、引用和不确定性。超限且无法保真适配时暂停该平台，不静默截断。
5. 上传指定封面并检查实际裁剪预览，确认标题、主体和 Logo 可读。页面要求横竖两张或列表／主页双比例封面时分别选择已有适配图；不能只上传一张后假定两种展示都正确。允许的裁剪会影响重要内容时，先记录待解决项。
6. 将话题按页面提供的方式逐个添加，并核对已选标签／话题状态；输入了文字不等于选中了话题。保留用户标签意图，不自动选择无关热点。
7. 核对目标合集的精确名称与账号归属，再选择并检查回显。有同名合集时用页面证据区分。配置要求合集时，若无入口、权限不足或目标不存在，只暂停这个平台，其余可继续；标签、话题、分区都不能替代合集。不擅自新建合集。
8. 核对页面要求的来源、原创／转载、AI 内容或其他声明，只根据素材事实和已有用户说明填写。事实不足时记录缺项，不猜测，不改账号权限或默认可见范围。
9. 在本次任务授权的提交模式下执行最终发布；提交前记录 `submitting`，提交后核对成功提示及内容管理页的对应作品。记录可获得的作品 ID、管理链接／公开链接、账号、标题、合集、时间与证据。审核中记录 `submitted`／`pending_review`，不能写成已公开。
10. 提交后超时、页面断连或成功状态不明，记录 `submission_unknown`。先查内容管理页并比对标题、时间、封面和视频信息；确认原操作没有产生作品前禁止再次提交。不能以缺少公开链接认定失败。恢复时保留各平台已完成状态。

验证码、扫码登录、浏览器权限提示或用户接管时按 ego-browser 规则交回控制。不要自动发布首评、置顶评论、互动消息，也不要顺带变更权限、启用付费推广或其他未请求的功能。

## 微信视频号

- 官方创作者入口：<https://channels.weixin.qq.com/>。
- 查找当前可用的视频发表入口，核对视频号身份。填写页面实际提供的描述／正文、标题或短标题；源文案中的完整标题不一定能直接用于短标题字段。
- 添加话题并检查实际选中状态；上传封面，核对发布预览及页面提供的各展示比例。
- 若账号提供合集选择或作品管理中的合集归属功能，按清单选择并核对。需要发表后才能归集时，先确认该能力和目标存在，提交后执行归集并核对；没有证据不能把“发布完成”写成“已入合集”。
- 检查页面要求的来源与声明；提交后在内容管理中核对作品、审核状态及合集归属。公开链接尚未生成时保留管理回执。

## 抖音

- 官方创作者入口：<https://creator.douyin.com/>。
- 在发布作品入口上传视频，填写标题／作品描述，按当前页面区分各字段；逐个选中话题。

- 按真实来源设置页面要求的声明。提交后在作品管理核对对应作品、处理／审核状态及合集，不将上传成功等同于发布成功。

## bilibili

- 官方创作中心入口：<https://member.bilibili.com/>。
- 在视频投稿页上传视频，核对标题、简介、标签及封面。简介可包含源文案中已核对的时间导航与引用；保留必要的事实限定。

### 网页操作经验（2026-10-31 核验）

以下是已观察页面的操作经验，selector 和路由仅用于识别，仍须在当前页面验证后使用；不构成新增发布、创建合集或修改旧笔记的授权。

- **封面需要显式应用。** 上传图片并等待完成后，编辑器可能仍使用视频截图。当前页面可点击 `button.uploaded-thumbnail` 应用已上传图片，再选择实际比例，截图核对标题、主体和 Logo；保存后等待编辑器关闭。不要以“上传完成”代替画面核验。16:9 原图若需适配 4:3／3:4，应另存等比缩放、加边的适配图并保留原图，不能裁掉关键内容；记录适配图路径、比例及指纹。
- **合集字段异步加载。** 刚进入投稿或编辑页时出现“创建合集”“未命名”等占位文字，不代表账号没有合集或合集真实名称如此。等待列表／已选字段加载完成，再核对精确名称；当前已选字段可见于 `.collection-plugin-choose .collection-name`。创建按钮只有在本次已获创建授权且确认目标不存在时才使用。
- **话题逐条确认。** 每次输入 `#话题` 前重新聚焦正文编辑器并移动到末尾，等待候选结果后选择名称相同的项；每次选择后检查编辑器内 `.tiptap.ProseMirror .tiptap-topic` 的实际名称，再输入下一条。不要把推荐区或预览区的重复节点计入正文话题，也不要把纯文本 `#标签` 当成已选话题。
- **新投稿与编辑保存的回执不同。** 新投稿曾跳转 `/publish/success` 并显示“发布成功”；已有笔记的 `/publish/update?...` 页面即使按钮也叫“发布”，保存后可直接回到笔记管理。应按实际操作识别结果，不能因编辑保存未进入投稿成功页就重试或另行投稿。再次从管理页打开同一作品 ID，核对持久化字段，才记录编辑完成。
- **列表需要完整加载并确认状态标签。** 笔记管理首屏只含部分作品；在实际滚动容器内逐批滚动，等待卡片数增加或明确结束提示，再按作品 ID 去重。页面总数、首屏数量以及瞬时“全部 0”都不能单独证明盘点完整。核验已发布状态时精确选择“已发布”，确认当前激活标签（曾见 `.tab-item--active`）并等待加载结束；审核中、未通过分别检查，不能将“全部”列表内无状态文字的卡片自动视为公开。
- **旧笔记归集使用编辑入口。** 本次明确授权修改合集时，通过已核实的目标作品 ID 打开原笔记，保留标题、正文、话题、封面和声明，仅调整合集。保存前对照原字段，保存后重新打开同一 ID 核对合集；不重传视频、不创建重复笔记。若只查询归属，读取已加载字段即可，不点击保存。

## 本项目历史材料的读取

### 本地整理清单 `publish/publish-manifest.json`

常见字段为 `id/projects/topics/evidence/files/status`；`files[]` 中包含 `role`、`source`、`destination`、`path`、`sha256`、`state`，封面角色形如 `cover:16x9`、`cover:3x4`、`cover:4x3`、`cover:9x16`。

- 对迁移后的材料，优先用 **manifest 所在目录 + 文件项 destination** 查实际文件。`path` 和 `source` 可能仍指向已经移动的旧位置；必须核对文件存在性与当前 SHA256。
- 顶层 `destination` 可表示项目相对目录，不要与文件项 `destination` 再重复拼接。
- `state: moved`、`status: organized`、技术探测通过以及材料目录名 `publish`，都只描述本地整理，不证明内容已获发布授权、已经上传或已经公开。
- `work/publish-spec-*.json` 等历史外层清单可能是 `packages[]`，每个包再含 `files[]`；应先选择目标包、解析其目标发布目录，不能把多期视频合成一条投稿。

### 发布文案 `publication/<版本>/copy-data.json`

常见顶层字段为 `series/chapter/topic/version/platforms`，其中 `platforms` 是数组，平台项为 `id/name/titles[]/body/tags/pinned/includeNavigation`。

- 按平台项 `id/name` 映射到 `wechat/douyin/bilibili/xiaohongshu`，识别“B站”“微信视频号”等名称；不能假定 `platforms` 总是键值对象。
- `titles[]` 是候选标题，不存在单数 `title` 时应读取已明确选定项；没有选择记录时，在发布计划中明确采用的标题。`pinned` 是评论候选，不自动发送。
- `series` 是本地系列说明，不能自动推断为平台合集 ID；需与账号中可见的实际合集建立明确映射。
- 同目录 `manifest.json` 的 `ready-content-and-timestamps` 等状态只说明文案／时间导航准备情况，不证明视频、封面同版本或平台发布完成。核对与指定成片的版本关系。

Creator Workbench 另有 `source/publish/{wechat,douyin,bilibili,xiaohongshu}.json`，单文件字段通常是 `platform/title/body/tags/updatedAt`。读取其正文和标签即可复用；`updatedAt` 不是平台发布时间。Markdown 文案中的“首评”“置顶评论”“发布记录说明”须与投稿正文分开。
