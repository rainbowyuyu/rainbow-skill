# 可视化与交互

用于动态图、研究模型、人物素材、转场和交互实现。只采用内容需要的机制，不把所有效果都堆到每一页。

## 根据内容选择视觉

| 内容 | 优先展示 | 避免 |
| --- | --- | --- |
| 仿真或实验流程 | 条件输入、过程、时程曲线、结果文件 | 用风景动画替代真实计算输出 |
| 设计或优化 | 初始模型、约束、演化阶段、检查与交付 | 只摆界面截图，关键模型太小 |
| 视觉或重建 | 源图/视频、匹配过程、重建、同角度对比 | 选择与研究对象无关但“好看”的演示素材 |
| 模型比较或可靠性 | 样本结果、差异、分布、阈值或风险曲线 | 未经依据的性能评分与装饰曲线 |
| 未来分支 | 当前基础到多个问题的展开图 | 将假设路径画成已经跑通的闭环 |

每个步骤定义独立的视觉状态。允许共享一个场景和同一模型，但必须改变与该步相关的证据、构图、覆盖层、数据或输出。按钮需有清晰选中态，点击后观众应立即知道当前正在解释什么。

模型支持有用的旋转、平移、复位和阶段定位；曲线可提供进度游标、系列切换和数值读取。只放真正影响理解的控件，不把所有实现参数暴露给听众。

## 状态和时序

至少分开管理：

- 当前页及其导航过渡。
- 当前步骤、播放/暂停状态和步骤进度。
- 相机位置、缩放及手动控制状态。
- 人物动作是否已经播放。
- 自动导出的章节时间表。

用户选择步骤时，不重播无关人物动作；操作模型时，不切页或复位整页。返回上一页应恢复用户要求的状态，通常是完成态或上次状态；“重播”才明确从头开始。

现场版和视频版可以使用相同的场景组件，但不能共用“时间到就进入下一页”的导航行为。现场版在当前页停留；内部过程可以循环、停在完成态或由用户拖动，按内容选择。

滚轮翻页时，按一次手势去重并处理惯性，不只对每个 wheel 事件加固定延迟；明确反向滚动的行为。输入框、进度条、展开说明和内部滚动区应优先处理自己的交互。页面切换时忽略重复导航，防止连续跳页。点击模型、步骤和工具条不得冒泡成翻页。

## 流畅的运动

- 动作服务信息变化：用相同对象的位置、尺度、线条或色彩衔接两个状态，避免依赖长时间的遮挡过场。
- 常见控件反馈可从 150–300 ms、构图或章节衔接从 300–700 ms 起步；根据阅读和叙事调整，不用慢转场填补内容。
- 正文退场后再进入下一组正文；公共徽标、页码和背景按设计保持稳定。
- 思维导图展开可用同一根线或节点引出不同分支，避免每个节点各自无关地弹跳。
- 人物手部、标签和文字揭示使用同一动作进度，避免独立延时导致手到了而内容没到。
- 已结束的动作应停在自然状态；循环必须比较首尾位置、姿态和色彩，不能假定加上 loop 就会顺畅。

## 三维与高斯泼溅

先确认素材的作者、许可、坐标方向、单位或比例，以及实际重建范围。公开可浏览不代表允许下载和再分发。优先选择识别度高且重建完整的视点；缺损或模糊区域不要靠命名包装成完整景观。

广角要调整实际相机视场角，而不只是把画布放大。区分垂直和水平视场角，并根据宽高比核对覆盖范围；可提供少量有意义的取景预设。适度平移限制在可靠的采集区域附近，过大的位移容易暴露空洞。

相机转场使用缓动；开始拖动时从当前自动镜头姿态接管，避免跳回初始位置。相机、观察点和旋转中心要协调。复位行为应明确且一致。

优化前后在同一窗口、同一设备及可说明的场景下记录真实渲染帧率和帧间隔。不要把 requestAnimationFrame 回调次数当成绘制成功次数。截图对比同时检查清晰度、漂浮点、边界和文字遮挡。

优先考虑分辨率上限、按需绘制、惰性加载、复用对象、事件合并、后台暂停和局部预加载。必要时提供流畅/高清模式：降低高斯密度、球谐阶数或渲染尺寸会改变观感，需检查质量、保留原始数据，并说明取舍。不要仅凭帧率提升宣称画质也提升。

## 数字人：先明确交付类型

| 类型 | 可以承诺的能力 |
| --- | --- |
| 照片或风格化肖像 | 静态呈现，可搭配版式动画 |
| 由肖像生成的动作视频 | 固定镜头、有限动作；可与页面内容按时间同步 |
| 带骨骼的真实三维模型 | 可旋转、换视角、绑定动作；需要相应建模与驱动流程 |

具有三维动画风格的图像或视频仍不等于可自由旋转的三维人物。用户要求后者时，应评估可用建模资产和实际管线，不能以风格化视频冒充完成。

如需生成形象，提醒用户提供清晰、光线自然、身份特征一致的参考照片；不同角度有助于约束脸型和发型。优先保留脸型、五官比例、发型和年龄感，避免过度美颜。用户希望降低违和感时，采用适度卡通化和简洁表情，不强行追求照片级表面。

先完成一个可信的静态形象，再制作少量连续动作。初次打招呼或托举标签通常播放一次；选择技术方向只切换相应内容，不反复触发相同手势。重点检查手指、牙齿、眨眼、肩颈、视线、人物比例与分段接缝。

需要抠像时，检查头发、眼镜、手部边缘和浅色衣服；纯白背景并不代表可以无损删除所有接近白色的像素。主体与页面的光线、阴影和裁切要协调。

## 生成 API 与缓存

仅在用户需要且已有费用授权时使用收费服务。具体供应商、地域、模型和价格以实施时的官方说明与账户权限为准，不把某次使用的模型名写成永久依赖。

建立最小任务账本：用途、模型、提交时间、任务 ID、状态、预留费用、结果位置、已知限制。累计预算包含失败重试的预留；超时先查原任务，避免重复收费。连续两次同类失败且没有实质修正方案时停止盲目重试，先排查或提供明确标注的替代草稿。

预算和素材额度不足时缩减生成范围，不能悄悄更换收费账户或增加支出。只在存在新的付费授权缺口时向用户确认，不为已授权范围内的每个正常步骤反复询问。

密钥只在本地环境变量或不随包分发的配置中使用。生成结果立即下载并记录来源；浏览器端、演示运行时和交付包不携带密钥，也不调用收费接口。生成失败的照片占位版应明确标注未完成部分。

## 渲染实现

如使用 Remotion，保持各 Remotion 包版本一致，尊重现有锁文件。导出动画必须由帧决定，不能直接依赖系统时间、随机数或浏览器自由运行的计时器。随机视觉需要固定种子。

交互预览可以在帧更新之间平滑插值相机，但暂停和定位应停在正确状态；导出使用确定性帧序。素材加载完成后再渲染相应画面，不把网络尚未加载的黑帧写入视频。

导出或采集 WebGL 时，只在需要捕获的路径中保留绘制缓冲。等待实际绘制完成，必要时还需等待排序结果，不能依赖一个未经验证的固定延迟。视频播放时支持本地资源、合适的 MIME 和字节范围请求。
