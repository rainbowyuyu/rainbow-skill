# 内容与分镜

用于整理主题、阅读研究材料、编排章节和撰写讲稿。页数和时间服从用户目标，不把下面的示例变成固定模板。

## 选择合适的叙事结构

| 场景 | 推荐主线 | 容易浪费时间的内容 |
| --- | --- | --- |
| 首次见面 | 我是谁 → 之前做什么 → 现在做什么 → 希望探索什么 | 多页重复列技能、经历和能力标签 |
| 阶段进展 | 上次的问题 → 本次尝试 → 观察到的结果 → 问题与下一步 | 再讲一遍全部背景和基础概念 |
| 方向讨论 | 问题为什么值得做 → 可用基础 → 候选路径 → 最小验证 | 把设想写成既成成果，提前承诺性能 |

首次介绍可从“封面、自我介绍、之前的研究、当前工作、未来方向、致谢”起步。籍贯、兴趣、团队关系只在对介绍有帮助时加入。用户希望自我介绍一页时，不以“能力”“实践”等标题拆出重复章节。

多个未来分支适合用总览图说明联系，再按需要展开；只有一个问题时无需硬做思维导图。致谢可以留下一个明确的交流问题，避免制造夸张的愿景口号。

## 把技术内容翻译成可理解的描述

每项工作回答五个问题：

1. **为什么需要它**：以前哪一步麻烦、耗时或难理解？
2. **给它什么**：输入是需求、图像、数据、模型还是边界条件？
3. **它做什么**：保留关键因果，不在正文罗列实现名词。
4. **人得到什么**：曲线、模型、文件、建议，还是一种可检验的解释？
5. **还有什么没解决**：范围、假设、失败例、下一步。

例如，“用图像估计物体的空间形状”比只写一串模型缩写更适合跨专业听众。类比用于降低理解门槛，但应保留差异：可把结构演化比作修剪材料，不应因此暗示算法真正使用人工雕刻工艺。

屏幕保留结论、过程标签和必要数值；技术细节放到讲稿、展开面板或附录。不要把讲稿整段塞进页面，也不要把所有解释删到只剩抽象口号。

## 先建立证据清单

| 记录项 | 要回答的问题 |
| --- | --- |
| 展示主张 | 这一页具体在说明什么？ |
| 原始材料 | 来自哪份文件、哪张表、哪段记录或哪个网页？ |
| 内容性质 | 实测、历史仿真、方法复现、解释示意、待验证假设？ |
| 处理方式 | 是否截取、降采样、归一化、补间、裁剪或重新渲染？ |
| 边界 | 单位、样本范围、条件、已知不足是什么？ |
| 归属 | 用户本人、团队、外部作者，还是公开方法？ |

优先读取项目说明及实际产物，交叉核对二者。README 描述的路线不等于已经存在的产物；可视化文件存在也不等于结论通过了验证。

曲线保留量纲、坐标意义和必要的条件。不同模型或任务只在同口径下比较。动画插值是展示手段，不能把离散历史结果包装成新求解；不能把错误条、置信区间或准确率画出来后再寻找依据。

涉及可靠性或风险时，使用真实结果中的分布、差异、正确与错误案例、校准或阈值变化。没有数据时做明确标注的交互示意，只解释研究问题。

## 分镜表

每页至少记录以下字段，按工程规模使用 Markdown、JSON 或 TypeScript：

| 字段 | 内容 |
| --- | --- |
| page_id / title | 稳定编号和直白标题 |
| takeaway | 听众应记住的一句话 |
| visual | 一幅主视觉及其信息职责 |
| steps | 每步的输入、动作、输出和对应素材 |
| evidence | 已完成 / 在做 / 拟探索；真实 / 示意及来源 |
| interaction | 可点击什么、可旋转什么、暂停后显示什么 |
| timing | 现场建议时间、自动版时长、动画结束点 |
| notes / cue | 口语讲稿与操控提示 |
| missing | 尚缺的材料与临时替代方式 |

示例：一项“图像到模型”的方法，可用“输入图像 → 建立模型 → 对比验证 → 查看输出”四步。每一步依次展示源图、多视角或重建过程、同视角比较、最终可操控模型，而不是四次播放同一个旋转模型。

## 版式的落地标准

- 将参考图拆成配色、文字层级、对齐、间距、视觉占比和边框风格，再应用到内容；不要连同参考图里的人名、单位或项目一起复制。
- 1920×1080 可从标题约 56–76 px、正文约 30–40 px、图例约 22–28 px 起步，以实际投影截图为准。来源说明可更小，但不承载核心结论。
- 主体优先给模型、过程图或结果图；文字通常控制为两三组短句。信息过多时使用步骤切换或拆页，不靠缩字塞满。
- 标识使用用户提供的原件或经过核对的正式素材，保持比例和安全距离。需要固定标识时，将其放在不参与页面转场的公共层。
- 避免装饰性仪表盘、没有含义的百分比、过多胶囊标签、悬浮光效和细碎辅助文字。
- 列表与图表统一对齐；检查选中态、长标题和说明展开后的布局，而不只看第一页静帧。

## 讲稿

每页讲稿采用“承接上一页 → 用普通话说明当前画面 → 点出观察或限制 → 引出下一页”。首次介绍可轻松自然，阶段汇报则明确结果与困难。

字数依据讲述者实际语速与演示停顿估算。没有语速信息时可按每分钟约 180–240 个汉字初估，再扣除操作、模型展示与讨论时间；不要用文字长度假装精确计时。

把操作提示与要说的话分开。例如“此时点击第二步，暂停在对比图”属于提示，不是台词。逐页核对讲稿、标题、视觉和时间表，避免修改页面后讲稿仍沿用旧内容。
