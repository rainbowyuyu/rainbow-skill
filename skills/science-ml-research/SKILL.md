# 科学ML研究：从领域假设到实验反馈

仅在用户明确调用本技能或明确要求按这份流程开展工作时使用，不全局自动启用。按当前任务深度使用：只写方案就交付方案；执行研究时在既定资源内推进。普通网页、工程修复或单篇论文阅读不自动进入实验循环。

方法来源为 *Automating ML for Science*（arXiv:2610.28763v1）及 Agent4Sci 官方代码。本文为本机适配，研究收益尚未在本机验证。首次使用或需要引用论文结果时读 [来源与迁移依据](references/evidence.md)。

完整中文解读见 [论文导读](references/paper-reading.md)。本包可单独读取；若当前环境没有下文所列研究技能，直接按这些阶段维护项目记录，不假称已调用不存在的技能。

## 接入已有工作

先读用户当前目标、项目约束和已有研究产物。复用 `refine-logs/FINAL_PROPOSAL.md`、`EXPERIMENT_PLAN.md`、`EXPERIMENT_TRACKER.md`、`EXPERIMENT_RESULTS.md` 或项目已有等价文件，避免并行维护另一套计划。

- 选题与领域检索接入 `research-lit`、`research-refine` 或 `research-pipeline`。
- 假设和实验排序补充到 `experiment-plan`；已有方案稳定后才执行 `run-experiment` / `experiment-queue`。
- 运行结果通过 `experiment-audit` 与 `result-to-claim` 检查。沿用它们现有的审阅路由和结论边界。
- ARIS辅助脚本若尚未解析或不可用，直接维护可读的项目记录，并说明缺失能力；不要声称调用成功。

需要建立新项目记录时，按 [研究记录与复盘](references/working-records.md) 提供的最小字段补齐。

## 建立可比较的起点

确认科学问题、目标指标及方向、数据划分、基线来源、推理成本与当前任务预算。记录基线实际复现值和来源论文值的区别。只有基线已在当前协议下可信复现时才复用其结果；必要的复现、多种子评价和小规模检查应保留。

预先确定固定评价入口和最终产物选择规则。改进阶段使用训练/验证反馈；最终测试由独立评价阶段运行固定评价器。单纯分配不同子agent不提供文件权限隔离：若没有真实隔离，记录这一限制，避免宣称已实现论文的隔离保证。测试信息一旦参与方法选择，要报告污染并使用新的独立评价方案，不能仍称其为未见测试集。

## 用领域文献和ML方法共同提出假设

研究量足够大时，并行调查两个方向；小任务可由主agent完成同样的问题检查。

| 方向 | 需要回答的问题 |
| --- | --- |
| 科学领域 | 数据生成机制、对称性、守恒关系、观测误差和目标变量有哪些约束？领域通常怎样训练与验证？ |
| AI/ML方法 | 哪些表示、模型或训练方法适用于这些结构？是否存在更简单的解法或可借鉴的相邻任务？ |

必要时再将各方向分为数据/结构与训练/评价两部分。每条关键建议保留原始来源、适用条件和与当前任务的差异。可以同时做环境及接口检查，不必停工等待全部文献。

登记候选假设时写出简明的“改变什么、为什么可能有效、预计看到什么、什么结果会否定它”，附上文献依据、最小区分实验和成本。记录可审核的依据与决策摘要，不要求输出私有内部推理过程。

区分 **结构或机制探索** 与 **已有工程改进**。常见调参、扩大模型和集成可以有价值，但不自动构成新颖贡献；新颖性保留为待检索判断。两类实验都按预期信息收益、实现风险和预算排序，不强制全部先跑高风险方案。

## 实验应持续改变后续决策

先用代表性小运行检查数据、损失、指标和预计耗时，再扩大规模。每个实验记录运行ID、代码版本或diff、数据划分、配置、日志和产物位置。并行时明确文件编辑边界与资源归属，避免多个实验覆盖同一代码或checkpoint。

结果返回后读取实际日志和产物，核对假设，再决定下一轮。不要在缺少阶段反馈的情况下把整个预算交给一个巨大参数搜索脚本。

失败先分类：实现或数值错误、资源不足、评价问题，或假设不受支持。实现错误不能直接否定科学假设。修复仍受当前预算约束；保留失败依据后可停止或换方向，不必证明所有变体都不可能。

资源优化以有效信息产出为目标。只用本任务可用的设备，检查CPU、GPU和I/O争用；精度或批量变化需要满足数值与物理验收标准。资源闲置本身不构成继续增加实验的理由。

## 在结果和时间检查点复盘

每批有效结果返回后、恢复长任务时，或发现连续实验没有新增证据时，检查研究是否停滞。长任务使用 [checkpoint.py](scripts/checkpoint.py) 保存复盘时点；详细调用见 [研究记录与复盘](references/working-records.md)。

首次初始化默认60分钟或自上次复盘完成2个实验后提示到期，可按任务调整时间。主agent在恢复、结果返回及下一次研究操作前主动运行 `check`；到期后先完成复盘，再用 `record` 记录摘要。计数来自实验账本中的不同终结实验，不用轮询次数替代。

复盘包含四项：研究假设是否仍有根据；运行任务与瓶颈；剩余预算及未检验解释；下一步明确动作。选择继续、修复、换方向、缩小主张或收尾，并写出新证据与选择理由。常规调参若正用于回答重要问题，可继续；若只在同一思路周围重复且信息收益很低，应回到文献和问题结构。

这是任务内主动检查，没有常驻进程或唤醒功能，也不会阻止用户结束。跨回合自动唤醒需要用户另行要求并通过应用自动化工具配置；不要把helper或Markdown描述为已安装定时器。

## 评价、审计与结论

选定并冻结提交产物后，运行预先约定的评价；审计数据使用、指标、选择过程及实际保存产物。审阅者用来源记录和运行证据作判断，同模型家族审阅仍标为 provisional，不能写成跨模型独立验证。

同时报告指标变化、训练/推理成本和适用范围。区分工程收益、机制证据与科学主张；验证集改善不能替代未见数据评价。未运行的实验保留为计划，安装该技能不证明研究质量已经提高。

采用来源见 [evidence.md](references/evidence.md)；本文保留当前模型、权限、厂商和资源配置。预算是上限，达到目标、证据不足以继续或用户停止时正常收尾。
