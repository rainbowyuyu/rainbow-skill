# 最小研究记录与复盘调用

优先补充已有文件。下列名称为缺少项目约定时的建议，不要求创建空文件。

## 任务与评价约定

在既有研究计划中保留：科学问题；基线代码版本与实际复现状态；数据与split；主指标及方向；固定评价入口；最终模型选择规则；训练与推理成本；本轮资源上限；允许修改的范围；真实测试隔离状态。

工程数值任务还应记录单位、容差、物理约束，以及与参考解或数据的比较方式。修改评价口径意味着新协议，不能把新旧结果直接并列称为同口径提升。

## 假设登记

在 `EXPERIMENT_PLAN.md` 或等价文件中，为每项候选记录：

| 字段 | 内容 |
| --- | --- |
| ID与类别 | 结构/机制探索，或已有工程改进 |
| 改变与机制 | 如果改变X，预期Y，因为Z |
| 来源与差异 | 原始文献、适用条件；与已有方法相比改了什么 |
| 否证条件 | 什么结果会削弱或否定假设 |
| 区分实验 | 最小规模下如何区别竞争解释 |
| 比较约定 | 数据、基线、指标、随机性与最终选择方式 |
| 成本与优先级 | 时间、设备、依赖和下一步决策价值 |

## 运行账本

复用 `EXPERIMENT_TRACKER.md` 和 `EXPERIMENT_RESULTS.md`。每个运行对应代码或diff、配置、日志、产物、种子/fold、指标及成本，标明未开始/运行中/完成/失败/停止。

失败不填虚构指标。改进agent不使用test标签或错误案例指导下一轮。独立评价与审计分别保存实际执行范围和未解决的问题。

## 复盘摘要

每次复盘至少记录：

- 上次复盘后获得的证据及其来源。
- 对当前假设的影响，是否出现低信息量重复。
- 运行任务、资源瓶颈和剩余预算。
- 决定：继续、修复、换方向、缩小主张或收尾；对应下一步动作和停止条件。

可以先写临时摘要文件供helper读取，再按项目习惯保留到实验日志；状态中会保存摘要内容。无需另存用户的完整聊天或任何凭据。

## checkpoint.py

脚本位置是本技能目录下的 `scripts/checkpoint.py`，只用Python标准库。下例以 `SKILL_ROOT` 表示你解压后选定的技能绝对路径，执行时替换为真实路径；`python`替换为当前可用解释器。首次使用先查验该目录下实际脚本，无须安装到全局。

在项目目录执行，状态路径需按实际项目替换；先确认状态父目录已存在，缺少时在本项目内创建：

```text
python "SKILL_ROOT/scripts/checkpoint.py" init --state refine-logs/science-research-checkpoint.json --interval-minutes 60
python "SKILL_ROOT/scripts/checkpoint.py" check --state refine-logs/science-research-checkpoint.json --completed-total 2
python "SKILL_ROOT/scripts/checkpoint.py" record --state refine-logs/science-research-checkpoint.json --completed-total 2 --note-file refine-logs/last-research-review.md
```

`init`只在本轮确实进入长研究工作时调用，已有状态不能覆盖。`check`只读，不是守护进程；到时间或自上次复盘完成至少2个实验后返回due。`record`在完成实际复盘后调用，追加时间和摘要，更新下一次检查时点。

`completed-total`是该状态对应研究run的累计终结实验数，由账本提供。完成一次失败诊断也可构成一个终结运行；重复轮询同一运行不增加计数。脚本能检查相对上次保存记录的计数回退，不能证明计数来自真实运行。

脚本要求摘要非空，只验证结构与状态，不验证科学判断是否正确。时间以UTC保存，界面报告按用户时区表达。使用一名主agent作为同一状态文件的写入者；并行子agent回报实验结果即可。

从较长中断恢复后出现due，表示需要检查当前研究状态，不意味着任务在中断期间持续运行或已消耗相同计算预算。用户要求暂停或结束时，先遵从该要求，不用复盘机制强制延长任务。

要跨回合定时唤醒，必须另行配置实际应用自动化；本技能没有创建任何定时任务。
