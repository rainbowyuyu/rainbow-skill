# 高级演示制作

默认工作区：`D:/projects/zuhui`。使用现有 Remotion 框架、模板和管理命令，把每份报告存为独立项目；共享安装依赖并控制迭代占用。

## 开始前

1. 读取所选工作区的 `AGENTS.md`、`README.md` 和相关项目的 `notes/`，以实际管理命令及项目状态为准。
2. 根据当前任务上下文选择工作区。用户已指定其他工作区时沿用其位置；不要把某个报告子目录初始化成独立 npm 项目。
3. 运行根目录的 `npm run report -- doctor` 和 `npm run report -- list`，确认依赖、模板和项目状态。缺依赖时仅在根目录按锁文件安装。
4. 用户仅要求建架构、整理目录或创建技能时，完成这些任务即可；不额外生成报告内容或视频。

## 文件结构与依赖约定

```text
<workspace>/
  package.json                  # 唯一依赖入口
  package-lock.json             # 根级版本锁定
  node_modules/                 # 全部报告共享的一份安装
  PresentationStudio.exe        # 可选 Windows 统一启动器
  launcher/                     # 共享启动器源码与品牌图标
  scripts/                      # 项目管理、渲染和受限清理
  shared/                       # 跨报告复用的组件、主题
  templates/report/             # 新报告模板，不携带依赖
  projects/<id>/
    src/                        # Remotion 源码
    input/                      # 原始材料、论文、原始数据
    public/                     # 浏览器/Remotion 实际需要的素材
    notes/                      # 提纲、文献来源、决策与说明
    output/latest/              # 最近一次成功验收的产物
    work/iterations/<active>/
      scratch/                  # 本轮临时脚本、中间文件
      artifacts/                # 管理命令生成的待发布产物
```

- 报告 ID 使用简短的小写字母、数字和连字符，优先体现主题；需要区分同主题会议时加日期。
- 每份报告只建一个项目目录。迭代原位修改 `src/`，不复制 `v1/`、`v2/` 或整份工程；需要源码历史时使用现有 Git 工作流。
- 不在 `projects/` 或模板中创建 `node_modules`、依赖清单或锁文件，不逐项目执行 `npm install`、`npm ci` 或用 `npx` 下载临时工具。
- 新增依赖只修改根清单与锁文件；所有 `remotion`、`@remotion/*` 包保持同一版本。Node 可执行程序也复用现有环境，不复制到项目中；通用组件导入根目录 `shared/`，避免逐项目复制。
- 原始材料放 `input/`，运行时确需引用的素材放 `public/`。不要把整个原始材料目录再复制一份；大素材按实际用途选用，避免无用途的重复文件。
- 外部生成工具的临时任务脚本、中间文件和音视频放入当前报告 `work/iterations/<active>/scratch/`；从管理命令输出或 `work/state.json` 确定活动迭代，不能散放到 `work/` 根目录。最终需要长期使用的素材及时移入 `public/`。
- 单个报告目录依赖祖先工作区的共享安装，不承诺脱离根目录即可运行。迁移到其他电脑时带上根配置、锁文件、`scripts/`、`shared/`、所需项目与素材，在新根目录安装一次依赖；不必搬运 `node_modules/` 或临时目录。

## 可选共享启动器

工作区已有 `PresentationStudio.exe` 时，可将其作为 Windows 演示主入口；具体行为以根目录 `launcher/README.md` 为准。启动器自动读取 `projects/*/project.json`，新项目通过现有 `new` 命令创建后刷新即可出现，不逐项目制作 EXE 或安装依赖。有 `index.html` 的项目进入交互预览，其他项目进入共享 Remotion Studio；启动器选择空闲端口、验证页面就绪，并只停止自己拥有的进程。运行日志仍放当前受管迭代的 `scratch/launcher/`；启动已完成项目时可由管理命令建立新的活动草稿。

未提供启动器的平台或工作区继续使用既有 CLI，无需为了报告内容任务额外创建启动器。迁移已有 Windows 启动器时保留根 EXE、`launcher/` 和 `scripts/`，复用目标机器的 Node 环境与根级依赖。

## 创建与迭代

以下命令都在工作区根目录执行；若本地 README 的接口已更新，以实际接口为准。

```powershell
npm run report -- new <id> --title "报告标题"
npm run report -- begin <id>
npm run report -- studio <id>
npm run report -- check <id>
npm run report -- still <id> --frame 60
npm run report -- render <id>
npm run report -- complete <id>
npm run report -- clean <id>
npm run report -- clean <id> --apply
```

1. 新报告通过 `new` 从模板创建；已有报告直接复用其目录。`begin` 继续当前活动迭代，或创建新的草稿迭代。
2. 根据已有材料明确听众、时长、报告目标和必须呈现的证据；只对实质影响内容的缺项提问。未指定画幅时使用 16:9。
3. 编写或修改 `src/` 和必要素材，在 `notes/` 记录内容来源与关键假设。组会叙事可按问题、证据、方法、结果、局限与下一步组织，具体结构服从本次报告。
4. `studio` 用于交互预览，`check` 验证当前源码，`still` 为当前迭代生成代表帧。按实际时长选择有效帧号；多场景报告应覆盖主要版式和关键转场。
5. 用图像查看工具或浏览器实际检查渲染结果，确认中文字体、文字溢出、图表标注、留白与层级；动效需在预览中检查。只通过类型检查不算视觉验收。
6. 用户明确需要视频导出时才执行 `render` 生成 MP4；普通内容迭代可用预览和静帧验收，避免每次导出整段视频。
7. 视觉通过且当前内容检查通过、管理命令已生成非空产物后，执行 `complete`。源码、素材、依赖锁或 `shared/` 在检查后变化，须重跑检查及相应生成命令。该命令把本轮产物移动到 `output/latest/`，再清理旧受管迭代；未满足条件时修复或报告阻塞，不伪造检查记录。
8. 汇报项目位置、最近成功产物和实际验证情况。失败时保留上一轮成功输出，说明本轮尚未完成。

## 演示内容与实现

- 每个场景有明确的信息目的，正文保持适合投影阅读的字号与对比度；图表优先解释真实数据和科学关系。
- 动画由 Remotion 帧驱动，使用 `useCurrentFrame()`、`interpolate()`、`spring()` 等确定性机制；避免依赖真实时间、未固定随机数和无法复现的外部状态。
- 区分文献结论、用户实验结果、模拟示意与待验证假设。保留来源，不编造实验结果、数字或论文引用。
- 用户需要组会内容设计时，可按需参考已有 `zuhui` 技能；无需将其全部规则强加于其他类型演示。
- 需要配音、品牌素材或外部 Claude 协作时，遵循当前工作区及用户的全局工具约定；仅在本次任务需要时调用。

## 清理边界

- 每次成功迭代都通过 `complete` 收尾，由管理脚本释放旧迭代空间；常规受管理清理已属于这套工作流，无需重复询问。
- `output/latest/` 是本轮通过检查的完整成果集合。本轮只生成 PNG 时，上一轮 MP4 也会被替换回收，不能把旧视频当作本轮成品。用户明确要求保留的里程碑可另存到 `output/milestones/`，它在自动清理范围之外；不默认积累每轮归档。
- `clean <id>` 先显示待清理项；需要手动回收时检查清单后执行 `--apply`。只删除脚本认定的已过期临时文件，不以文件名看似旧版为删除依据。
- 保留 `src/`、`input/`、`public/`、`notes/`、最近成功的 `output/latest/`、显式保留的里程碑和共享 `node_modules/`。保留活动及最近成功迭代；当前轮 `scratch/` 到下一轮成功发布后才回收，失败不能覆盖成功产物。
- 不递归清理整个工作区、用户下载目录、其他项目或系统缓存。遇到历史散落文件，先识别归属与引用，未经本次任务明确授权不批量删除。
- 需要修复清理脚本时，解析并校验绝对目标必须位于预期的当前项目受管理临时目录；拒绝越界、链接绕过和当前活动目录。Windows 文件操作保持在同一套 PowerShell 或 Node API 内完成。
