# 四平台发布文案与 GitHub 配套资料

用于已有视频的发布包，不承担自动发布。先读成片事实，再为不同阅读场景写文案；不用一段营销话术填满四个平台。

## 先确定可兑现的内容

读取最新交付说明、讲稿／时间线与必要实验结果。确认主标题、系列章号、实际时长、作者名、角色名字／代词、观众将理解的问题、实际完成的实验及应用示例。较新的验收记录优先于旧版学习指南；发现旧角色、种子、指标、音乐或链接时，在发布包里采用当前事实并记录待修文档。

写稿前核对一条对应关系：封面承诺 → 开头实际可见的画面 → 正文结论及证据。用时间点或镜头号定位，核对同一对象、问题和适用条件；只拿到脚本时标为计划镜头。结论支撑不了承诺就收窄文案，画面缺证据就指出具体缺口，在已授权的制作范围内修补；不编结果，也不因写发布文案而自动重剪正片。系列名沿用本项目确认值，未统一项见 [差异记录](series-and-size-status.md)。

封面问题与发布标题保持同一主题。当前指定标题不因追求点击被擅自换掉，可以补一个方法或收获作为后半句。陌生角色不能承担唯一钩子：先说“AI 怎么画出真实图像”，在简介中再介绍踏雪。

## 网页研究要能影响写作

用户要求搜索时，优先查目标平台官方创作指引、标题与评论规则，再看与主题相近的具体科普作品。记录查询日期、URL、正文核实情况和采用的表达方法。搜索摘要只作入口；正文打不开则写明，不能从摘要补造规则。热门样例若没有可见播放量，只叫“表达参考”，不要写成“已证实爆款”。

区分官方规则、案例观察和自己的编辑建议。建议标题长度、标签数量及前两句的结构可以给实用范围，但不冒充平台强制上限或推荐算法。播放效果不归因于一个封面或固定“黄金发布时间”。

有用入口，使用时重新核验：

## 各平台交付

每个平台默认给一个推荐标题、两个不同角度的备选、可直接复制的正文和首条评论。内容简单或用户只要一句话时缩减。使用明确字段标签，研究解释放到单独文件，别混入可复制正文。

用户只要求标题与首评时，只交付这些字段，不自动扩写正文、摘要或公众号长文。

| 平台 | 写作重点 | 需要交付的内容 |
|---|---|---|
| 微信视频号 | 第一眼知道讲什么，第一段建立熟悉对象与问题 | 清楚的短标题；口语化介绍；少量相关话题；资料／讨论首评 |
| 微信公众号 | 标题提出问题，文章本身提供价值 | 标题、摘要、开篇、完整图文正文或按请求给提纲、配图位置与图注、文末仓库入口和留言引导 |
| 抖音 | 前一句出现可想象的变化，接着兑现教学范围 | 精炼钩子、准确的GAN／扩散关键词、短简介、自然问题；长课不包装成几十秒速成 |
| B站 | 可搜索问题、真实方法与观看价值 | 标题、内容路线与简介、根据当前时间线核实的章节跳转（有用才加）、出处／署名、资料首评 |

标题从具体问题、反常识结果、可操作任务中选角度，例如“为什么加噪声，反而能教会 AI 画画？”；不堆“震惊、最强、全网、彻底、一次精通”。正文像作者在讲自己做了什么：日常疑问→可观察变化→本集如何解释→可继续尝试的事情。减少“本片将”“赋能”“深度揭秘”等套话，也不把内部审查、制作困难或思考过程写给观众。

技术说法需准确：GAN的训练与生成分开、扩散的加噪训练与反向采样分开；参考图引导不等于给小型实验模型训练了该角色。用一两句自然分清实验和应用即可，不反复写防御性免责声明。宣称零基础、可运行或无需GPU前核对材料。

公众号图文应使用选中封面、真实实验图或成片截图，不生图伪造结果。图注说明图像实际含义，数字／时间点从产物核实。已有本地素材可生成小尺寸发布图，保留来源映射。用户只要文案时无需调用付费生图。

## 首条评论：资料价值在前

第一句先回答“仓库可以拿来做什么”，随后放准确入口，最后只问一个具体问题。不要开头连续求赞、关注、收藏、转发；资料访问不与这些互动绑定。

通用结构，按核实状态替换而非机械复制：

> 想把视频里的原理变成自己能跑的实验，可以从这个系列资料仓库开始。\nGitHub：<真实URL>\n目前已整理<已公开内容>。这一章你更想要<图文笔记>还是<可运行实验／具体原理补充>？我会据此安排后续整理。

本章已经公开时，直接说清目录和能做的实验；不要继续问要不要上传已经存在的同一批文件。本章尚未公开时，写“本章资料还未同步”，不能说“代码和图文都在评论区”。评论可以征集希望增加的内容，不能把未知更新时间或作者未作出的承诺写死。

完整URL用作来源／资料入口。实际平台是否支持点击、置顶、挂文章或外链，按该账号可见功能判断。给纯文本仓库名可提升可识别性，但不把它作为规避禁止外链规则的办法；不写“私信暗号领资料”、拆字、谐音或引流口令。公众号／图文还没发布时，不写“点下面的图文”“主页已有讲义”。

## 核实仓库并询问后续整理

本系列已知候选仓库为 `https://github.com/rainbowyuyu/AI_revolution`，每次仍核对仓库、分支、README与目标章节实际文件。不能仅因目录存在就断言代码已上传。公开可读也不自动等于有开源许可证，措辞依许可和文件范围选择“公开资料”或“开源”。

记录三类状态：

1. 已公开且链接可用：首评可以直接说明用途。
2. 本地已完成、尚未同步：说明事实，列拟整理范围。
3. 尚未制作：作为可选后续内容，不许当作下载承诺。

在发布文案语境中，“放出／附上我的GitHub仓库”通常表示附资料链接，不等于向仓库推送文件。只有明确的整理、上传、同步指令才授权其对应文件范围；根据完整句意判断，不能单凭“GitHub”一词扩大动作。

本系列完整发布包完成后，按作者偏好默认提供一次资料整理选项；先完成已授权的文案与本地资料清单，再用一个具体问题收尾。用户仅改封面尺寸、单句标题，或已明确不整理时省略：

> 要把本章的图文讲义、最小可运行实验、结果记录和论文索引整理到仓库对应目录，并更新首页入口吗？

询问时给具体目录、现有／新增文件范围和需要纠正的旧信息，使下一步可评估；不是每次机械增加审批。如果本会话已授权同一范围的整理上传，则直接继续。不要重复索要已有仓库地址、角色名或许可确认。

获得上传授权后才执行相应远端变更。整理的是可阅读和可复现的资料，不是整包制作工程：检查当前脚本、依赖、结果证据、许可、文档中的绝对路径和旧版信息；实际API凭据、私有配置、付费模型、第三方未授权原件及大体积视频不随资料包进入公开仓库。只有在真实更新完成并核实远端后，才能把文案改成“本章资料已上线”。

## 文件与验收

可在本次发布目录保存 `发布文案.md`、`微信公众号图文.md`、`平台研究.md`、`GitHub同步建议.md` 与所需配图；只有复用系统需要时再加JSON，不建重复空模板。一次交付包含可复制成稿与来源链接，而不只给写作建议。

检查：标题与正文一致；四平台不是机械复写；首评有用途、真实入口和一个自然问题；没有将计划说成已上传；图片和字幕不虚构；固定标题、rainbow鱼、角色代词正确；保留成片确实要求的音乐／外部素材署名。实际含AI生成音画时结合当前平台提供的标识功能说明，不擅自修改影片或添加与用户无关的警示段落。

最后给发布包入口、推荐标题与通用首评的简短预览；完整发布包按上述规则附上已具体化的后续选项。发布到平台、发评论和推送仓库仍按当前会话授权范围执行。
