# 系列封面的结构规范

继续《AI 进化史》系列、模仿第二章封面或修复文字位置时使用。**当前用户明确选择优先**；本系列新封面的默认基线是第二章真实交付版：16:9、9:16、3:4 为 V6，4:3 为 V7。四版全部左对齐、品牌在左上、无装饰短线。它取代旧模板“竖版居中标题＋左下品牌”的做法。

基准经当前／版本配置、实际成图、layout report、字体及布局锁哈希核对，不从旧 README、历史模板或截图目测推断位置。机器快照见 [ch02-approved-layouts.json](../assets/ch02-approved-layouts.json)；四版视觉结构见 排版参考图（外部或本机资源，未随公开包收录）。参考图的标记、边框和坐标仅供说明，不进入正式封面。

## 如何选择与保留基线

- 用户要求“像第二章”：读取本文件及机器快照，复用实际 x/y、字号、字重、对齐、行距、品牌尺寸与颜色。替换本期文案、背景和主体；不复制第二章的狗或扩散元素。
- 用户要求继续某个已经确认的新版：以该版真实 `layout*.json` 及交付图为基线；本文件不覆盖更近的明确选择。
- 只有用户明确要求重排时才改变坐标。若只是新短标题，允许墨迹宽度随字数变化，不能为占满旧宽度擅自放大、拉伸、居中或平移。
- 快照中的 `actualRenderedBoxes` 只证明旧文案的墨迹范围。新文本必须重新测量，不把旧字形包围盒冒充新标题安全区。

## 四比例精确排版

坐标、字号、行距均为最终输出像素，不能再乘 supersample。全部文字有效值为 `anchor: lt`、`align: left`，`supersample: 2`。标题两行，按语义断行。下表每格为 `x,y / 字号 / 字重`。

| 元素 | 16:9 · 1920×1080 | 4:3 · 1440×1080 | 9:16 · 1080×1920 | 3:4 · 1080×1440 |
|---|---|---|---|---|
| Logo：x,y,高 | 92,88,48 | 70,70,44 | 70,70,42 | 70,58,40 |
| rainbow鱼 | 155,95 / 34 / 700 | 122,76 / 30 / 700 | 122,77 / 29 / 700 | 118,66 / 28 / 700 |
| 系列眉题 | 108,245 / 32 / 600 | 72,205 / 28 / 600 | 72,172 / 31 / 600 | 70,148 / 28 / 600 |
| 主标题 | 105,325 / 140 / 850 | 72,305 / 106 / 850 | 72,260 / 125 / 850 | 70,240 / 116 / 850 |
| 主标题 spacing | 14 | 16 | 12 | 14 |
| 副标题 | 110,700 / 38 / 550 | 76,617 / 34 / 550 | 76,588 / 34 / 550 | 无独立副标题 |
| 技术行 tags | 110,900 / 32 / 600 | 76,940 / 27 / 600 | 76,640 / 28 / 600 | 74,535 / 30 / 600 |

- 主标题与署名：Noto Serif SC；其他文字：Noto Sans SC。变量字体显式设字重，不接受静默字体替换。
- 主标题渐变 `#f8efdb` → `#d3b27a`；品牌与眉题 `#dec298`；副标题 `#b4d5d4`；技术行 `#f8efdb`。Logo 保持 SVG 原宽高比。
- 3:4 将必要的主题补充合到眉题，不自动新增副标题行。眉题过长先精简内容，不推移主标题或主体。
- 两个横版采用左文右主体；两个竖版是左上品牌与文案、中下主视觉。技术行在竖版主标题下方，不放到底部。
- 默认 `rules: []`，不用短金线、破折号或细亮条补装饰。当前用户明确要求保留其他既有排版时，以该要求为准。

对应模板：[16:9](../assets/episode-landscape.json)、[4:3](../assets/episode-4x3.json)、[9:16](../assets/episode-9x16.json)、[3:4](../assets/episode-3x4.json)。模板保留第二章短文案作为已测量的排版样本，使用时替换为本期事实；相对字体路径和 `brand/rainbow-vector.svg` 按项目目录解析。

## 先锁结构，再生成背景

先从讲稿提取 1 个能画出来的变化，以及 1 个主体；必要时增加 1 个辅助道具。标题回答“讲什么”，机制回答“如何变化”，材质与景深建立空间。不要先生成占满画面的背景，再靠缩字挤进去。

为生图规划留白时，采用以下起始安全区，并以新文案真实墨迹框为最终依据。坐标为 `[left,top,right,bottom]`，都是画布像素。这些是**需要保持低细节的排版空间**，不是把一片黑矩形盖在图片上。

| 比例 | 品牌安静区 | 标题系统安静区 | 技术行安静区 | 主视觉起始空间 |
|---|---|---|---|---|
| 16:9 | [72,68,370,160] | [80,220,930,770] | [85,875,700,955] | 右侧约 x≥980；主焦点避免进入左侧文字 |
| 4:3 | [50,50,320,140] | [48,180,710,690] | [52,915,600,990] | 右侧约 x≥750；下方可延伸机制，但避开技术行 |
| 9:16 | [50,50,320,138] | [48,148,920,625] | [52,620,930,700] | 中下区域约 y≥750；不要把品牌移到下方 |
| 3:4 | [50,38,310,125] | [46,124,950,510] | [50,510,930,595] | 中下区域约 y≥620；不新增副标题占位 |

1. 精确字形框四周至少保留 16–24 px 的局部检查间距，标题与主要轮廓依尺度留更宽空气。新题目或字体实际需要更大范围时扩大背景留白，不让表内边界成为文字碰撞的借口。
2. 亮线、透明玻璃边缘、光斑、漂浮词语、概率柱与毛发也属于视觉障碍；不可穿过前景标题、眉题和署名。暗部渐变只做对比微调，不能代替重构冲突的主体。
3. 标注本次底图真实 `protected_regions`：面部、眼睛、耳尖、动作接触点、机制出口或核心候选。不要把第二章狗的旧框复制给词语海，也不要缩小保护框来使检查通过。
4. 主体和机制共享地面、透视、光源与接触阴影。生成身份参考决定外观，旧封面参考只决定结构；旧人物或动物不能因为借版式被自动带入新章。
5. 无字背景独立生成／重构；中文、准确数字、论文信息和真实 Logo 由可重复的后合成添加。横竖版各自安排构图，不硬裁带字成图。

## 词语海与概率筛选的机制背景

只在章节确实讲词元预测、概率或选择时采用。重点是可读的因果关系，而不是随机漂浮的汉字墙：

- 用明确的上下文入口连接一组候选；候选经过同一个权重区或筛选通道，再有一个结果进入延续的序列。前中后景和光路都服务这个方向。
- 海量远景只作低对比的序列节奏；少数近景候选负责阅读。用高度、大小、亮度或有规律的通道表达权重，避免同时使用多套难以比较的编码。
- 用户明确要求“文字海／中文文字点阵”时，成品必须具有明显可辨认的中文词语，不能只交空光流、发光网格或没有字的海面。以准确字体后合成有意义的字词：远处密集、较暗且有景深，中景形成候选组，近景选中词清楚可读；明暗和疏密体现筛选过程。点阵是字形表现手法，不能把汉字变成不可识别的点簇。
- 可读中文、百分比及候选名称后合成。生成模型负责材质、体积、景深、容器和通道，不能依赖生成乱码充当关键词，也不能让明亮候选越过既定标题区域。
- 若标概率，使用能追溯的数据，检查非负、归一化、精度与标签对应；没有数据时用定性的相对权重，不编造“真实模型概率”。若展示了候选子集，注明子集或包含“其他”，不能将部分概率强行当完整分布。
- 区分最大值选择、按分布随机采样与 top-k/top-p 截断。最高概率只代表更容易被采到，不代表每次必选；top-p 是累积质量边界，不是每个词的独立阈值。
- 封面用一个关键时刻说明机制，不负责复现全部计算。所选词、上下文与技术行随当前内容确定，不把某章的雨伞、狗、标题或候选词写成永久要求。

当这套机制包含承载图像的玻璃面、悬浮图板或成像层，且用户指定了图像时，读取确切原件进行透视合成，或用原件作严格保真的图像编辑参考；不能把“相似题材”当作同一张图。共享消失点、光照和玻璃厚度，以克制反射融合材质，保持原图的关键对象与关系可辨。字符、概率柱、玻璃边缘和高光不得压住核心对象，也不能用强反光或透明度把指定图像消除。

按需范例：第三章用户指定“红伞靠在蓝门旁”的原图时，原件是该章工程的 `public/media/v2/01-umbrella.png`；应保留红伞、完整伞柄及蓝门的关系，避开关键轮廓。这个路径与题材只用于该次指定素材，不是其他章节的固定主视觉。

四比例成品参考（外部或本机资源，未随公开包收录） 展示这一范例的最终组织：保留第二章文字坐标，横版右侧、竖版中下方放原图玻璃，词语沿立体微粒曲面的透视与起伏展开。参考的是文字和主体的距离、字海密度、景深及原图融合；不要把其具体词语或物件套给后续章节。前景大词周围先划出空白再放小词，避免靠透明叠加制造文字重叠。

## 只换背景时锁定现有排版

用户要求“只换背景／文字位置不变”时，不用本页新封面默认替换其已锁定布局。

1. 读取每个比例当前交付 `layout*.json`，核对成图、版本与包围盒报告。只有成图时先找原工程，确实缺失再还原并记录精度限制。
2. 冻结 `size`、`supersample`、`fonts`、`texts`、`logo`、`rules`：文案换行、x/y、字号字重、anchor/align、spacing、颜色、渐变及 Logo 尺寸均保留。新背景不能成为改字形位置的理由。
3. 保存 `layout-lock.json`：基线文件 SHA-256，冻结字段规范化 JSON 与 SHA-256，以及字体／Logo 内容 SHA-256。使用 `json.dumps(payload, ensure_ascii=False, sort_keys=True, separators=(',', ':')).encode('utf-8')`；缺失字段保留 null，不能把缺省补成新设计。移动资源可单记等价路径，但内容哈希须相同。
4. 允许更换 `background`、针对新底图调整 `crop` 与 `shades`，重新标注真实主体保护框。场景必须表达本章，并满足已经冻结的排版；冲突先重绘背景，不移动文字。
5. 完成后用同一算法比较布局与资源哈希，再看原图和 320/160 px 缩图。用户后来明确要求重排则更新基线，布局锁不是永久限制。

## 四比例验收

- 每版依次查看无字底图、带字原图、长边 320 px 与 160 px 缩图；横版通过不等于竖版通过。
- 逐项比较默认或用户指定基线的排版字段；可变标题宽度单独计算。查不到真实布局时如实记录，不以“相似”代替核对。
- 160 px 先读出主标题与主视觉；320 px 能看出候选筛选、去噪或本章其他核心关系。眉题和技术行不能承担唯一主题说明。
- 原图检查真实 Logo、汉字、背景高光、透明层边缘、前后遮挡和主体结构。机器框检测不理解透视与语义，不能关闭检测或滥用 `allow_overlap`。
- 保存本版布局报告、具体主体保护区、布局差异和人工审查结论。构图不合格先修底图；未获准重排时不能用缩字、移位解决。
