# rainbow鱼 · 视频封面与发布文案

让人先看懂“讲什么、为什么想看”，再发现画面细节。根据本片主题选择配色、材质与光线，用一个空间同时容纳生活入口和可读的机制示意；不固定深蓝黑或其他调色板。封面承诺必须由内容兑现。

封面像素默认值尚未统一。先沿用本次明确尺寸或项目已确认的配置；没有基线时，按交付平台选择一套适用模板，并记录模板来源与实际像素，不升级为全局默认。两套来源及名称差异见 [系列名与尺寸待统一项](references/series-and-size-status.md)。

若采用科普短片的 [四比例JPG模板及片尾规范](../rainbow-science-short/references/covers-and-coda.md)、[可编辑配置](../rainbow-science-short/assets/cover-template.json)与[排版脚本](../rainbow-science-short/scripts/render_covers.py)，该模板族的16:9为1920×1080，3:4为1440×1920，4:3为1920×1440，9:16为1080×1920；均为RGB/sRGB高质量JPG。左上角使用用户PNG图片Logo，右侧并排“rainbow鱼”，严格遵守[短边缩放位置规范](../rainbow-science-short/references/visual-brand.md)。后文第二章坐标、配色及旧SVG仅作为历史案例；不能覆盖当前品牌规则。修改已锁定历史排版时服从该次具体要求。丰富版示例见 `assets/topology-cover-example.jpg`。

本技能独立使用，不需要先加载完整视频制作技能。当前用户选择优先；六章、猫、机器人是《AI 进化史》的案例，不能机械套给所有未来视频。仅创建／修改技能时不启动生图或发布。

用户只要标题、简介、首评或公众号图文时，直接进入发布文案流程，不重做已确认封面。用户只改封面时，不强制产出四平台长文。

用户说“只换背景／保持文字位置不变”时，进入 [锁定排版更换背景](references/series-layout.md#只换背景时锁定现有排版) 流程：读取当前已交付的布局 JSON，锁定前景排版与字体，保存前后布局哈希。新背景适配既有文字安全区；发生冲突先修背景，不擅自换行、移位或缩字。新封面沿用本系列时，以第二章已交付四版的 [精确基准](assets/ch02-approved-layouts.json) 为默认；四版均为左对齐、左上品牌、无装饰短线。当前用户明确选择始终优先。

## 确定封面类型

从用户要求、脚本／成片说明、已选封面和品牌资产提取主题、完成范围、平台、尺寸与生成授权。已知信息直接沿用；普通设计参数可合理推断时先做，不逐项询问。

为平台准备封面时，先读 [平台封面位置与上传适配](references/platform-covers.md)，建立“平台＋展示位置→比例→文件”映射。抖音横／竖封面、B站首页推荐／个人空间封面需要分别处理；视频画幅不决定封面画幅。小红书按当前可用比例和已选构图准备，视频号现场核对。合集总封面另列用途，不拿单期封面比例代替。

| 类型 | 观众先读到什么 | 画面组织 |
|---|---|---|
| 单期教学 | 一个具体任务或问题 | 一个主视觉，辅助机制只取本期内容 |
| 系列预告 | 系列要解释什么 | 两个能力端点与连接关系，准确说明计划状态 |
| 合集总封面 | 系列名与总体价值 | 2–3 个视觉锚点，其余主题以次要物件融入 |
| 现有封面小改 | 已确认的主题 | 保留其余内容，只改指定文字、比例或对象 |

“包含所有元素”先转为主题覆盖表：涵盖所有大章，按重要性取舍物件，不把每个缩写、论文、代码和章节卡塞上去。计划中的章节可以成为合集主题，不能说成已全部完成。

## 制作闭环

1. **内容与钩子。** 确认观众问题、正片能兑现的答案和主视觉；标题可调整时，围绕同一承诺先写两版不同表达角度的短标题。每张科普封面同时满足“专业看得出原理、非专业看得懂入口”：用一个生活或工程钩子、一行章节承诺、一个可读的原理图，形成“问题→机制→结果”。详细术语和完整论文放发布文案或视频片尾。需要公开样例提炼时读[缩略图研究记录](references/thumbnail-research.md)。
2. **构图与比例。** 为主体、标题与品牌划定区域；跨横竖幅先重构场景，确认裁切安全才复用底图。读 [风格与多比例](references/design.md)。沿用本系列、参考旧封面或修复位置时，再读 [系列结构规范](references/series-layout.md)：横版左文右主体，竖版左上品牌和文案、中下主体；按实际交付坐标留出负空间，禁止从历史模板推断位置。
3. **生图与精确合成。** 生成有留白的无字场景；中文、作者名、准确数值和真实 Logo 后期排版。同一比例的两版短标题共用同一底图、裁切、配色、字体样式与品牌位置，只变标题和必要的语义断行，便于比较；不为换字重新生图。用户锁定标题或仅换背景时，按指定范围执行，不强做新标题。调用前读 [生成与预算](references/generation.md)，需要构思时读 [提示词案例](references/prompts.md)。
4. **手机检查。** 将两版并排查看原图、长边 320 px 与 160 px 缩略图，逐比例记录标题可读性、主体辨识和选择理由；先能读懂，再比较吸引力。装饰不能掩盖主体或抢走唯一焦点，出现竞争先删减装饰。按 [验收与交付](references/quality.md) 检查。
5. **交付。** 输出要求的每个尺寸，默认高质量sRGB JPG，明确需要透明版或无损文件时另加PNG；保存底图、排版配置、提示词和来源／生成记录。按 [平台映射](references/platform-covers.md) 标明每张图的展示位置、实际像素、格式、字节数和SHA256；同一适配图可以供多个位置使用。直接展示成图与绝对路径链接，说明实际生成工具。实际投稿按本次授权交给 `rainbow-publish`，由其核对上传后的裁切与应用状态。

## 发布文案与配套资料

需要发布包、平台标题、首条评论、图文或 GitHub 引导时，读 [平台文案与资料衔接](references/publication-copy.md)；需要查竞品与内容钩子时，再读 [内容与平台](references/content-platform.md)。

- 根据当前成片与公开仓库核实事实，再为本次指定的抖音、小红书、B站、微信视频号写可直接复制的标题、正文和所需首评；公众号摘要及图文按需扩展。固定标题、作者名和角色设定沿用用户最新选择。
- 文案以具体问题和可见变化吸引观众；必要限定融入叙述，来源与音乐署名集中在文末一句，AI声明填写平台专用字段。避免反复免责声明和“看点：”“特别说明：”式提示，保留实际要求的署名与事实边界。完整来源映射留在本地发布包。
- 首评第一句解释资料能帮助观众做什么，给真实仓库入口，再自然询问更想看图文笔记、代码复现还是某个具体机制。已公开、本地已完成但未上传、仅计划三种状态分别写清。
- 本系列完整发布包交付后，默认给出本章具体资料范围，再简短询问是否整理／上传 GitHub；仅改图片尺寸或标题时不额外开启此流程。对本会话已经明确授权的同一范围继续执行，不重复询问；未授权的发布或推送不由技能自动触发。

## 关键约定

- 署名严格为 **rainbow鱼**，放在 用户图片Logo（外部或本机资源，未随公开包收录） 右侧；两者常驻左上角，不用旧SVG、重绘符号或文字单独替代图片，也不擅自用于其他作者。
- 电影感来自构图、材质、光线、层次；去掉无意义 HUD、LIVE、小屏幕边框、密集小字、厚重浮雕和霓虹。本系列默认不加装饰短线。重要文字大且清楚，不遮主角。
- 科普封面必须有信息层级，但默认保持极简：系列标识＋一个4—10字钩子＋一个可视化过程。原理优先用主体背景中的虚线残影、材料粒子、荷载箭头或前后形状表达；不要放公式、代码、论文目录、参数清单或独立信息窗口。专业感来自过程和材质，不来自堆文字。
- 系列名称仍待统一：“每天5分钟科普”和“每天5分钟知识”都出现在历史技能中。本次沿用用户或项目已确认的名称；没有确认依据时可先省略系列标识，在制作记录中标待定，不擅自选一个全局名称。见 [差异记录](references/series-and-size-status.md)。
- 合集多主题共享透视、照明、桌面／地形／路径；不是六宫格拼贴或给现成小图套滤镜。
- 概念封面不冒充实测图、真实设备、论文或官方背书；确需数字与论文时采用核实的原件，不让模型编造。来源和生成事实留档，不强制全部挤到封面。
- 吸引力不能来自虚假战绩。查询平台时记录日期与来源，区分事实、样本观察和推断，不承诺“必爆”。
- 先少量候选，再针对主要缺陷修；改标题不重生底图。未知提交状态先核查，不重复付费。
- 技能没有密钥、永久预算或账号授权。当前会话已有授权继续有效，无需重复询问；新任务不能直接把历史预算当作批准。

## 离线排版工具

`scripts/compose_cover.py` 不调用生成 API，支持等比裁切、精确字体、手动分行、轻微渐变、Logo、带间距的主体保护区、文字冲突检查和缩略图联系表。依赖 Pillow；SVG Logo 另需 PyMuPDF。脚本有多种排版能力，不代表应启用全部装饰；本系列默认 `rules: []`。

复制 [16:9 单期模板](assets/episode-landscape.json)、[4:3 横版模板](assets/episode-4x3.json)、[9:16 竖版模板](assets/episode-9x16.json)、[3:4 竖版模板](assets/episode-3x4.json) 或 [正方形合集模板](assets/collection-square.json)，填入实际图片与字体。四个单期模板的排版数值来自已交付第二章，示例文案须替换；不要沿用示例的具体角色或机制。**这套历史单期模板的4:3为1440×1080，3:4为1080×1440；它们不是已统一的全局默认值。** 与前述科普短片模板的同名比例区分，以本次所选配置及实测输出为准。 相对路径按配置文件目录解析。换字后重新计算真实墨迹边界；短标题宽度不同属正常，不为凑旧宽度放大、平移或拉伸。看图后重新标注主体保护区，透明层、亮线与粒子也须避让。

```powershell
python <skill>/scripts/compose_cover.py --config <project>/cover/layout.json --out-dir <project>/cover/output
```

字体必须明确提供，不静默换成不支持中文的字体；输出已存在时默认拒绝覆盖，同名重排可用 `--overwrite`。只生成本次所需比例。用法见 [排版工具](references/compositor.md)。

## 技术教学章节的封面规则

技术教学封面先说明一个可见的机制关系，再用材质和景深强化吸引力。按当前正片选择题材，不把某一章的对象、标题或术语固定到后续章节：

- 先从正片已经使用的无字场景提取一个明确机制，再做无字底图的暗部、光线和景深调整；在后期合成一个简洁、可读的原理示意。不要把公式截图或代码墙直接塞到封面。
- 若采用“词语海／概率筛选”，必须看得出上下文进入、候选有不同权重、筛选或抽样选出结果的关系，不能只堆漂浮文字。准确中文与数字后合成；没有真实数据就不标成实测概率，最大概率候选也不等于随机采样每次必选。详细做法见 [机制背景](references/series-layout.md#词语海与概率筛选的机制背景)。
- 四比例遵循各自已验证坐标，不把带字横图压缩或硬裁成竖图；4:3 独立确定裁切窗口与主体保护区。
- 用本章具体问题作短钩子，系列胶囊明确栏目和主题；原则上不再加副文。专业与非专业信息共享同一主视觉方向，由“消失的材料”和最终形状讲清过程；完整公式、论文、实验数字留给视频或发布文案。
- 先验收大标题、主题主体与机制关系，再看 320 px 和 160 px 缩略图；160 px 仍应先读出主标题。封面交付同时保存无字底图、layout JSON、source record、布局报告和 PNG/JPG 哈希。

### 拓扑优化封面特例

当画面讲“材料被挖走、承力路径留下”时，系列胶囊固定写为 `每天5分钟·拓扑优化`，其他文字只保留一个 4—10 字的生活化钩子，例如“支架怎么瘦成这样？”。禁止公式、参数、算法缩写、论文目录和说明性小字。消失的材料用贴合支架几何的珊瑚色虚线体积表达，可配少量青色粒子与一支过程箭头；不要使用像软件选区一样的孤立矩形框，也不要把原理做成独立信息窗口。横版让标题留在左侧、支架和过程在右侧；竖版把标题放在上半部、支架放在下半部并压缩无意义留白。Logo 必须使用用户 PNG 图片，左上角与 `rainbow鱼` 并排。
