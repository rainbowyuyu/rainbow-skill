# 平台文案与投稿前校验

在实际发布前、生成可发布文案包或用户要求适配平台规范时读取。平台限制、活动资格与账号能力会变；本文件给出检查方法，不维护永久字符上限。浏览器操作沿用 `ego-browser`，投稿执行与防重回执沿用 `rainbow-publish`。

## 先锁定内容，再查当前限制

- 将视频版本、绝对路径、时长、封面比例、文案来源和章节来源写入本次计划。“最新”用交付证据消歧，不仅看修改时间。
- 记录当前投稿页或官方规则的 URL、核验日期、账号及观察到的字段限制，包括标题、正文、标签数量、章节格式、封面比例和必填声明。截图或页面文字可作为证据；不保存认证参数。
- 离线 Unicode 字符数仅作初筛。中文、表情、换行、链接、话题和提及的计数口径可能不同，填入后以页面计数和报错为准。任何超限修订后重新核对实际值。
- 校验每个章节起点不小于0、严格递增、小于成片时长，并与同版字幕／剪辑时间线对应。抖音可使用平台智能章节，生成后审阅名称、顺序和时间并确认保存；错误章节应修订或关闭，不冒充已核实导航。
- 从项目事实决定自制／转载与AI声明。自制教学视频引用新闻片段时保留来源；自制与含AI生成内容可以同时成立。不因追求原创标识删除引用或隐藏AI使用。

## 平台差异

| 平台 | 写入与回读重点 |
| --- | --- |
| 抖音 | 标题与正文分开；确认话题与真实账号提及已成为选中项；按当前页面设置竖版／横版封面及合集。检查活动必带前缀、话题、提及、时长和投稿入口。 |
| 小红书 | 分别检查标题、正文计数；正文段落保留可读性；选中实际话题候选。封面上传后确认被应用并核对裁切，不能把上传成功当作设置完成。选择对应合集和当前内容类型声明。 |
| B站 | 标题、简介、标签分别校验；清除新稿表单自动带入的不相关标签。分区与合集分别选择。简介可保留来源链接与时间导航；原生章节另行填写并检查保存结果。 |
| 微信视频号 | 区分短标题、描述、话题和合集；检查本账号当前可用的声明与封面入口，以手机预览核对截断和裁切。 |

2026-11-12的一次页面观察中，小红书正文显示1000字上限，B站显示标题80、简介2000、标签10个。它们仅是有日期的观察示例，不能直接充当未来账号或界面的规则；标题建议长度也不是平台上限。

## 活动投稿：入口也是条件

用户指定活动入口时，先打开当前官方活动详情，确认有效期、适用平台／端、内容条件、必带话题与提及，再点击活动的投稿入口。保存活动页到投稿页的实际导航证据。只有添加活动话题不能证明走过指定入口。

例如用户要求从“精选 App 征稿”进入抖音发布，就从当前对应活动详情的“去参与”或其明确提供的精选投稿入口进入，核对导航结果与关联话题。若入口明确跳到创作者中心，应如实记录官方跳转地址，不伪称在另一个客户端投稿；若活动要求与入口矛盾或入口不可用，先查活动页现有替代入口，不能绕到普通上传页后声称符合活动要求。

其他活动前缀、`@账号` 和话题按本次已核实规则设置。不得将某一期活动、截止日期或推广标签设为以后所有视频的默认。用户未要求报名的额外活动不自动勾选。

## 最终回读与校验结果

发布计划中的每个平台保留：

```json
{
  "validation": {
    "checked_at": "本次实际时间",
    "source_url": "当前官方投稿页或规则页",
    "observed_limits": {},
    "ui_counts": {},
    "status": "verified 或 pending",
    "pending_items": []
  }
}
```

先确认账号、文件名／时长，再回读最终标题、正文、已选话题、提及、封面预览、合集、分区、公开范围、AI声明和活动。页面尚无的能力或字段留作待核验，不能靠文案文件自行填成已验证。不要为展示内部检查把这些技术字段塞进公开正文。

超限时优先删重复信息、空泛修饰和泛话题，再改写句子；把设计／实测限定与教学演示性质融入正文，必要来源署名集中在文末，AI声明优先使用平台专门字段。完整研究来源留在本地，不将内部审计清单堆进公开文案。新的修订保存到本次发布计划，发布工具重新生成指纹；不能只改网页而让本地回执继续指向旧文本。

校验通过只说明当前表单满足已观察要求，不保证审核、流量或活动入选。发布后按页面证据区分已提交、审核中与公开可见。
