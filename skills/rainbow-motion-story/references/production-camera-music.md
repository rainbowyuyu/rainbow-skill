# 从音乐段试做到完整成片

适用于：音乐盖词、展示没有留白、第一人称接入翻转、机构高潮文字遮挡。方法来自 PID V04 的实际故障与修复，不指定其他作品的题材、配色或固定时长。

## 稳定镜头接力

外部相机看向一个传感器，进入传感器后又看向前方，两端视线可能相反。分别线性插值 position/target 会使它们在中途重合；即使相机位置很平滑，画面仍会突然翻转。

[camera-handoff.mjs](../assets/camera-handoff.mjs) 提供可复制的 `blendViewPose(THREE,a,b,q)`，复用项目已有 Three.js。它对视线姿态做四元数球面插值，独立插值正焦距，再重建 target；roll 走最短角度。`q` 由项目的缓入缓出函数决定。相机始终使用真实世界坐标，进入后接实际传感器节点；需要看障碍时转动真实云台或头部，而不是只更新 HUD。

```js
const pose = blendViewPose(THREE, outsidePose, sensorPose, ease(progress));
camera.position.fromArray(pose.position);
camera.up.set(0, 1, 0);
camera.lookAt(...pose.target);
camera.rotateZ(pose.roll);
camera.fov = pose.fov;
camera.updateProjectionMatrix();
```

该函数不处理穿模、构图或所有竖直视线的 up 退化。镜头路径仍需避障，检查位置、视线角步长、正焦距、主体画幅及前景遮挡。V04 用它的原始实现修复了真实 POV 视线翻转。可复用助手另验了 121 个相反视线样本、乱序采样、输入不变及 roll 跨 ±π，不把这些数值检查说成完整视觉验收。

`dollyFov(distance,K)` 使 `distance*tan(fovY/2)=K`。相机必须真实移动，检查背景视差；不变量只稳定选定平面，不能保证立体对象所有点大小不变。

## 冻结的应该是同一世界

相机时间与世界时间分离。根节点、关节、轮角、杯子、液面与物体材质动画读同一个 `worldTime`；冻结时镜头继续动。视角相关反射可以改变，物体状态不应偷偷继续。对从属状态打包比较，而不只检查根节点。旧章节 progress 驱动的伸手动作曾在章节切换时复位；应接回统一状态，而不是加长淡入掩盖。

## 音乐抬起，信息交接

每个展示窗口记录前一句字尾、动作开始、音乐源位置、结果停留和下一句字头。保留自然人声速率；同一镜头可用不同的成片时间、物理解算时间、摄影机时间和原曲时间。新公式留在稳定说明段，拆解或大幅飞行时撤掉已经讲完的重复公式。V04 的密集抽帧发现青色公式项压到花瓶，撤掉重复层后主体重新可读。

候选成形、筛选、确认使用分开的 0–1 进度。完成时检查未选路线确实归零；保存了新候选批次不代表新计划已经锁定。状态字符串和事件锁定时间应来自同一契约，避免旁白说“重新看”，画面却提前给出最终路线。

音效由真实事件表驱动：接触起声、拆件回装、候选确认、保存的轮速。缺少落杯动作就不要加落杯声。更新相机或事件来源后重新计算事件哈希；若声音样本完全未变，保留音频并记录验证，不做无意义的再合成。

## 把声音与成片分别验清楚

先比较活跃语音窗的分轨频带能量，再检查完整母带与最终 AAC。整句预让位和缓释能避开逐音节抽吸；音乐交叠检查接缝能量和实际听感。ASR、源样本比对、LUFS/真峰值、主观实听各自记状态。不能从前三项推断第四项。

几何预审、密集抽帧、原速播放、全片编码检查各有范围。稀疏静图不能证明没有瞬间遮挡；位置连续也不能证明 target 没有翻转。问题修正后保存前后证据，勿放宽阈值隐藏失败。

长片分段渲染记录源码、时间线、数据、字体、音轨、实际 bundle 的哈希。断点续跑须校验输入和片段文件；只重用已证实不受修改影响的片段。磁盘不足时可把可重建渲染放在另一盘，但最终交付文件和 TTS 源句要回到项目的可持续位置，不能依赖系统临时目录。不要在渲染中途修改其固定输入。
