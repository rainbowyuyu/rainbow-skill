# 线稿的体积、材料与过程

适用于机械原理、实验装置、结构拆解、流程空间和需要短暂停下来读的工程图。参考来源为沁雨莲的 AI 工厂作品；实际观察范围与时间码见 [逐段研究](../studies/qinyulian-linework.md)。用 [原创工作台](../lab/ui-line-studio.html#engraved-flow-path)比较黑场与纸白两种表达，接口见 [engraved-mechanism API](../examples/engraved-mechanism/API.md)。

## 让实体成立，再决定画哪些线

这条参考的线稿保留了实体体积：前面挡住后面，形体承受光线，排线随表面弯转。深橄榄黑背景、灰白实体与少量暖金构成稳定层次。把所有三角面边同时画出，容易得到杂乱的透明线框；为“手绘感”逐帧随机抖动，也会让金属和结构失去重量。

线条应有分工。轮廓告诉观众物体在哪里；结构线说明接缝、面与装配；尺寸和引线用于当前解释；隐藏线只在明确约定的技术视图中出现。三类线用不同宽度和明度，先保证轮廓，再加细节。手机尺寸看不到的密线应合成明暗，不能强行保留成噪声。

| 表达 | 适合解决的问题 | 材质与动作 |
|---|---|---|
| 黑场雕刻 | 从局部部件进入内部关系、沿工艺路线追踪 | 深背景、灰白实体面、随表面的排线；暖金只突出当前过程 |
| 纸白工程图 | 解释构造、比例、部件对应，提供阅读停顿 | 轻纸色、墨线；结构→排线→尺寸，拆开和回装保留 ID |
| 空间流程旅行 | 多步骤怎样成为一件事情 | 给每步一个可辨认的工位，沿物体运动或管路移动；关键控制点回访时改变状态 |
| 局部到全局 | 一台机器怎样属于更大的网络 | 保存主角位置与方向，先退到周围空间，再揭示整个网络；跨尺度降低细线密度 |

后两项来自参考观察和制作建议，当前新增的两项代码只实现有限机构短段，没有完成整座工厂或全球尺度镜头。

## 排线必须跟着形体

平面可用面内方向场，圆柱用轴向或环向的局部线族，弯面可用 UV/几何等高线。排线先在部件局部坐标生成，再通过同一物体与相机变换投影。用可见面裁切线条，前景实体遮住背后的线。

把线密度与屏幕投影联系起来。当前样例在线距约 1.7–5 像素间逐渐减弱排线；阈值是此画幅下的候选，需要按输出尺寸检查。更复杂的正式影片使用屏幕导数、mipmap 或解析过滤，并做连续推拉验收。只在静帧上锐化会加重运动摩尔纹。

细线、颗粒和纸纹使用稳定种子或固定纹理。部件转动时纹理跟着部件，背景纸张不动时纹理也不动。明暗可以随真实灯位变化，不能让每帧噪声伪装成“有生命力”。

## 描画顺序是一种讲解顺序

参考 106–110 秒先建立图框与主体，再补其他观察视图，随后实体明暗转轻线，返回黑场机器。可借鉴其“先认出、再比较、再解释”的节奏。不要把整个 SVG 从头到尾匀速扫描，当作有逻辑的绘图。

一笔至少保存 `strokeId / partId / role / points / revealStart / revealDuration`；按弧长控制描画进度，独立笔画之间抬笔，不画跨空白的连接线。中心线、轮廓、孔洞、尺寸可以不同时间出现，但尺寸端点和结构必须共享几何数据。

原片的图版具有多个观察视图；当前纸白候选是同一机构的单一正交投影拆装，不认领三视图复刻。需要正式多视图时，复用同一三维模型和部件 ID，分别设置相机；不要手画三个互相不一致的轮廓。

## 光色如何承担语义

灰白负责实体，深色负责空隙与空间，暖金集中在当前动作。金色不应把整件物体照成均匀霓虹。要讲流向，让颜色沿明确路径传播；要讲通电，颜色跟随电路事件；要讲温度，则读真实温度标尺，并保留单位。艺术强调不能伪装为物理计算。

当前黑场样例的金色虚线明确标为“流向示意”，不输出流速、压强或流量。正式影片应由仿真/实验状态驱动几何、粒子、数值与标注。开盖是教学动作，应先建立停机/示意语境，不能让观众以为真实高速设备可运行中拆盖。

## 代码、接入与检查

```js
import {sample, draw} from '../lab/modules/engraved-mechanism.js';
const opts={id:'engraved-orthographic-assembly'};
const s=sample(frame/fps,opts);
draw(ctx,frame/fps,width,height,opts);
// s.parts / faces / camera / drawProgress / hatchProgress / flow
```

本样例使用有限凸面深度排序与真实数学投影，适合试选线条、节奏和构图；它不是通用三维渲染器、光追或流体求解。接入 Blender/Three 正式场景时保留局部排线、部件身份和事件表，遮挡由深度缓冲与真实网格处理。不可将本例的平均面深度算法用于任意交叉网格而宣称无穿模。

本次实际画面检查发现，单按面中心排序会让叶轮越过已闭合的盖板。代码现针对这组有限机构，根据盖板/壳体平面的三维关系与实际投影裁切内部叶轮；合盖遮住内部，开盖只露出未被遮挡的部分。修法保留几何关系，没有按时间把叶轮整组藏掉。这个案例说明首尾截图与平均深度测试不足以证明遮挡正确，必须看真实中间画面。

重点复看：拆开一半时的遮挡、盖板孔与螺栓、镜头缓慢推拉时的排线、回装前后的位置与速度、标注是否压住主体、深色与纸白交接时的对象身份。稳读窗口应有真正停留，不是所有线条一起呼吸闪烁。音效另按接触、绘制和装配事件安排；没有主观听审的来源不据画面猜原音色。

更多方向可比较 Lemo 的 `engraving / blueprint / urban-sketch`，查 [图谱](../lab/lemo-atlas.html)和 [辅助技术来源](../studies/ui-line-principles.md)。选择一种主材质，再组合必要的局部方法。
