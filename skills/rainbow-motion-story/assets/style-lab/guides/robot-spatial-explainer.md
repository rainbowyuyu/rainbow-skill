# 空间解释镜头：从实体到数据，再回到动作

适用于机器人、导航、传感器和机械原理片。问题是观众看见了漂亮数据，却不知道它从哪里来、改变了哪个实体。来源研究见[林花钱 RoboCup](../studies/robocup-blender.md)；可运行实现见[Blender 小样 API](../examples/robocup-blender/API.md)。这里的镜位与色值是原创候选，源片未公布这些参数。

## 先约定一个可追踪的世界

保存实体 ID、安装位姿、障碍边界、目标点与单位。相机、扫描、路径、标注读取相同世界坐标。Blender 用米和 Z 向上；网页数据若 Y 向上，应转换整个坐标系，不只旋转模型。

每个镜头记录：

```text
question       观众此刻要看懂什么
anchorBefore   从上一镜保留下来的可见实体
worldState     该时刻真实数据或明确标记的示意数据
representation 实体 / 点 / 体素 / 场 / 路线 / 局部结构
camera         position, target, roll, lens, focusAnchor
readWindow     结果能被稳定阅读的区间
anchorAfter    交给下一镜的物体、位置或动作
```

不要为了让转场方便而换障碍位置。展示拆解偏移独立于工作位姿；在拆开状态下不要继续伪造正常的传感器与控制输出。

## 五条可挑选的镜头配方

### A｜靠近眼睛，再展开世界

**适用：** 雷达、相机、扫描和观测。先低位/三分之四建立实体，再轻推传感器；第一束射线出现时稳住；命中点扩展到环境后，镜头升高并后退。旋转角度由需要揭示的遮挡区域决定。

- 射线始点 = `sensor.matrix_world @ local_origin`。
- 命中点取实际场景射线求交，保留命中对象、距离和世界位置。
- 点出现的动画改变其局部大小/亮度，不能缩放整组世界坐标，导致点飘离墙面。
- 用有限扫描范围解释未看见区域，不把未知格直接画成可通行。
- 读一个测距结果时镜头减速；扩大范围时才给较大视差。

原例：`build_demo.py` 的障碍求交与 `camera_samples`。这不是具备噪声、遮挡融合和重建误差的真实 LiDAR 仿真。

### B｜同一张地图，拆开信息层

**适用：** 地图融合、多传感层、置信度、建筑系统。先保留同一地图边界，将层沿一个轴分离；镜头从平面读法转到斜俯视，使间距看得见。每层进入时只强调该层新增的信息，再依次压回一个坐标空间。

- 层几何共享 XY 原点与尺度；只加展示用 Z 偏移。
- 标注靠近对应层边缘，不跨过中心主体。
- 风险区、障碍区、目标色的含义跨镜固定。
- 真正合并时用实际数据运算；简单叠加显示不能声称完成地图融合。

这是可复用配方；当前原创短片着重实现距离代价场，未复刻源片全部多层地图。

### C｜把代价变为能看懂的表面

**适用：** 代价、误差、风险、速度等标量场。先给障碍与二维场，再把数值编码成高度，机位降低，让高度差可读；展示路线时抬回能辨认绕行关系的位置。场的高度不是地形，单位和色标必须说明。

- 字段数据与渲染网格分开；显示插值不得改写计算结果。
- 路线、障碍膨胀和机器人实际包络保持一致。点机器人找到的路线，不代表实体能通过。
- 折线平滑后重新核对扫掠区域，不能直接使用越过障碍的贝塞尔曲线。
- 路线 z 从同一表面函数取值，增加很小可见间距，不任意悬空。
- 有限时窗可先显示候选再显示提交结果；没有计算候选就不伪造“思考过程”。

原例中的 signed-distance 代价和 A* 用于解释程序几何，不是训练扩散或世界模型的实验结果。

### D｜沿命令进入机器

**适用：** 控制器、执行机构、电子装配。先停住整机，让目标和路径暂留；焦点从机身移到控制板；沿真实装配轴开盖，摄影机绕到可见一侧。命令进入控制板后再分到执行部件，最后回到整机动作。

- 控制板、线缆、轮轴拥有真实父子关系，不能跟着屏幕转。
- 上盖拆开位姿单独记录，固定件和线缆的演示方式要合理。
- 先用不透明材质、关闭景深/模糊检查前后关系，再加局部透明与焦点。
- 拆开极值处留足画面，避免上盖在边缘被裁掉。
- 相机近裁面不切进外壳；遮挡不靠关闭深度测试解决。

原例通过金属上盖与内部控制板实践这一条，并未建立真实电机控制回路。

### E｜从路线收束到交付点

**适用：** 送物、接触、装配完成、任务闭环。路线全景回答“去哪”；动作前以侧面或三分之四视角读接触距离；机构伸出时镜头只跟随需要观察的末端。动作完成后稳定，留下一眼能懂的结果。

近景仍需保留托盘边、门框或地面的一部分作为参照。镜头停止不等于实体瞬间停止；有真实动力学就读取它，没有则明确为运动学演示。当前示例没有声称完成真实交付仿真。

## 材质、景深与大角度的实际起点

本机 Blender 5.1 的接口、试验和官方文档见[技术底稿](../studies/robocup-blender-technical.md)。下列是选择方法，不是源片参数。

| 部分 | 可比较的候选 | 要检查的画面 |
|---|---|---|
| 机身 | 深石板底色、浅金属边、低强度青色传感器、暖色数据 | 灰度下主体与背景仍可分；不靠每条边发光 |
| 金属 | 几何倒角＋宽主光＋条形侧光 | 转动时高光随实体变化，不出现贴在屏幕上的亮边 |
| 轮胎 | 较高粗糙度、有限几何纹路 | 远景不闪烁，近景有接触与厚度 |
| 透明 | 局部开盖 / 裁切 / 弱结构轮廓中选择 | 内部有清楚的前后关系，背面不会压过重点 |
| 镜头 | 从低到高、斜俯视、贴近部件；roll 只辅助转向 | 大角度后能落稳，目标与地平线不无故翻转 |
| 景深 | 焦点 Empty 绑定当前部件；先比较较深景深 | 零件清楚，文字不糊；不拿景深掩盖穿模 |
| 模糊 | 用真实快门采样运动；先小快门验证 | 静止轮廓清楚，运动方向正确，切点不混叠 |

构图、roll、焦距、焦点应分别参数化。源片的多角度效果不能只靠不断转 Y 轴模仿。相机局部滚转要围绕观察轴，目标交接需连续；穿过正上方时单纯 `to_track_quat` 可能翻转，应改变路径或使用连续 up rig。

## 接入已有技能

- 与[运镜景深](camera-depth.md)结合：焦点交接必须与要解释的实体一致。
- 与[速率曲线](rate-curves.md)结合：靠近原因时建立期待，结论到位后停住；真实数据不加审美缓动。
- 与[机构](anatomy-mechanics.md)结合：工作位姿和拆解展示分离，按装配轴移动。
- 与[Motionface 文字](motionface-type.md)结合：先有物件变化，再让标签出现；保持基线与最终排版。
- 与[声音事件](sound-design.md)结合：扫描、命中、锁定、扣合各读真实事件；不为每个点加声音。
- 与[逐句配音](expressive-voice.md)结合：镜头进入前提出问题，停住时解释，结果显现后留呼吸。

## 完成条件

看过代表静帧，再看关键动作前后相邻帧。检查扫描点是否贴物、路线是否可通行、拆解是否重叠、零件是否越过近裁面、透视变化是否改了前后关系。关闭景深和运动模糊能帮助定位问题，但最终须恢复目标设置再验。

保存脚本、可独立重开的 `.blend`、关键状态参数、引擎与分辨率、连续样片和实查范围。生成动画、成功解码、源帧联系表观察、连续播放和音轨听审是不同证据，分别记录。只把通过实际运行的方法标为可复用，预定配方明确标为尚未制作。
