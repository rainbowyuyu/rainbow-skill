# 同一个对象，怎样带出下一问

用于解释顺序、数量、迭代规则和状态空间，也适合需要跨实体与公式的科普片。观察依据见[洗牌全片研究](../studies/shuffle-story.md)。以下是可供选择的原创制作方法，不要求每部片子沿用同一种故事。

## 先选观众的问题

| 结构 | 适合什么问题 | 画面要提供什么 | 容易失败的地方 |
|---|---|---|---|
| 小例子长出公式 | 数字知道了，来源不明白 | 每步操作与一个因子/一项共用状态 | 公式提前出现，实体只作装饰 |
| 结果之后问条件 | 观众刚得到一个有用结论 | 改变一个真实条件，显示它怎样影响结果 | 无依据地编造反转 |
| 保留身份，揭开循环 | 表面变化大，但规则可追踪 | 初态参照、固定ID、精确重排和最后一次完整操作 | 每轮随机改颜色，观众找不到来路 |
| 同一目标，更换方法 | 要比较人工与算法或不同方案 | 共同评价指标，方法改变而对象不变 | 每个方法独立讲一遍，失去比较 |
| 数量换尺度，再回到手边 | 大数难想象 | 比较假设、单位和清楚标出的线性/位数/对数坐标 | 把视觉长度当真实数量比例 |

为每段写下当前问题、一次操作、可见证据、带条件的结论和下一问。下一问由刚得到的证据引出。新术语进入时，观众应已见到它描述的关系。

## 让运动密度跟着理解任务变化

第一次建立规律，给操作足够的辨识时间。重复部分可用状态接力压缩，留下初态与末态。结果发生的关键一步应展开过程，落定后保留比较，最后再把注意力交给新对象或新问题。

这不是一条固定的快慢曲线。需要追踪身份的动作可以速度平稳，连续重复可分批加速；结论阅读时让主要几何静止，背景只保留不妨碍阅读的轻运动。镜头抵达与文字读窗分开控制，不能靠一个全局ease同时完成所有任务。

| 动作阶段 | 原创6牌样例的时间 | 解释职责 |
|---|---|---|
| 牌移到槽位 | 每步0.9秒 | 看见本次选择 |
| 因子从牌接到公式 | 随后0.4秒 | 明白数字对应这一步的选择数 |
| 局部结果停留 | 随后约0.85秒 | 看完这一位，再开始下一位 |
| 全部结果 | 14.4–15.1秒显现，15.1–20秒稳定 | 读清720及其对象；最后留白 |

这些是示例设计值，不能冒称原片节奏或所有题材的最佳秒数。接入实测TTS后按句子调时间，保持事件的先后关系。

## 用稳定身份连接视觉效果

每个对象保存`id`和`originalRank`，颜色映射绑定身份。位置与排列可以改变，ID不能在过场时重建。新出现的标签、轨道或符号从对象当前的位置出发，并在下一次操作前退场，避免全片积累辅助线。

大变化留给有语义的事件：翻面改变信息可见性，散开显示所有成员，收拢恢复整体。镜面、辉光和粒子只在有明确作用时增加。用少量字体与稳定字号建立层级，正文读窗保持高对比；避免把细彩虹线当成唯一的数据编码。

## 讲稿和画面共用时钟

[新工作台](../lab/shuffle-story.html)的两个讲稿分别20秒和22秒。它们是原创小例子，可逐句定位和导出；目前未合成语音，`timingBasis`为`planned`。

```js
import {sampleOutShuffle} from '../lab/modules/shuffle-explanation.js';
import {beatAt} from '../examples/shuffle-story/narration-plans.js';

const t = frame / fps;
const scene = sampleOutShuffle(t);
const beat = beatAt('storytelling-perfect-shuffle', t);
// scene.settledOrder 表示已完成的顺序。
// scene.targetOrder 只是正在前往的顺序，不能提前用作结论。
// scene.readHold 包含几何、文字和对照线已稳定的要求。
```

“回来了”放在第三轮17.7秒完成之后，完整对照关系在19.3秒稳定。前一段只提出第三次会怎样，让观众先看见。六牌的数值由`choiceProduct`计算；八牌的顺序由`outShuffle`推导，不在文案中手写一套独立答案。

这里的8张牌三轮复原来自上半先出的精确外洗，52张牌同一规则是八轮；不要用同一个结论配不同的演示。计数滚动时避免出现不成立的等式。讲稿语言清理遵循用户指定的去AI味规则，不删事实限定词，也不把问句本身视为问题。

## 声音跟着什么走

落牌可以用轻接触声，因子提交可用一次细小确认，整轮归位才给较明确的落点。连续交织时可选择少数接触点或随运动变化的摩擦层；不必每个成员都打一声。声音事件来自与动画相同的状态表，跨帧时按事件时间触发，定位时不重放已过去的瞬态。

读公式时减少新声音与大幅运动，高潮用于已建立规则后的变化释放。旁白不要预先把揭晓说完。更具体的音量、尾音与让位方法见[音效指南](sound-design.md)，可在[三配法工作台](../lab/shuffle-rhythm.html)选择配法。参考原声本轮只有信号分析和播放运行记录，音色判断需要实际试听。

## 接入与验收

1. 从两种[候选接口](../examples/shuffle-story/API.md)中选观察任务合适的一种，保留公共依赖；无需新增node_modules。
2. 替换对象与数据时重新计算结果，不把表现曲线当求解器。保存来源、单位和算法条件。
3. 用真实配音替换计划时长，调整动作锚点；局部结论与最终结果都要有稳定阅读窗口。
4. 检查乱序定位和同时间重复采样，逐帧看阶段边界；观察身份、颜色、遮挡和等式是否一致。
5. 分别验静音画面、旁白逻辑、完整音画。自动检查可以证明索引与时间关系，不能证明观众一定看懂或声音一定悦耳。

先做一个机制段，确认它能解释，再扩到长片。完整源码与测试均随技能安装，原参考长视频仍在既有缓存按需读取。
