# 让文字、颜色和画面一起解释

需要进一步选择文字入场、图形转义或结果接力时，读 [Motionface 文字与图形指南](motionface-type.md)，在[六方法工作台](../lab/motionface.html)试换文案与配色。它补充一次有限揭示、环字归位、对象接棒、阅读落定和焦点交接；已有的公式身份、实体标签和数据颜色规则继续保留。

文字已有规范、整体画风仍难选择时，使用 [审美方向指南](aesthetic-direction.md)，在[三方案工作台](../lab/aesthetic-direction.html)比较同一对象的层级与留白。保留数据颜色角色，再选择材料与构图；[公开设计资料](../studies/aesthetic-design-principles.md)区分参考观察和本项目的视觉决定。

先写出观众这一刻需要看懂的一个变化，再决定文字要不要移动。标题建立问题，标签认出对象，公式解释关系，字幕承接口语。四者各自承担任务，画面才会有清楚的主次。

公开样本与出处见 [研究记录](../studies/type-color.md)。四个 12 秒候选均是 `loop:false`，最后一帧应停住，由用户重播或接下一镜。

## 按当前问题选候选

| 问题 | 候选 | 选择理由 |
|---|---|---|
| 每一个字都在动，观众抓不住重点 | `type-semantic-emphasis` | 保持词位，语义重音从变化交给结果；3.5–8.5 秒供阅读 |
| 标注离物体太远、线条交叉 | `type-anchored-label` | 说明靠近测量点，沿清楚的路径调整位置，最终把注意力交给误差 |
| 公式换行后观众找不到同一个量 | `type-equation-identity` | 保留 V、I、R 的身份，分别迁移；符号增减有顺序 |
| 配色多、量与颜色的关系不稳定 | `type-palette-attention` | 角色颜色固定，只改变焦点，保留文字与几何关系 |

```js
import {candidateById} from '../lab/modules/index.js';

const demo = candidateById['type-equation-identity'];
const time = Math.min(12, frame / fps); // 非循环镜头抵达末帧后停住
demo.draw(ctx, time, 1920, 1080, {intensity: .65, palette: 'titanium'});
const state = demo.sample(time, {intensity: .65, palette: 'titanium'});
```

用这个接口比较方法后，再把 `sample` 中的教学状态换成工程数据。文字、仪表、图线和物理实体应读同一个值；不要让它们各自播放一条看似相近的动画。

## 四种可直接编排的文字段落

**语义重音。** 一句分成“对象 / 变化 / 结果”，只在旁白提到的词上短暂增加字重、亮度或下划线。句子落定后，文字位置不再上下呼吸。呼吸可以留在光线、环境或与主题相关的物体运动里。

**实体注释。** 先看见对象，再在附近出现短标签。标签贴近投影点，leader line 避开主体轮廓和其他文字。镜头跨过对象时重新判断左右可用空间，用一条连续迁移路径换边；不因几像素变化每帧反复跳侧。对投影到近裁面后方的对象，应按设计退场，不能把错误坐标压到屏幕边缘。

**公式变形。** 给每个量一个持久 ID：`voltage_V`、`current_I`、`resistance_R`。先保持等式可读，再把 R 移入分母、收走乘号、显出分数线。新的布局落定后才开始代入数值。颜色只辅助识别量，字母和单位始终保留。

**材质标题。** 章节开场可固定字形轮廓，内部流动一种与内容相关的质感，如水、纸、金属扫描光。配套字幕仍用稳定实色。Carbon hero 的字形填充是一个可观察的方法来源；不要把原片影像、字体样张或人物当成自己的素材。

1920×1080 输出可从三个字号角色试起：主标题约 80px，重点说明约 46px，必要标签约 34px；字幕独立约 46–50px。数值只是候选起点，要以手机缩小预览和最复杂背景为准。默认一套中文字体、两个字重，英文/数学字体只为缺字或公式排版补充。

## 六套角色配色

完整可读数据在 [role-palettes.json](../examples/color/role-palettes.json)。这是可选配方，不改工作台已有的三个运行时配色。背景色指稳定的说明区；叠加到真实场景时需重新检查局部背景。

| 配方 | 背景 / 正文 | 强调 / 对照 / 误差 | 气氛与用途 | 避免 |
|---|---|---|---|---|
| 石墨暖金 | `#101722` / `#F4EFE5` | `#E8B56B` / `#75D9D7` / `#ED8774` | 精密机构、深色实验室；暖色指出正在解释的部件 | 所有材质和数据都刷成金色 |
| 瓷白蓝墨 | `#F1EEE7` / `#20343D` | `#8C4F26` / `#1D6873` / `#9B4149` | 推导、论文、结构对照；用明快留白承载信息 | 直接叠在白浪、强光或白色实景上 |
| 夜紫杏金 | `#1C1425` / `#F6EEE8` | `#EFB78B` / `#B6B2ED` / `#ED8D97` | 夜景和尺度展开；柔和而有暖色落点 | 把装饰性紫色自动解释成负值 |
| 深海青玉 | `#08252B` / `#E8F3EF` | `#E8B77B` / `#6FD3BD` / `#E7A094` | 水、环境、传感；暖金与青绿形成观察层次 | 水和数据线同色同亮度，轮廓无法区分 |
| 暖幕琥珀 | `#241719` / `#F7EEE7` | `#E9B466` / `#A9C9CA` / `#F49B93` | 音乐驱动段、历史机制、暖色实体故事 | 红橙画面上再铺暖色小字 |
| 钴蓝编辑 | `#F4F2EB` / `#172E55` | `#294E9A` / `#8B4D24` / `#A33C48` | 明亮科普、图表、纸面说明；深蓝负责秩序 | 将整块亮背景无来由地盖在夜景上 |

每套另有 `muted` 用于上下文，目标、观测和误差分别绑定 `accent`、`compare`、`warning`。主题变化时可以更换整套配方，但同一幕内同一个量不应悄悄换角色。误差同时保留正负号、数值或区间，不依赖红绿辨别。

已按 WCAG sRGB 相对亮度公式计算每套 5 个前景角色与指定纯色背景的 30 个精确色对：最低值分别为 **7.124、4.748、7.531、7.523、8.218、5.362**，均高于 4.5。详细逐色结果在 JSON。此计算只涵盖不透明纯色；透明度、渐变、辉光、实景高光和视频压缩会改变实际可读性。

## 数据颜色按任务选择

| 数据问题 | 编码方式 | 必须同时交代 |
|---|---|---|
| 哪个类别？ | 类别色，每类稳定色相，加名称/形状 | 类别名称，固定映射；不能按排序重新分配颜色 |
| 数值有多大？ | 顺序色标，感知明度单向变化 | 固定量纲、最小值/最大值、图例；不要逐帧自动拉伸范围 |
| 比基准高还是低？ | 发散色标，两侧围绕有意义的中点 | 明确零点或基准值、正负方向、两侧范围 |
| 当前在解释哪个对象？ | 焦点强调，其他对象退为上下文 | 保留原本数值编码，避免强调色覆盖符号含义 |

设计梯度时可在 OKLCH 中先确定 L 的变化，再挑选 C 与 h；导出到 sRGB 后检查是否越界或压缩。若用普通 RGB 插值，就按实际实现标注。当前 `type-life` 示例使用 sRGB 通道插值。

## 让运动留下阅读时间

一段变化可以分为四个动作：建立对象、改变一个条件、停住看结果、把焦点交给下一对象。文本不必从第一帧完整亮起，重要的词也不必一直弹动。先给当前层级一个稳定位置，再出现下一层级。

Carbon 的 UI 时长 token 可帮助理解不同运动量的差别；影片的时长应由中文口播、方程复杂度和观众需要的观察时间决定。大镜头段落少放字，关键公式出现时降低背景和相机的变化率。工作台保留暂停、逐帧/拖动、降低运动的入口。

## 接入后的检查

1. 在原尺寸与手机缩小尺寸看最复杂的一帧；检查正文、单位、标注和片头标题。
2. 抽查每个文字变化前后：对象能继续追踪，同一字母没有复制成两个互相矛盾的量，标注线不交叉。
3. 在亮、暗、渐变端点及实际背景上测对比；文字不因透明退场而长期停留在半透明难读状态。
4. 检查颜色含义：灰度下依然能通过名称、位置或符号分辨重要状态。
5. 用相同 `t` 重画、倒序 seek，并检查观察停留段的位置变化量为零；最后一帧不会自动跳回开头。

用检查结果选择适合当前故事的方法。将原始值、单位、有效范围和字幕窗口保留下来，下一次更换主题时就能复用编排与呈现，而不把上一期的事实和视觉语义混入新片。
