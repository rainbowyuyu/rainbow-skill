# 音乐、音效与连续视觉：把重音放到结果上

用于连续轨迹、流程演进、焦点接力、年表、多个方案收束等片段。先看[研究证据](../studies/syy-rhythm.md)，再打开[三种编排](../lab/syy-rhythm.html)试听和逐帧比较。它补充已有的[音效时机](sound-design.md)和[疏密选择](shuffle-rhythm.md)，不替代实际曲目的听审。

## 先定一句话，再定一组声音

把一个动作拆成四个时刻：准备、结果成立、观众看清、交给下一段。声音的起音、包络峰和结束分别对齐这些任务。准备声可以先进入；低频重音或确认音通常落在到位、会合、提交等有意义的结果；尾部可以进入下一镜，但不能盖住新解释。

| 画面任务 | 可试的声音 | 怎样落点 | 何时少用 |
|---|---|---|---|
| 连续前进 | 持续音床、稀疏脉冲 | 保持乐句，不给每个物体重复加声 | 阅读任务已经很满时减少高频脉冲 |
| 接近目标 | 上升气流或逐渐收窄的频带 | 提前起声，抵达前后回落 | 运动很慢或距离很短，不必加掠过声 |
| 完成换位 / 装配 | 短确认音、局部接触声 | 对齐真正的状态变化 | 同时有旁白关键词，先避让 |
| 多条线汇成结果 | 一次主要重音与较长尾部 | 最大重量留给共同结果 | 不把每条线的到达都做成主重音 |
| 引出未知 | 保留音床，减少节拍或缩小频带 | 先让已知收束，再让新点进入 | 不用持续升调制造没有答案的紧张 |

这些是候选音色，不是对 syy 原片音效的鉴定。接触声用真实接触事件；纯图形强调可以用合成音，但标为声音设计。

## 呼吸有三个独立旋钮

**能量、密度、空间。** 降低音量但保留节奏，会让段落继续向前；减少音效次数但保留长尾，会让空间变宽；固定镜头和对象，让字幕读完，会让观众重新掌握方向。不要用“所有东西同时慢下来”代替编排。

音乐高潮之前，安排一段真正需要理解的动作；高潮到来时让观众看见这个动作的结果，而不是再引入三个概念。片段需要留白时可保留环境声或和声底，撤掉竞争性瞬态。最终比例必须与实际旁白混听，纯音乐试作不证明对白可懂度。

## 连续画面靠身份与路径连接

1. 给主角、轨迹、标签一个跨镜不变的 ID。相机改角时，路径的世界位置不变，色彩意义不变。
2. 整体持续运动时，只让正在讲的节点获得最强亮度和最清晰的标签。其他节点仍然存在，但降低权重。
3. 强调采用短亮点 → 小环 → 扩大并退去的层次。发光作用于物体和轨迹，文字保持清晰边缘。
4. 空间转向需要一个过程：保留背景视差、前后次序和轨迹方向，不用一次全屏闪光遮住重置。
5. 多线收束前先撤掉会挤在一起的标签，再显示共同结果。结尾由旧轨迹继续变形，新问题才有来处。

若位置代表真实数值，不能为了配乐让领先者提前、改变相交点或捏造排名。保留数据时钟，另给相机、显示进度和音乐源文件建立映射。

## 一份事件表同时驱动画面和声音

```js
const events = [
  {
    id: 'result-approach', objectId: 'route-07', kind: 'air',
    onset: 13.3, peak: 14.36, end: 14.7,
    semantic: '三条路线接近会合', pan: 0,
  },
  {
    id: 'result-committed', objectId: 'route-07', kind: 'impact',
    onset: 14.4, peak: 14.4, end: 15.8,
    semantic: '三路会合完成', pan: 0,
  },
];
```

这是接入自己工程时的事件结构示例。当前 `buildPlan(id)` 生成内置事件，`renderAudio(id, sampleRate)` 不接收外部事件表；复用时应修改计划生成和合成入口。预备气流与落定重音是两个事件：本例 `impact` 在 `onset` 起音、持续 1.4 秒，不以 `peak` 延迟起音。`peak` 不是实际波形最大采样点；如果要显示实测能量，应从对应分轨计算。声音事件的持续范围必须覆盖合成器真正输出的尾部。

播放时以 `AudioContext.currentTime` 为主时钟，两条分轨先准备 buffer，再用同一个开始时间和 offset 启动。换候选、暂停和跳转时让旧 source 退场并失效旧回调；不要在逐帧绘制中重复触发同一声音。真正静止的观察窗要冻结相机和主体，声音尾部可以继续。

## 如何选择本例三个候选

| 候选 | 适合内容 | 应保留的约束 |
|---|---|---|
| `pulse` 脉冲接力 | 多个短因果步骤、机械提交、流程推进 | 短促动作后必须看得到结果 |
| `legato` 连奏航行 | 长轨迹、空间旅行、演进与关联 | 少音效不等于没有语义重点 |
| `suspended` 悬停后释放 | 会合前的期待、最后决定、关键装配 | 悬停有观察任务，之后必须兑现 |

代码入口是 [signal-relay.js](../lab/modules/signal-relay.js)，实际接口见 [API](../examples/signal-relay/API.md)。原创建议拍速为 100 BPM、长度 24 秒，均不是原片测量，也不是以后固定模板。

工作台支持逐帧、精确定位、分轨音量、三种候选、PNG / JSON / WAV 导出。音乐行显示合成音乐分轨的 100 ms RMS 包络；音效行显示事件持续范围。当前音色未做主观听审，使用前在实际音箱与旁白下试听。

## 接入自己的影片时检查

- 先关声音看一遍：能否辨认主角、原因、结果和交接？
- 再仅播放音乐：段落高低是否支持故事，而非每隔固定秒数重起？
- 单独试听音效：一次事件是否被过多声音重复解释？尾部是否过长？
- 合并旁白：术语、句尾和关键因果词是否清楚？
- 任意跳转与倒序：对象、文字、声音事件是否仍是同一状态？

将实际听看结论写入工程。没有完成的部分保留“待听审”，不把数值峰值、测试数量或几张漂亮静帧当作完整验收。
