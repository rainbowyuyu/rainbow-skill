# 文案、解释逻辑与剪辑

先写观众看完能回答的一个问题，再写答案。把支撑答案的事实列清楚，给不确定结论保留条件。需要重构时，先改故事和证据顺序；成稿后再使用用户指定的去AI味规则做最小清理。

## 挑一个适合内容的入口

| 入口 | 何时使用 | 避免 |
|---|---|---|
| 直接任务 | 教程、工程步骤、短时间说明 | 为了悬念拖延必要定义 |
| 结果回看 | 结果能看见，原因可追溯 | 虚构观众误解或把猜测写成原因 |
| 同条件对照 | 能锁定其他条件，只改一项 | 两组机位和时间不同造成误导 |
| 同物体接力 | 内部机制能解释外部结果 | 每镜换主角，失去对象身份 |
| 决策岔路 | 可选方案有依据且稍后验证 | 用明显错误选项凑互动 |
| 尺度转换 | 同一关系从整体进入局部 | 同时偷换模型、单位与时间尺度 |
| 条件边界 | 已讲清基准，需要解释何时变化 | 尚未理解主体就连续添加例外 |

[研究与完整例子](../studies/story-craft.md)包含这些入口的同题改写。选一个主入口，再用一个变奏推进。吸引力可以来自看清一次变化，不必每期开头都惊呼、设谜或讲新闻。

## 每段先填这四格

| 当前问题 | 做了什么改变 | 看见什么结果 | 结果怎样引出下一问 |
|---|---|---|---|
| 滑台为什么越线 | 提前同样条件下的制动起点 | 停车点回到目标线 | 速度改变后距离还相同吗 |

“然后介绍A，再介绍B”只有顺序，仍需说明B为什么在此时进入。可以保留时间顺序，但上一段的结果必须给下一段提供对象、条件或问题。每个新术语先给可指认的对象，再给名称；后面至少使用一次，避免只为显得专业而点名。

## 文字、画面与声音写在同一行

每条旁白配一个可执行的画面事件。说“更快”时，画面要能比较速度；说“这一项”时，该项已经可见并被轻量强调。画面不能只换一个背景继续朗读。旁白解释关系，画面显示状态；正文标签不重复整段字幕。

脚本分别保存 `narration`（自然可读的口播）、`screenText`（标签与公式）和 `pronunciationNotes`（术语读法）。不要把符号串直接交给TTS；例如画面写 `πr²`，口播可说“圆周率乘半径的平方”。每份分镜注明 `timingBasis: planned|tts-measured`，实测后写入句音频时长，按原自然语速调镜头窗口。

对照实验在项目与镜头中保存 `lockedConditions`，例如高度、初速度、单位、机位和投影比例。换模型、换景别或改时间映射时重新核对；锁定条件是内容的一部分，不能只留在制作人的记忆里。

镜头切换写清 `anchorOut → anchorIn`。换机位前后保留当前关注点的屏幕位置或运动方向，再用新空间揭示信息。匹配动作的两镜使用同一物体、同一动作相位；新增一个硬切要有明确用途。

- J-cut：下一镜的声音先进入。适合先提出新条件，再看到控制该条件的部件。
- L-cut：上一镜的声音延续到下一镜。适合说明尚未说完，结果已经开始验证。
- 同位置接力：物体标记进入公式槽位，或曲线进入真实路径。保留身份，落点避免旧字与新字重叠。
- 阅读停留：结果与关键式子落定后，给它一个稳定窗口。不要在读数时同时高速运镜和换状态。

音乐段先确定完整动作及其出口，再决定是否撤下旁白；关键条件和数字进入时先给人声让位。信号分析与主观听审分别记录，不能用总响度合格代替“弱字听清了”。

## 新故事写完，再做有限清理

使用 `C:/Users/USER/.agents/skills/lieflat-less-ai-tone/SKILL.md` 的实际规则。保留事实、来源和限定词；成稿清理不改标题层级、段落顺序或列表结构。只改明确命中的翻案腔、空转提示语、理想化拟人等白名单问题，未命中的句子逐字保留。

去掉“说白了”可以直接给判断；将“完成了对停车距离的计算”改成“计算了停车距离”可以恢复动词。不能据此加入没发生过的经历，不能为制造节奏改写所有长句，也不把问句或普通比喻本身判成问题。需要再次重构时，回到用户授权的结构编辑步骤，另存一版，随后重新清理。

## 成片前怎么核验

只看无声画面，检查对象与变化能否指认；只听口播，检查因果和代词是否完整。合起来检查每个量出现的时间、阅读窗、字幕与音轨，再看剪辑是否改变了实验条件。判断问题是脚本缺环节、动作缺证据还是声音遮盖，再修对应位置。

结构检查可发现断开的时间、失效的引用和提前使用的术语；“有趣”“听懂”仍需实际观看与试听，不用自动打分冒充观众反馈。

运行 `node scripts/inspect_story.mjs examples/storyboard/cup-75s.json` 可检查示例的时间、术语和依赖。交给未看脚本的人复述中心问题、结果与一条原因，是另一个有用的试讲方法；没有做过时记录“未试讲”，不用模型自评代替观众反馈。
