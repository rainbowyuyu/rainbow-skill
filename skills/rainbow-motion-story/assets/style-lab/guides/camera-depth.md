# 运镜与景深工作台

打开 [焦点与空间](../lab/camera-depth.html)，先选观察任务，再调光圈。三条14秒候选共用近景铜片、中景圆环和远景拱门；物体的位置不变，机位或焦平面改变。这样可以看清效果来自哪里。

| 候选 | 默认动作 | 适合的解释任务 |
|---|---|---|
| `camera-focus-handoff`，`handoff` | 固定机位，2–5.5秒把焦点从近景交给中景 | 从测量器读数转到被测物；先认出双方，再转移注意力 |
| `camera-focus-track`，`track` | 2–9.5秒斜向推进，每帧重新对焦中景 | 走近机构检查接触点，同时保持主体清楚 |
| `camera-parallax-reveal`，`parallax` | 2–9.5秒平行侧移，近景逐渐让开中景 | 用真实前后关系说明“后面还有什么” |

所有候选在11.5–14秒标为稳定读图；末帧保持，重新播放才回到开头。它们是三种可选镜头，彼此不会自动无缝连接。正式拼接需要匹配出入锚点、屏幕构图与相机速度。

## 怎样比较

先暂停在同一秒数切换候选，观察铜片、圆环和拱门的相对位置。打开“对照全清晰画面”，左右采用同一个候选、同一时间、同一组光学参数，右侧只关闭景深虚化。左侧的好看不能来自偷偷换模型、改曝光或移动物体。

“光圈”调整`fNumber`，小数字对应更大的孔径。固定机位、焦距和对焦距离，数字越小，离焦部分越模糊。页面为方便比较保持亮度不变；真实拍摄改变光圈也会改变曝光。

“焦距”调整取景范围，当前为28–85mm、固定36mm横幅16:9裁切。改变焦距后主体大小会改变，不会自动退远相机补偿。要比较同主体大小的推轨和变焦，另做匹配终帧尺寸的对照；技术推导见 [研究文档](../studies/camera-depth-technical.md)。

“对焦目标”可选近景、主体或远景；“按镜头设计交接”恢复该候选的默认焦点。“手动焦平面”允许在2–24m之间检查焦点落在哪里。距离均为沿相机光轴的正深度，单位米。斜向推进时，不能用相机到物体的欧氏斜距代替它。

逐帧按钮与画布左右方向键每次移动1/30秒。空格切换播放/暂停。打开文档阅读层、切到后台或离开页面会暂停；回来后保留观察位置。改参数也会暂停，便于检查当前帧的变化。

## 代码接入

模块为 [camera-depth.js](../lab/modules/camera-depth.js)，实际函数与完整字段说明见 [API](../examples/camera-depth/API.md)。下面是按帧求值的最小用法：

```js
import {
  sampleCameraDepth,
  circleOfConfusionMm,
  focalLengthToFov,
} from '../lab/modules/camera-depth.js';

const fps = 30;
const state = sampleCameraDepth(frame / fps, 'track', {
  focalLengthMm: 50,
  fNumber: 2.8,
  focusMode: 'directed',
  depthMode: 'dof',
});

// 世界坐标与对焦轴深是米；焦距 / 传感器 / CoC直径是毫米。
const pose = state.camera;
const focusDepthM = state.focus.depthM;
const hero = state.objects.find(o => o.layer === 'hero');
const cocMm = circleOfConfusionMm(hero.depthM, focusDepthM, 50, 2.8);
const fovYDegrees = focalLengthToFov(50, 20.25);
```

`resolveOptions()`将工作台参数限制在本样例有效域；底层光学函数对非正参数、物距或焦深不大于焦距的情况抛出错误。`circleOfConfusionMm()`返回非负**直径**。样例的`cocPx`对应900px逻辑画布高度；换成1080输出时重算`cocMm/20.25*1080`，不要把900px值当成任意输出上的像素值。

相机位姿只读绝对时间，随机跳到某一帧与顺序播放得到相同状态。正式离线导出使用`frame/fps`，不要把实时鼠标位置、`Date.now()`或上一帧累加状态放进镜头逻辑。

Three.js接入保留相同单位。设置位置、target和FOV后更新投影矩阵；当前样例没有横滚，`camera.lookAt()`可复现朝向。主点为`[0.5,0.52]`，正式适配应匹配这一取景偏移，而非默认居中。景深通道另外接入`focusDepthM`与光学设置。普通`PerspectiveCamera`本身不会显示景深，`BokehShader.aperture`也不是f-number；不同后处理的单位需要单独校验。

接入已有 Three 相机时，使用库中的`applyCameraPose()`匹配主点并清除上一镜的投影残留：它每帧设置`zoom=1`、`filmOffset=0`，因为导出的`fov`就是目标有效视角；同时保留渲染器aspect并重设viewOffset。如需要别的镜头偏移，应明确扩展pose协议，而非依赖相机旧状态。

Blender可使用50mm焦距、36mm水平sensor fit、16:9输出，并在`camera.data.dof`打开景深。用一个放在真实目标位置的Empty作为`focus_object`，或显式写入每帧轴深。输出主点、灯光、材质和焦平面都要与预演比较；接通数值不等于已经验证正式画面。

## 选效果时看什么

固定机位拉焦适合明确的注意力交接。近处先清楚，观众认出物体后再把焦点移向后方；焦点到达后留出阅读时间。默认候选是近景→中景，选择远景可自行比较更远焦平面。

移动机位追焦适合看接触、几何或机械结构。相机在移动，焦点继续守住同一个世界锚点。要同时比较两件物体时，可以收小光圈，让必要信息都保留足够清晰度。

侧移揭示靠前景遮挡和视差解释空间，不需要同时加快速变焦。抵达时前景不应盖住主件，主件也不能在旁白需要看清的瞬间被完全虚化。需要炫酷大运镜时，可用 [穿梭、离体与子弹时间候选](camera.md)先抵达观察点，再在观察点使用这里的焦点交接。

## 输出与边界

“导出相机与焦点JSON”保存完整0–14秒、30fps的421个采样点，含末端校验点。直接渲染14秒、30fps视频时通常使用0–419共420帧，第420点用于定义14秒端点与拼接，不额外渲染成第421帧。导出也记录当前候选、参数和显示时刻，以及来源、指南和代码路径。

“保存当前画面PNG”保存当前显示帧，之后切换候选不应改变该截图的身份。JSON是可重算的镜头计划，PNG是预演静帧，两者都不是已经完成光学渲染的视频。

当前画面根据每个物体中心的轴深计算薄透镜CoC，再做深度分组高斯虚化。它保留真实的参数关系，但忽略物体内部的深度变化、光圈散景形状与复杂遮挡。`blurPx=min(24,cocPx/2)`中的上限和高斯映射是预览选择；原始`cocMm`保持未截断。文字在景深层之后绘制，方便读数。

正式渲染要复查前景边缘漏色、透明材质排序与焦平面的到达时间，并观察原速和关键邻帧。研究来源、公式推导和光学边界见 [camera-depth-technical.md](../studies/camera-depth-technical.md)。独立工作台交互检查运行`node scripts/test_camera_depth_studio.mjs`；它检查事件与数据，不替代浏览器像素和主观观感审核。
