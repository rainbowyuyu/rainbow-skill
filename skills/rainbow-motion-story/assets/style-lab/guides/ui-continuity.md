# 让界面里的动作被看懂

适用于素材管理、软件功能介绍、实验面板与从总览进入细节。原片观察见 [MAX 研究](../studies/max-ui-motion.md)，原创试作用 [线与界面工作台](../lab/ui-line-studio.html#ui-identity-relay)，代码入口见 [UI choreography API](../examples/ui-choreography/API.md)。

## 先确定一个可追踪的对象

MAX 参考把“找素材—导入—进入时间线”连成一组明确动作。可迁移的是对象与动作的连续性：观众先认出一张卡片，看到它去哪里，再读结果。卡片、面板、光标与文案同时乱动，会让演示失去主线。

给主对象固定 `assetId`，给动作设置 `select / depart / arrive / commit / read-ready`。这些事件读取同一状态。外观可以从缩略图变成时间线片段，身份、内容与结果保持对应；不能用毫无关系的色块代替真实素材。

| 观察目的 | 适合的安排 | 当前代码候选 |
|---|---|---|
| 从许多项目进入一个项目 | 先选中，抬出网格，跨容器，展开详情；抵达后读信息 | `ui-identity-relay` |
| 解释点击的实际结果 | 光标到目标，按钮反馈，同一素材抵达播放头，提交后确认 | `ui-click-to-timeline` |
| 展示更多内容但不迷路 | 保留面板边界或选中项作锚点，整组换位，子内容稍后进入 | 组合上述状态与项目布局 |

## 三个最容易被忽略的细节

**跨容器不要跳坐标。** 先保存对象的屏幕矩形，将对象提升到共同浮层，在浮层完成移动，再交给目标容器。切换前后位置、大小、内容和裁切一致。原容器不留第二张主卡片。示例的 `hero.parentId / hero.box / masks.hero` 分别表明所有权、矩形与裁切。

**大面板负责动，小文字负责读。** 布局移动可以有倾斜与余势；解释结果时收正、收稳。正文不随大幅缩放被压扁，圆角和描边按设计单独处理。正式 DOM 项目可用 Motion 的共享 `layoutId`，但仍需检查嵌套变换、滚动与文字失真；本例使用 Canvas2D 仿射矩阵。

**按钮反馈与成功确认不是一个时刻。** 按下时显示接收到操作；结果真实提交以后才出现确认。示例片段起点与播放头使用相同的局部 x 坐标，并随同一父矩阵运动。声音接入 `commit`，不在素材还没到达时先响“完成”。

## 节奏与声音的接法

先让目标可辨认，再加速到达；停留时间由信息量决定。长距离位移可以快，结果阅读不能被下一个转场挤掉。当前代码的 14 秒时长、minimum-jerk 曲线和颜色是试作选择，不是参考原片的测量值，也不是所有界面必须照搬的规范。

输入、拖动、落定最多挑一个主要声音层。接触事件可用轻短的 click；大面板掠过可用弱气流；确认声只在结果提交时播放。原片声音尚未主观听审，以上是独立制作建议。详见 [音效时机](sound-design.md)。

## 可直接接入

```js
import { sample, draw } from '../lab/modules/ui-choreography.js';
const options = {id:'ui-click-to-timeline'};
const state = sample(frame / fps, options);
draw(ctx, frame / fps, width, height, options);
// state.hero / masks / transform / events / readWindow
```

接入项目时替换素材内容、布局和事件来源；不要只改界面上的标题。声音调度器在播放跨越事件时触发，任意 seek 不补放历史声音；导出视频按事件表离线混音。当前模块静音、不连接真实剪辑器。

## 检查交接而不只看首尾

1. 在抬出、抵达和换父容器的两侧逐帧定位，确认对象没有双影、突然变小或被边缘切掉。
2. 在中间态看文字、圆角、裁切和父矩阵；确认标签没有各走各的。
3. 倒序定位后回到同一时刻，应得到相同状态。阅读窗中相机和主内容确实停稳。
4. 接入真实素材后在目标输出尺寸复看，并实际试听；状态测试不等于观看和听审。

本方法可与 [线稿语言](linework-language.md) 相接：详情卡的边框变成图版边界，同一部件从缩略图变成工程结构；切换媒介时保留身份、强调色和一个空间锚点。
