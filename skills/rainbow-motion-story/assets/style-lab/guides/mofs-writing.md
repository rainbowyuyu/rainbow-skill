# 让开场的问题接得上后面的解释

先给观众一个能认出的对象，让每句话都推进一个可见变化。[文案工作台](../lab/mofs-writing.html)提供三套原创开场，每套 38 秒，12 秒后进入相同解释：节点与配体怎样连接，哪里留下孔隙，两颗示意球怎样通过或停住，最后区分孔口通行与内表面吸附。

这是静音分镜与写作练习，时间为计划值，尚未合成旁白。参考作品的文案观察见[原片研究](../studies/mofs-script.md)，科学表述与类比边界见[资料核对](../studies/mofs-writing-principles.md)。

## 三种入口怎样选

参考片的开头从“这是一个方框”开始，接着重复排列、缩小尺度，再把支架与顶点逐项映射成化学结构，约 13.5 秒的样本才出现 MOF 名称，随后补充诺奖背景。这种吸引力来自跟着简单操作走向新对象。可见字幕与范围见[科学和写作研究](../studies/mofs-writing-principles.md)，后续推进见[原片文案研究](../studies/mofs-script.md)。

当前三套是原创迁移：保留低门槛对象、连续操作和名称跟随对象的原则，再提供不同入口。它们没有复刻原作整段尺度穿越，也不要求每次都先问一个悬念问题。

| 候选 | 开场做什么 | 适合当前内容的条件 | 要检查的地方 |
|---|---|---|---|
| `story-mofs-result` | 从小球已进入、大球停住的结果开始，随后明确回看 | 结果能直接看见，原因可以回到同一对象解释 | 回看要有提示；不要让倒放看起来像真实物理过程 |
| `story-mofs-build` | 从一个节点开始，按连接关系搭出框架，再问空隙能让什么进入 | 观众先需要认识结构，逐个连接能展示整体怎样形成 | 连接必须有可追踪的起点；拓扑示意不能冒充实际合成过程 |
| `story-mofs-predict` | 同时给出孔口和两种尺寸，留判断窗口后验证 | 预测有可见依据，验证能保持相同条件 | 不用明显荒谬的选项制造优越感；不提前泄露结果或无故拖延答案 |

先选一套完整播放，再在同一时刻切换。12 秒后的讲解与对象相同，便于判断不同入口是否建立了需要的观察任务。三套都不要求夸张惊呼，也没有假设观众一定抱有某种错误认识。

“先看结果”保留 4.8–6.5 秒的静止结果段；“从连接搭起”在结构完成后才引入两颗待测球；“先做预测”先描出可比较的轮廓，验证尚未发生。要换到自己的题材，应保留这种因果关系，具体问题和动作另按事实编写。

## 中段怎样接住兴趣

原片先让人知道材料的用途，再追问它为什么直到后来才被做出来。约 125–148 秒的可见段落给出具体困难：连接太弱，去掉孔内溶剂后结构容易散架；连接太强，搭错后又难以纠错。成功结构因此有了要解决的条件。时间与可见字幕以[全片拆解](../studies/mofs-script.md)为准，不把这组简化关系扩张成所有材料的通用定律。

自己的长讲稿可以这样写：先确定观众想看到的结果，再挑一个真实障碍，展示某种直觉办法为什么还不够，最后说明新办法同时满足了哪些条件。每次补充都应改变观众的判断，不能把“然后又有一位科学家”当成唯一的章节连接。

原片约 200–213 秒回到研究者的回忆与晶体出现的具体场景。需要有情感的结尾时，可以从前面解释过的对象回到一个有来源的观察或实现瞬间；让观众知道这件事为什么值得做。没有采访、实验记录或现场依据，就不要编造研究者心情，也不把泛泛的赞美当作结尾。

这两个方法用于完整故事；当前 38 秒工作台只验证三种入口与同一段机制解释，没有声称复现全片的历史叙事。

## 共同解释链

| 计划时间 | 当前问题 | 画面任务 | 口播分工 |
|---|---|---|---|
| 12–15.8 s | 框架由什么连接 | 同一批节点先亮起，连杆随后被指认 | 命名金属节点与有机配体 |
| 15.8–20.5 s | 空出来的部分在哪里 | 保留连接网络，再显出孔隙轮廓 | 说出孔隙和金属有机框架的全名 |
| 20.5–24 s | 小球能否通过 | 小球沿固定入射轴穿过同一孔口 | 让小球对准入口，动作中不提前宣布结果 |
| 24–24.5 s | 小球到了哪里 | 完整进入后，才出现通过标签 | 无口播，观察已出现的结果 |
| 24.5–27.4 s | 只改变球的大小会怎样 | 大球沿同一轴接近，在碰撞位置停住；机位不变 | 换球再试，条件限定为当前理想几何示意 |
| 27.4–28 s | 大球停在哪里 | 抵达计算出的接触高度后，才出现阻挡标签 | 无口播，结果与动作分别落定 |
| 28–35.2 s | 通过后是否一定留得住 | 同一小球移到内表面附近，标为停留位置示意 | 引出吸附与孔内化学环境，分开通过和停留 |
| 35.2–38 s | 两个问题分别看哪里 | 完整框架及两颗球保持静止，就近指认孔口与内表面 | 无口播，供观察结论 |

共同段的术语出现顺序由对象决定。先看见连接，才给节点与配体名称；先指出空间，才给材料名称。内表面停留另起一问，避免让观众把所有行为都归因于孔口大小。

这个关系可以迁移到别的题目：先指认部件，再给可见变化，最后解释变化的条件。完整故事无需机械套用这张时间表。定义已经熟悉时可以缩短，机制复杂时就延长观察时间，配音保持自然速度。

## 在工作台里改写

点击任一句讲稿会定位它的画面。右侧同时显示当前问题、画面依据和屏幕短字，便于检查“这一句到底靠什么解释”。播放与逐帧用于核对动作，变速只影响预览，不生成配音或改变源计划。

展开“试着改写这一句”后，修改保存在本机浏览器，并按候选与句子分别记录。恢复示例只恢复当前句。改写文字不会自动改变模型动作、屏幕标签或镜头时长；如果修改了共同事实，另外两套也需核对。它们应继续保留同样的科学结论。

导出 JSON 包含完整讲稿、每句动作依据和来源 ID，并保存原文与改写标记。导出状态保持 `timingBasis:'planned'`、`audio:'not-synthesized'` 和 `needsTimingReview:true`。先合成自然语速 TTS，再根据实际句长重新安排窗口；不能仅因原表有 38 秒就拉慢人声填满。PNG 导出用于检查当前版式，不能替代连续播放。

## 代码接口

源码为 [mofs-explanation.js](../lab/modules/mofs-explanation.js)，详细接口见 [API](../examples/mofs-explanation/API.md)。它只依赖现有的 `common.js`。

```js
import {
  candidates, storyById, sampleMofs,
  GEOMETRY, LOCKED_CONDITIONS
} from '../lab/modules/mofs-explanation.js';

const id = 'story-mofs-build';
const selected = candidates.find(candidate => candidate.id === id);
const time = frame / fps;
selected.draw(ctx, time, 1920, 1080);

const state = sampleMofs(time, selected.variant);
const plan = storyById[id];
const cue = state.activeCue;
// cue.narration / screenText / question / visibleEvidence
// cue.sceneEvent / sourceIds / kind / start / end
```

每句有 `sceneEvent` 和 `visibleEvidence`，供镜头、字幕与后续 TTS 对齐。`sourceIds` 区分官方科学解释、原创几何例子和仅提供视觉方法的参考观察。模型在任意绝对时间求状态，38 秒后保持末态；不需要从头播放才能定位到某句。

框架 ID 为 `pore-frame-01`，客体 ID 为 `guest-small` 与 `guest-large`。几何使用设计单位，孔口与客体半径固定；球沿同一轴进入，只有球的大小参与当前几何对照。`physicalSimulation:false` 与 `adsorptionComputed:false` 保留在状态与计划中，避免迁入工程后被误当成真实分子计算。

## 类比与用词保留什么

可以把节点和连接体画成球杆，便于跟踪连接。金属节点可能是离子，也可能包含团簇；球杆不展示所有原子与化学键。要呈现具体材料，需另接真实结构与参数。当前三层八边形笼架是原创教学拓扑，不命名为 MOF-5 或其他具体晶体。

孔口相当于进入路径上的开口，孔腔是里面的空间。这个类比适合解释位置，不能单独说明真实筛分性能。吸附还涉及客体与材料的相互作用，温度或压力等条件也会影响结果。样例只显示可能的停留位置，没有计算吸附率、容量或分子运动轨迹。

口播可以用“连起来”“留下空隙”“穿过去”“停住”对应动作。屏幕短字负责指认位置，不重复完整口播。若一句只有“神奇”“颠覆”或“无限可能”，检查它是否遗漏了具体变化；不要用形容词替代刚好需要解释的机制。

MOFs 首次出现时说完整中文名称，后面可用“这类框架”保持指代清楚。发音备注独立保存，`吸附`读作 xī fù。当前工作台没有 TTS 音轨，不能根据它确认实际断句或发音已经通过听审。

## 写完后的清理与检查

先完成事实和故事的编辑，再按用户指定的 `lieflat-less-ai-tone` 白名单清理成稿。去掉空转起手式或恢复被名词化的动词时，保留原有条件与引用。问句、普通类比和长句本身都不是必须修改的问题；没有经历过的事，不写成亲历。

静音看完整动作，确认当前问题确实有画面依据；只读口播，检查指代是否能跟上前一句。随后将两者合起来，检查结论有没有早于结果，命名是否早于对象可辨认，读定段是否仍被其他变化抢走注意。听审要等真实音轨生成后单独进行。

这三套开场用于比较叙事选择。它们没有经过观众完播率实验，也不能凭代码检查证明“更吸引人”。选用时记录解决了哪一个具体问题，以及还需补哪些证据或配音校时；不要把一套开场变成所有题目的固定模板。
