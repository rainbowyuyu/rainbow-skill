# 音效放在哪里，为什么放

音效先回答一个问题：观众此刻需要听见什么变化？零件扣合、物体从镜头旁掠过、计算结果稳定，分别对应接触、运动和状态确认。整段剪辑先标这些事件，再选声音。没有明确作用的音效，可以留空。

## 从观察任务选声音

| 画面发生什么 | 声音负责什么 | 放置依据 | 容易做过头的地方 |
|---|---|---|---|
| 齿轮入位、物体落桌、卡扣锁住 | 交代接触的瞬间和重量 | 实际接触事件，短起音后衰减 | 用巨响把轻小零件做成重型机器 |
| 物体贴近镜头掠过 | 给出接近、经过、远离 | 相对镜头的运动和最近点 | 镜头只转头，整座城市却发出飞行声 |
| 剖面打开，进入内部 | 引导注意力进入新空间 | 开启动作到观察位的抵达 | 每次切镜都重复同一声长 whoosh |
| 一串候选最后确定一个结果 | 标出状态提交 | 最终锁定，必要时保留少量过程声 | 每个数字刷新、每个字幕字都响 |
| 电机持续转动 | 让速度变化可听见 | 与画面读取同一转速曲线 | 任意正弦起伏，停机后仍然高速鸣响 |
| 公式由实体关系中建立 | 提示一次对应关系，然后让位 | 关键项建立、等式完成 | 三个项同时响，压住术语或读数 |
| 新场景尚未出现 | 提前建立空间或动作期待 | 下一场真实环境声提前进入 | 提前泄露应保留的关键结果 |
| 画面切走，动作或情绪尚未结束 | 保持连续性 | 前场声音自然延续到新画面 | 混响尾拖到下一句关键信息上 |
| 风速、误差、压力等计算值变化 | 用声音辅助比较变化 | 明确标注的数量到音高/密度映射 | 把设计出来的音色当作实测声音或计算证据 |

这些是可选方法，不要求每部片逐项使用。台词、关键物理动作、音乐已经交代清楚的地方，新增音效先做静音对照。

## 锚定事件，区分起音、重心和尾音

时间线至少区分四个点：动作开始 `onset`、运动重心 `peak`、实际接触 `contact`、动作完成 `end`。声音也有自己的起音和衰减。长气流声从接触时才开始，往往已经来不及；金属敲击提前一大段，又会让接触看起来错位。

接触声可从接触帧附近试起。预备气流可提前进入，让能量重心在抵达观察位附近出现。确认声跟随最终状态，不能在计算仍变动时提前宣布成功。尾音要根据空间和下一条信息决定长度；缩短尾音时保留平滑收尾。

下面的范围只是本库试做起点，并非人类感知阈值，也不是必须遵守的剪辑速度。

| 用法 | 可试的时间安排 | 怎么判断要不要改 |
|---|---|---|
| 近景接触 | 先把起音放在接触帧，逐帧前后对照 | 物体是否像先响后碰；是否出现双重接触感 |
| 近景掠过 | 在最近点前约 0.15–0.45 秒进入，随后回落 | 气流能否帮助跟住物体；有没有盖住刚开始的旁白 |
| 小状态确认 | 约 0.08–0.25 秒的短声，状态提交时触发一次 | 多次刷新会不会被误听成多次结论 |
| 图表/公式读数 | 关键关系建立后保留安静窗口 | 能否复述读数；尾音有没有拖到术语上 |
| 声音桥 | 围绕具体动作或场景连续性试剪 | 提前声是否有来源；切走后的余声是否还合理 |

30 fps 的一帧约 33.33 ms；48 kHz 的一个采样约 0.0208 ms。声音可以在视频帧之间调节，画面事件的标注精度仍受帧率和原始时间戳限制。不要用小数位很多的时间码掩盖事件位置的不确定。

固定帧率项目用整数帧作为画面锚点。带变速或可变帧率的实拍片先使用源 PTS 和成片映射，不能直接把源片帧号除以成片 fps。音乐重剪后重新计算映射，旁白保持自然语速。

## 把“拟声”和“信息提示”分开

有画内声源的接触与机械声，先核对材质、体积、运动方向和距离。木块声偏短促，金属声可以保留多个衰减模态；具体音色仍取决于真实物体。库中的合成器用于试选声音性格，没有解算材料的真实声学响应。

界面确认、文字强调和公式建立可以使用抽象提示音。它们应有稳定含义：同一种短声对应同一种状态，不要同一段里一会儿表示错误、一会儿表示成功。没有屏幕内的实体声源时，在音效表注明 `designed` 或 `sonification`，避免把表现声音写成现场录音。

需要原创拟音时，可以分别录接触、物体振动和空间余声；先保留完整原录，再在副本中选干净的动作。选与镜头相近的材质和尺度，留头尾余量，记录设备、距离和实际动作。为动作补声音时，先用单层试剪；需要重量或空间感，再小幅添加另一层。

第三方声音保留作者、下载地址、许可、原文件哈希及修改记录。能下载不等于能商用；参考作品里的配乐和拟音不能顺手抽出来放进自己的成片。

## 让连续声音跟随连续动作

转速、接近距离和速度读取实际动画或计算状态。状态确认使用离散事件，连续发动机声使用连续曲线，不能每帧启动一个新的声音。

镜头掠过可把可控范围内的左右位置映射到声像，用距离控制幅度，用运动速度影响纹理。立体声只是辅助，折叠为单声道后主体仍要存在。真实多普勒需要声源和观察者的径向速度及声速；任意升降音高只称为设计的掠过效果。

科学数据的听觉化先确定量纲、范围和缺失值处理，再决定音高或脉冲密度。保留一张映射表，不在镜头之间偷换范围；用旁白或画面说明声音代表什么。音效不能替代图例、数值或物理验证。

## 先让讲解清楚，再选择冲击力

音轨建议拆开保留旁白、音乐、效果和环境，既能独立调整，也方便回看哪个轨道遮住了字。实际优先级由当前段落决定：读公式时语音和观察优先，无旁白的演示段可以让动作声成为主角。

给旁白标记真实活动窗口，尤其注意轻声、气口前后和句尾。音效先尝试移到句间，或缩短尾音；必须与动作同时发生的声音，再减小增益或收窄会抢话的频带。避让包络提前下降，短词间保持，句尾后平滑恢复。不要让每个字都触发一次音量抽动。

音乐如果已经有明显击打，动作命中同一点时可以只用音乐；再叠低频冲击可能让结果更浑。带明确音高的确认音要核对与配乐的关系，不能仅凭画面配色选择和弦。跨段落保持少量合理的环境底，会比每个镜头突然切成全静音更连贯；有意的停顿另行设计。

响度、峰值和人声清楚程度是不同检查。样例的电平不是发布标准。EBU R128 的广播目标不能直接当作所有短视频平台目标；实际交付按平台或用户要求设置。测过 LUFS 和真峰值，也仍需在正常音量下复听。

短音效可能不足以取得有效的整体响度值。本库的 0.28 秒木质声和 0.35 秒确认声，FFmpeg 整体响度返回不可用，报告保留空值与原因；没有把它们当作静音，也没有补一个看起来合格的 LUFS。不到一分钟的样例不以 LRA 判断呼吸感。

## 五组原创对照怎样使用

工作台在同一画面上切换 A/B，避免把更漂亮的画面当成更好的声音。A 是有意设置的问题，B 是针对它的一个修订，并非任何场景都更合适。默认不自动播放声音。

| 场景 | A/B 要比较的问题 | 实际制作中要替换的内容 |
|---|---|---|
| `contact-sync` | 接触声延迟与接触声同步 | 实际接触帧、材质录音或拟声 |
| `cue-density` | 每个变化都响与只标关键结果 | 观众需要辨认的状态，不是字幕数量 |
| `tail-control` | 长余音与阅读前收住 | 空间混响与真实阅读/旁白窗口 |
| `velocity-mapping` | 固定声与运动相关声 | 真实的镜头/物体运动曲线 |
| `narration-space` | 效果占满窗口与避让 | 实际旁白，不可用合成占位声代替验收 |

八种原声素材由确定性合成代码生成，可改种子和参数，不含参考视频采样。占位声只显示一条轨道占了时间和能量，不会说话；它无法证明人声可懂度。声音主观听审的状态记录在检查报告里。

## 接入自己的片段

先建立一份与镜头共用的事件表。锚点从实体状态或人工核对的画面得到，不能直接把 20%、50%、80% 的片长当成接触时刻。[生产用音效表样例](../examples/sound-design/production-cue-sheet.json)展示了接触帧、声源、声音内的同步位置、旁白保护窗和许可字段；数值是教学样例。

核心文件为 [sound-design.js](../lab/sound-design.js)，接口和调用方法见 [声音代码接口](../examples/sound-design/API.md)。工作台导出的 JSON 保留场景、参数、事件与声音计划，WAV 可导入剪辑软件或 Remotion。源代码和离线文件要同时归档，便于以后在动作改动后重算声音。

```js
// 同一份事件表交给画面和音效；eventFrame 是已核对的实际动作帧。
const eventSeconds = eventFrame / fps;
// assetSyncSeconds 是声音文件内部选中的接触/能量重心位置。
const soundStart = eventSeconds + offsetMs / 1000 - assetSyncSeconds;
```

时间线定位到声音中间时，要从对应的声音采样继续播放，不能把已经开始的尾音全部漏掉。浏览器预览使用音频时钟对齐画面，导出则按采样位置混合 PCM。浏览器播放设备延迟仍需实际校准；不能把调度测试说成零延迟保证。

## 一段声音的检查顺序

先静音看动作，确认对象和时间锚点。再单听效果，检查不必要的嗡鸣、点击和过长尾音。加入旁白听轻字和句尾，最后加入音乐并折叠单声道比较。小音量的手机扬声器与耳机各复听一遍，不能只在大音量下判断“震撼”。

量化检查包括文件格式、有效采样、端点、相邻采样跳变、左右声道与单声道折叠、峰值和响度。最终编码后重新检查时长与起止，防止剪辑或编码改变对齐。任何自动检查都不能替代人耳判断音色、音乐相容和语言可懂度。

每次实际使用后，把有效的声音选择与事件位置写回项目音效表；只把可复用的方法写回技能。某个片段需要提前 120 ms，并不表示以后所有镜头都提前 120 ms。
