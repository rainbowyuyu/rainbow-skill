# Lemo-Opuscar：按内容选择风格

本模块研究 [lemomo-ai/lemo-opuscar](https://github.com/lemomo-ai/lemo-opuscar)，固定在 `3961ddb3d24d8876e0e2754f7790d66908acee51`（2026-10-22）。它包含 **59 种可用风格**，另有 **98 个电影风格档案**。两套目录的用途不同：前者有独立 STYLE、DEMO 和实现源码；后者主要提供媒介组合、导演意图与镜头提示。

[打开风格工作台](../lab/lemo-atlas.html)。按名称、用途或表现方法搜索，选择一种主要风格，再挑局部技法。导出的 JSON 保存题材、来源版本、注意点与原创试作入口。

## 学习覆盖与依据

59 项均有中文分析，包含画面、运动、镜头、文字、叙事、适用题材、常见失误与原创练习。98 项均有画面与运动分析、用途及迁移练习，完整原提示和镜头表按需展开。具体阅读范围在每项 `verification` 中；源码核对指关键函数阅读，未将上游 1,895 份文件全部运行验收。

157 张来源静帧经过缩略联系表观察，适合判断构图、层次和材料区别。它们不能证明动画连续性或声音质量；本次未逐片完整观看约 56 分钟的现成风格影片，也未做原片主观听审。14 个原创试作是单项技法练习，不能写成 157 套完整影片已复刻。

研究分册：[A：纪实与实证、部分绘画](../studies/lemo-analysis-a.md)、[B：绘画、印刷、图形、数据](../studies/lemo-analysis-b.md)、[C：信息、动画、游戏、电影、三维](../studies/lemo-analysis-c.md)。结构化分析在同名 JSON。来源静帧与许可在 evidence/lemo-opuscar（外部或本机资源，未随公开包收录），下载文件均对固定提交的 Git blob 哈希进行核验。

## 先判断观众要看懂什么

| 观察任务 | 优先比较 | 选择依据 |
|---|---|---|
| 一个新闻数字怎样得到 | caption-news、visual-investigation、archive-lighttable | 保留原始资料、来源标签和具体高亮；生成图不能冒充档案 |
| 一个空间隐藏了什么 | lidar-survey、white-model、microscope | 真实尺度、统一空间锚点、逐层揭示；测量值需要真实数据 |
| 一个机构怎样工作 | teardown、blueprint、iso-infographic | 拆解轴、安装关系、切口与运动状态同时一致 |
| 一个数量怎样增长 | data-physical、dataviz | 单位对象可计数；坐标、材料和颜色有稳定含义 |
| 一个自然过程怎样发生 | watercolor、urban-sketch、engraving | 结构先出现，细节随后；笔触、注释和观察对象共同形成画面 |
| 一个动作有何情绪 | rubber-hose、midcentury-toon、silent-film | 预备与结果能在剪影中读出；重要动作保持完整 |
| 让观众跟着走流程 | pixel-rpg、microgame、living-screencast | 状态变化可见、身份持续；速度加快时仍留结果阅读 |
| 层次怎样进入空间 | paper-popup、shadow-puppet、paper-lantern | 纸铰链、皮影铆点与灯箱层间距各有约束 |
| 展示材料和内部结构 | glass-product、brick-toy、tilt-shift | 材质来自光照、尺度和镜头；局部特写后交代整体关系 |

不要把所有候选混进同一部片。主要风格负责持续的画面语言；局部技法只解决一个问题。比如用 blueprint 解释连接，再转到 data-physical 比较数量，必须保留对象名称、单位与强调色，并设计清楚如何从结构进入测量。

## 把媒介规则写进代码

**水彩与水墨。** 水彩依赖透明笔触交叠、纸白和层层铺色；水墨用墨色层次和留白建立空间。纹理绑定世界或材料坐标，避免镜头移动时逐帧随机噪点。将同一物体的结构、底色、细节分别安排时刻，不能先画完整矢量物再盖一层噪声就称完成。

**Riso、丝印、木刻与铜版。** Riso 分版乘色与固定套印偏移；丝印强调遮盖色块；木刻先有黑底再减去刀痕；铜版靠增加细线和排线改变密度。控制细线频率，缩小后应归并成明暗，不能变成摩尔纹。正式输出另验色域和抗锯齿。

**纸卡、皮影与三维实体。** 纸卡是带厚度的刚片，铰链旋转保持边长；皮影是可见铆点连接的平面部件，操纵杆跟随手的位置；三维实体则有完整的遮挡与受光关系。不能把一种投影代码换名称后当成三种材料。

**像素、HD-2D 与移轴。** 像素 RPG 连字体、相机和调色板都受栅格约束；HD-2D 把像素卡片放进真正三维光照；移轴依赖透视、焦平面及时间重映射。低分辨率滤镜、全屏模糊都不足以替代这些结构。

**新闻、档案与实机。** 画面中的来源、目录编号、日期和计数要能追溯。将真实材料放到同一坐标系里标注；片中的网页或录屏如果是重绘，应明确其性质。学习示例的讲法不等于核实其中全部事实。

## 从题材到时间线

先写一个可回答的问题，并提出三种故事结构。例如解释弹簧，可从一个按钮失灵、两种材料对照或一个动作慢放开始。再选最适合观察任务的风格。不要先把上游 DEMO 的人物与场面换名，然后才找主题。

每段至少记录观察对象、原先状态、当前变化及结果。开场尽早出现对象和矛盾，结尾回到观众已经理解的那个对象。一个媒介特有的动作可以承担高潮：纸页真的翻开、画笔真的把轮廓接到下一镜、图表确实扩展到更多数据。

采用一份时间线同时驱动画面、字幕与声音。源库的 120 BPM、每片至少四种运镜、固定字幕秒数等是其制作建议，不能机械套用。字幕停留按实际中文阅读量和用户 TTS 时长校准；重要对象刚出现时，给观众看清它的时间。

快速重复动作可放在乐句密集处，解释因果时降低运动密度。留白应让人看见某个结果。音效绑定碰撞、落定、翻页或状态提交；不要机械地给每一个微动配声。主观听审、对白遮蔽和最终响度仍需单独检查。

## 14 个原创试作

所有试作位于 [lemo-trials.js](../lab/modules/lemo-trials.js)，无新增运行依赖。每项 12 秒，提供随机定位、静帧保存和独立的实现边界。

| 风格 | 实际试做 | 后续正式制作应补什么 |
|---|---|---|
| caption-news | 数字落地、跨镜字幕、目录证据高亮 | 根据真实题材取得原始材料与事实来源 |
| blueprint | 弹簧位移与尺寸同源 | 真实结构尺寸、受力条件、线宽层级 |
| watercolor | 枝干先行、叶片透明叠色 | 更丰富笔刷、纸纤维与长镜头空间 |
| ink-wash | 渐隐山体、留白水面、近远差速 | 有方向的加载笔触与干湿边缘 |
| risograph | 两张色版移动后乘色混合 | 真实分版密度、网角与输出色彩管理 |
| swiss-motion | 网格中的偏移、剪切显字 | 由真实讲稿决定排版节奏 |
| data-physical | 两组落片与精确计数 | 真三维材质、数据来源、统一物理单位 |
| rubber-hose | 软管曲线肢体、蓄力与跟随 | 完整角色表演与动作同步的声音 |
| pixel-rpg | 像素路径、同一对象、状态框 | 真索引调色板、手绘精灵和像素字体 |
| silent-film | 全景球车惯性、结果后字卡 | 完整动作表演、雕刻重绘和原创配乐 |
| paper-popup | 固定底边、刚性折起、影子跟随 | 实体纸厚、裁切阴影、透视与微距景深 |
| glass-product | 暗场轮廓、分层、光脉冲 | 实际透明材质、灯面、环境更新与景深 |
| shadow-puppet | 镂空、共享铆点、杆随手动 | 分层染色透射、衣饰与角色表演 |
| dataviz | 数据点先落、再连接、数值回读 | 真实数据、画笔表演与数据声音化 |

## 交付前检查

先看真实绘制的建立、变化、落定三帧，再连续观察关键动作。任意时刻重复绘制、逆序定位应得到同样的画面。检查源数据身份、计数、铰链长度、相机遮挡和字体实际测量；测试通过只能说明对应检查通过。

正式影片另检中文读音、声音让位、最终编码、接缝和字幕阅读。上游演示的运行经验可以作为检查线索，不能直接填写自己的验收结果。
