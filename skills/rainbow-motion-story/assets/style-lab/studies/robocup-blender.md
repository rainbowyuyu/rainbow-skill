## 逐段看到的关系

时间按源片 PTS，以下是画面观察，不是作者工程说明。

| 时间 | 画面与运镜 | 可以迁移的做法 |
|---|---|---|
| 0–2.5 s | 真实场地、围观者与轮式机器人；明亮边界扫过，场地退去，机器人位置附近留下浅色模型 | 用主体轮廓和屏幕位置交接实景与模型；前景退出也有方向 |
| 2.5–6.5 s | 黑场中建立机器人，略俯视推进到传感器；粉色射线与飞行时间小图相连 | 先让人认出机器，再靠近正在解释的“眼睛”；一次只强调一条测量 |
| 6.5–11 s | 射线增加，命中点累积，机位升高、拉远并改变方位，整个场地轮廓逐渐可见 | 镜头扩大和信息范围扩大同步；机器人仍是扫描中心 |
| 11.5–16.5 s | 平面扫过地面、圆柱包住自身、红色离群点被移除 | 用空间范围表达过滤规则，不能只有角落数值变化 |
| 16.5–22.5 s | 障碍点转为体素；地图平面沿竖直方向分层，粉/青/绿语义层依次加入、叠合 | 同一边界和坐标贯穿转换；斜俯视让层间距离能被看见 |
| 22.5–25 s | 障碍周围出现多色代价带；近旁遮挡区被指出 | 障碍、膨胀区、可走区域要同时可比较；强调色有固定含义 |
| 25.5–30 s | 从终点向外展开的阶梯/等高场，白色路线在场上出现；镜头靠近表面 | 把抽象代价编码成高度来读趋势。高度是可视化，不是真实地形或重力 |
| 30.5–35 s | 路线圆角与角度解释，随后沿路线立起速度幕帘；机位降低到掠视方向 | 观察路径时看平面，观察速度变化时让竖向差异可读 |
| 35.5–41.5 s | 机器人沿路执行，新障碍出现后路线变化，画面维持路径和机器的关系 | 状态变化有起因与结果；不能随意抖动路线假装实时思考 |
| 42–47 s | 停车后镜头推进机身，指令箭头、数据字节和信号沿着机身进入控制板 | 跟随“要去哪—怎么发命令—谁执行”的因果方向，旧路径留作空间锚点 |
| 47–50.5 s | 信号分到四个电机，轮子附近出现不同方向的箭头，俯视便于比较 | 标签和箭头绑定实际组件；车轮类型与动力学还需独立资料核验 |
| 51.5–58.3 s | 线框床/房间、距离测量和局部对准，伸缩机构伸出；镜头跟到末端完成交付 | 从大空间收束到接触点，最终动作回答全片任务；不是突然插入片尾卡 |

## 最值得保留的五种方法

### 1. 一个主角，多个表示

实体、浅色结构、扫描点、体素、地图是同一空间的不同读法。跨段保留机器人、场地轮廓或终点中的至少一个明确锚点。不要每个章节换一套坐标、镜位和装饰，再靠淡入淡出补救。

### 2. 大角度移动对应一个新问题

源片不是持续环绕。它从传感器近景退到空间全貌，在地图层叠时倾斜，在速度幕帘出现时降低，在讲执行时靠近底盘。可复用的是**观察任务决定相机位置**，不是猜测一个万能广角参数。技术选择和本机 API 见[官方技术底稿](robocup-blender-technical.md)。

### 3. 数据从发生的位置长出来

射线的起点属于传感器；点落在被测位置；过滤体积与被过滤对象相交；速度图沿着路径生长；电机箭头贴近电机。这样观众能沿着位置关系追因果。随机散点、屏幕浮层和装饰曲线只能产生相似外观，不能替代这条关系。

### 4. 透明结构只揭示当前原因

原片用低饱和青白结构保留整体，重点用粉、橙、绿点亮。我们的原创例子选择实体金属与局部开盖，练习相同的观察关系。整体全透明容易让背面边线和控制板叠在一起；先选需要露出的部分，再比较开盖、剖切和低对比轮廓三种方式。

### 5. 节奏是认出、展开、停住、转交

扫描增加时快，观察层级时稳定，靠近内部时沿明确目标推进。建立新概念前先让镜头到位，结果出现后保留观察窗。图形与字幕不是每次一起跳出来。本文不从联系表臆测源作者的确切缓动曲线或音乐重音。

## 本次原创实践

代码与实际渲染放在[Blender 原创小样](../examples/robocup-blender/API.md)，从自建轮式传感平台出发，比较实体材质、扫描命中、代价场、路径和拆盖观察。场景由本地 Blender 生成，不使用原作者的机器人、水印、音频或视频片段。

扫描取自示例障碍的射线求交；代价场与栅格路线有可追溯计算。它仍是演示场景，不等同于真实雷达、SLAM、机器人导航实测或学习型世界模型。镜头、爆炸拆解与信息显露是编排动画。具体渲染引擎、分辨率、重开和检查结果以 API/验收记录为准。

以后迁移到无人机、建筑或机械视频时，优先读[空间解释镜头配方](../guides/robot-spatial-explainer.md)，保留“实体→观测→表示→决策→执行”的因果顺序，按题材删减；不强制所有影片套用这六章。
