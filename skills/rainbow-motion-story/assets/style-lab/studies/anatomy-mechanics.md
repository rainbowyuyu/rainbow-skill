## 百分表：一份高度状态控制三个反馈

小示例[build.mjs](https://github.com/wheresryan22/anatomy/blob/1482e8469b0a9e0d8cc18ea2740a01423d29ae80/examples/dial-indicator/build.mjs)最适合研究“输入怎样变成可解释的反馈”。它先构建底板、导轨、磁性支座、表盘、测头和三个量块，再通过SVG组平移移动滑台与测头。读者的指针或方向键改变滑台目标位置，`heightUnder(cx)`计算测头横向覆盖范围内的最高量块顶面。

| --- | --- | --- |

这里的高度明确以px显示，表盘上的“0.01”图案不能把它变成经过标定的真实百分表。接触求解是简化区间模型，测头又允许弹簧滞后；源码阅读不足以保证连续接触、真实测量误差或力学精度。若原创工作台标毫米或牛顿，必须另外定义换算、刚度和接触约束。

它的交互循环累计`clock`、`tip.at`和速度，并将`dt`截到1/30秒。因此它不是天然可任意定位的`sample(t)`。接入本方法库时，应保留已有绝对时间接口：把用户事件保存下来，以解析解、固定步长重放或经过核对的状态缓存求任意时刻；只复制实时循环会破坏导出和倒序定位的一致性。

## 发动机：拆解路径必须服从承载关系

[火箭构建脚本](https://github.com/wheresryan22/anatomy/blob/1482e8469b0a9e0d8cc18ea2740a01423d29ae80/examples/raptor-engine/build.mjs)73–101行把每个总成定义为名称、说明和世界空间移动向量。`piece`表示选择时所属的解释组，`ride`表示它实际上跟随的承载总成。例如某个传感器可归“管路”解释，却必须跟随它固定的燃烧室运动。这是值得直接保留的数据区分。

构建时用`A.recorder`记录绘制对象和几何形状，`A.settle`求排序关系；随后把移动向量、静态排序键、承载归属与弹簧参数写入页面。几何描述与动画审核因此可以读取同一组参数，减少“审核用另一条轨迹”的偏差。这里没有读取或运行`kit/audit.mjs`实现，不能确认它覆盖全部几何错误。

[交互脚本](https://github.com/wheresryan22/anatomy/blob/1482e8469b0a9e0d8cc18ea2740a01423d29ae80/examples/raptor-engine/live.js)93–163行展示了三个具体做法：

1. 每个总成独立保存当前位置、速度、目标和待生效事件；打开按顺序启动，合拢按相反顺序启动。中途反转时，只重新安排目标确实改变的总成，并取消不再需要的待执行事件。
2. 世界空间位移通过同一个相机基向量映射到SVG平移。高亮归属与运动归属分开，避免零件在拆离途中从支座上滑走。
3. 每帧排序键为静态键加`dot(move, view) × 当前拆离比例`。实际排序改变时才用一个`DocumentFragment`重排节点，其余帧只改位移。

[运动文档](https://github.com/wheresryan22/anatomy/blob/1482e8469b0a9e0d8cc18ea2740a01423d29ae80/references/motion.md)106–132行进一步要求检查中途反转、错峰边界以及“前面的已离开、当前的正在走、后面的仍在原位”这些状态。该文档记载上游曾在完整打开/关闭都看似正常时，仍于短暂反转窗口出现穿插。这里可迁移的是状态覆盖方法；文档里的1,119个状态等数字是其特定配置，不能直接写成我们的验证数量。

装配顺序不等于随意给零件错开延迟。外部包围件应先让路；一个移动向量若朝向相邻部件，占位部件必须先移开；交错穿过同一孔洞的零件需要共同的运动组。回装和快速反向也应遵守同一几何约束。

## 操作需要前置条件，读数需要单位与模型边界

火箭的`ignite()`先请求合拢并置为`armed`，`stepBurn()`等到所有总成接近归位且没有待执行动作后才启动燃烧时钟。这比点击后立即发光更能表达真实操作依赖。原创机械开关可以用类似结构明确“安装到位后才允许演示工作”，或在拆开状态中明确哪些运动仅为教学展示。

但是火箭的压力与推力仍是简化演示。构建脚本33–36行预设300 bar、海平面230 tf和1.3 m出口直径；交互脚本698–699行用归一化`burn.pc`缩放压力，并用`max(0, vacuumTf × pc − backTf)`生成推力读数。燃烧状态本身由阶段目标与平滑弹簧更新。这些代码可以支持“读数和效果来自同一个状态”，不能支持已经求解喷管流动、涡轮泵、燃烧稳定性或真实瞬态推力。将这种演示迁移为科普时，应标出它是简化模型，并独立核验参数来源。

画面也不是通用真实三维渲染。主要是等距投影后的SVG实体，按深度排序；火焰等效果使用共享相机的WebGL层。火箭构建脚本890–927行明确组装背景SVG、烟焰Canvas、前景SVG、辉光和遮罩层。可借鉴前后层的遮挡关系，但不能把这些图层称为已经算过的光照、烟气流体或任意机位下都正确的完整三维场景。可选3D模式另被上游标为beta，本子任务未阅读其引擎实现。

## 给原创机械工作台的审核流程

[审核文档](https://github.com/wheresryan22/anatomy/blob/1482e8469b0a9e0d8cc18ea2740a01423d29ae80/references/verify.md)把几何、绘图和视觉检查分开。它还明确截图有60–200毫秒甚至更长的开销，联系表的实际间隔大于请求间隔；慢放只影响页面动画时间时，`setTimeout`仍可按墙钟触发自动巡游。这些是研究和测试中容易漏记的真实限制。

| 检查层 | 应检查的问题 | 本项目可采用的方式 |
| --- | --- | --- |
| 状态与因果 | 弹簧、触点、指示灯、读数是否读取同一时刻；冻结、恢复和退出手动模式是否改变相位。 | 独立期望值测试，再以同一事件快照导出有限分镜。 |
| 装配与运动 | 拆离后连接端是否仍有归属；回装、反向和中间路径是否穿插。 | 对每一运动组保留装配基准、承载组和路径；覆盖所有允许操作顺序。 |
| 投影与遮挡 | 局部放大和换观察角后，近远关系是否正确；透明/剖切是否掩盖几何错误。 | 多角度投影检查加实际画面审阅；不能用固定排序偏置掩盖相交。 |
| 绘图细节 | 线是否落在实体边缘、触点与导线是否接到具体部件；是否存在悬空纹理。 | 按接点和端口逐处检查；几何碰撞测试看不到所有SVG线条缺陷。 |
| 人机操作 | 键盘、指针、触屏、离屏暂停和减少动态效果是否有定义。 | 用实际输入完成操作，避免仅用伪造事件推断指针捕获可用。 |
| 视觉与证据 | 完整、剖开、拆离、按下和恢复状态是否都能读懂；小屏是否遮挡。 | 全景及局部截图确实打开查看；记下范围，不把截图生成记成视觉通过。 |

上游火箭构建末尾仍存在两个`CROWD_OK`豁免配对。它们需要连同具体理由和近景检查一起评估，不能把“审核通过”理解成没有任何例外。我们的原创候选应保存自己的审核输入、误差阈值和已检查状态，而非沿用上游的通过措辞。

口径：`pix_diff` 是 160×90 缩略图相邻帧灰度差的均值（0–255 量纲，下文写作“像素差”）；`hist_diff` 是 24×8 HSV 直方图差（归一化到 0–1）；`grid` 是 8 列×5 行共 40 格差分，`rows` 指 5 行各自 8 格之和；`edges` 是 Canny 边缘密度；`sat`/`val` 是 HSV 均值。**这是帧级像素与音频事件统计，不是原速主观复看结论。** 上文第 81–85 行记录的“约 20 秒按键、25.6 秒布光、32.06 秒发动机”三处画面，本节按 shot 边界重新归位（见 §1、§4），与上文时间戳的差异以本节为量化版；上文对机制本身（`piece`/`ride` 分组、错峰反转、深排、审核覆盖）的**代码层结论，本轮数据既不能证实也不能证伪**，仍属源码阅读结论。

### 2. 切点吸的是 onset，不是节拍网格

123 BPM 的拍长是 0.4878s，小节 1.951s。7 个检测切点换算成拍相位是 0.333 / 0.602 / 0.862 / 0.198 / 0.293 / 0.083 / 0.465——**散布在整拍内，没有对齐到任何一格**，所以不能写“卡在小节线”。

真正对齐的是音频事件：7 个切点到最近 onset 的时间差是 **+0.111 / −0.068 / −0.016 / +0.051 / +0.026 / −0.035 / +0.007s**（中位绝对差 0.035s）。其中 44.533 与 57.300 两处，最近 onset 是 12.3 和 7.06 强度的重音，误差分别只有 26ms 和 7ms。三个补出的切点同样对齐（23.300 差 +0.013s、30.000 差 −0.069s、53.167 差 +0.007s）。

另外 5 处非切点的单帧大跳（3.500 的 16.41、7.400 的 18.60、15.367 的 29.48、41.900 的 6.51、45.400 的 10.26）到最近 onset 的差在 −0.155…+0.065s 之间。**可迁移的判断：这类片子是把画面事件吸附到音频瞬态上，而不是给画面找一个 BGM 网格。** 123 BPM 只是供节奏感参考，不是对齐依据。

### 3. 音频床是“恒密”的，没有呼吸段

- 372 个 onset / 61.09s = **6.09 个/秒**；按 5s 分箱是 27 / 31 / 30 / 29 / 31 / 29 / 28 / 31 / 30 / 34 / 31 / 32，**方差极小**（27–34）。
- 相邻 onset 间隔的众数：0.14s（87 次）、0.12s（84 次）、0.19s（49 次）、0.16s（41 次）、0.09s（27 次）。0.12–0.14s 即每秒 7–8 个事件的密度，与 123 BPM 的十六分/三连音层吻合。
- kind 分布：279 tonal / 93 noise（噪声占 25%），说明“机械咔哒/气流”这类噪声音效是**有设计地撒在 tonal 床上的**，不是点缀。
- `silence_ratio` 0.005，`silences` 只有 [60.98, 61.09] 一处（片尾）。**全片没有任何一处 1.2s 以上、强度 >3 的 onset 空档**。
- RMS 均值 −12.1 dB，2s 级均值落在 −8.7 到 −14.7 dB 的窄带里（最低 52–54s 段 −14.7，最高 16s 段 −8.7）。**没有靠“静音—爆点”的对比做强调**，强调只靠音色与重音强度（最强 1.76s 的 17.51、18.97s 的 15.79、14.74s 的 15.27）。

以上四条合起来是一条反直觉的可迁移结论：**这种“可拆解机械”片的声床是恒定的，靠画面事件去撞它，而不是靠音乐段落去驱动画面。**

### 4. 三个可量的动作参数

**(a) 按键微距推进：1.00× → 2.16×，1.40s。** 测量方法：取 19.500s 帧中底座右端圆角亮块（高 65px、宽 90px）作模板，对 19.400–21.300s 每 0.05s 帧做 0.98–2.58 步进 0.02 的缩放匹配，最优匹配分数全程 ≥0.991。逐段速度（每 0.1s 的倍率增量）为：+0.02 / +0.04 / +0.06 / +0.10 / **+0.16 / +0.16**（峰，20.00–20.20s）/ +0.14 / +0.12 / +0.10 / +0.08 / +0.08 / +0.04 / +0.04 / +0.02，之后 21.00–21.30s 完全静止。即**加速 0.5s、减速 0.9s，峰速 1.6×/s，峰在总行程 28–36% 处**。用间距衰减拟合得 τ≈0.254s（残差 0.306，呈拱形，说明不是纯指数，而是中段更陡的类 smoothstep），到 90% 用 0.585s。

同一时段内 `pix_diff` 从 0.57（19.600）升到 **3.68（20.133）** 再回 0.44（20.933），**推进与按键动作共用一个窗口**，推近过程中机构本身在动，不是推到位再按。这与上文第 29–30 行“压下量同时驱动弹簧长度、推杆位置、接点间隙”的写法一致，但要补一条：**本片的做法是把推进与按下叠在同一 1.3s 内**，而不是“先给全景、再切近景、再按键”三段。

推进前还有一次预兆：19.100–19.370s 有一组小幅动作（`pix_diff` 0.26→0.16，行 2 的格子值 7.80→3.93），随后 19.400–19.566s 归零约 0.17s。**“小幅预动 → 停一下 → 主推进”** 这个两拍结构在上文的 A 窗讨论里也出现过，可以当作同一作者的习惯。

注意 19.9–21.0s 期间读数字串（`K · 3.8 mm · 58 cN · sent`）在画面上位置基本不动，是**固定的文字层**；只有 3D 层在推。所以整体构图稳定、局部放大，避免了大倍率推进时字被拉糊。

**(b) 推力读数斜坡：14 → 320，2.1s，分三段。** 从 0.1s 步联系表逐格读出：31.400s 为 15，31.567s 16，其后每 0.1s 为 19 / 24 / 30 / 37 / 45 / 55 / 66 / 78 / 91 / 104 / 119 / 134 / 150 / 168 / 187 / 208（33.200s），再 33.267s 229、33.333s 266、33.367s 292、33.433s 309、33.500s 320 收住。

- 31.57–33.20s 这段的速率是 **23 → 50 → 60 → 70 → 80 → 100 → 110 → 120 → 130 → 130 → 150 → 150 → 160 → 180 → 190 → 210**（单位/秒），单调加速、无平台。
- 纯指数拟合：倍率周期 **0.431s**（ln 残差 rms 0.101，残差呈系统拱形）；带偏移的幂律 `24.09 · (t−31.57+0.79)^2.422` 的 ln 残差 rms 只有 **0.049**，明显更好。即**读数走的是幂律加速（p≈2.4），不是指数**。
- 33.267–33.367s 有一段**尖刺**：速率 617、650 单位/秒，约为前一档（210）的 **2.2–2.4 倍**；随后 33.433–33.500s 立刻跌回 283 → 157 收尾。这一段正是联系表里读数从 229 猛跳到 292 的地方，即“油门推到顶”的一脚。
- 伴随的 `edges` 从 31.5s 的 0.158 单调升到 33.7s 的 0.179，`hist_diff` 在 33.23–33.47s 出现 0.05–0.173 的几次小峰——**读数变化是有视觉副作用的（数字位数变多、面板边缘变密）**，不是纯数字替换。

**(c) 文档滚动：0.63s、首帧即峰、无加速段。** 45.333s 时 `pix_diff` 0.04，45.367s 直接跳到 **10.26**，然后 10.37 / 10.04 / 10.56 / 9.69 / 7.83 / 7.10 / 6.07 / 5.98 / 4.72 / 4.36 / 3.58 / 2.86 / 2.46 / 2.18 / 1.69 / 1.16 / 1.13 / 1.13 / 1.04，到 46.033s 落到 0.54。`val` 同步从 118.5 降到 89.2。这段是**典型 ease-out**：没有爬升段（第一帧就是峰值），衰减近似每帧 ×0.92。行分布始终集中在中下三行（r1–r3），说明是纵向滚动而不是整体位移。

对照第 (a) 项的推进：**同一个片子里，推镜用“慢起—快—慢收”，滚动用“立刻起速—慢收”**。区分依据是动作由谁发起：用户推/按的动作给入场缓动，页面滚动不给。

### 5. 版式与配色（可核实的部分）

- 画幅 1080×1440（3:4），不是 9:16。字幕带固定在 **y≈1120–1319 之间**（帧高 78%–92%），横跨 x 87–1026，全程未变。
- 高亮色：HSV 掩膜（S>140、V>180、H 25–45）取中位色为 **#daff22**（2.0s、18.5s、34.0s 三帧一致，hue 中位 35）。这是**逐字高亮的字色**，只覆盖句中关键词，不是整行变色。
- 底/纸两色：k-means 三色里 `#131216`–`#141317` 的暗底占比在 0.51–0.93 之间浮动，`#f5f5f6`–`#ededea` 的纸白占比 0.22–0.42。**同一支片子在同一套两色之间来回切**（白底讲解 ↔ 暗底展示），不是固定一种底色。
- 逐字高亮的时间格：对字幕带做逐帧高亮像素计数，值只在 **约 0.1–0.2s 的整数倍**上变化（例：17.367 → 17.667 → 17.767 → 17.867 → 18.033 → 18.167），即**高亮以 5–6 帧（166–200ms）为一档推进**，与 §3 的 0.12–0.19s onset 众数同量级。可迁移：**逐字高亮的步长应与声床的事件间隔同量级，而不是按字数平均分配。**

### 7. 对“可拆解机械原理”这一诉求的结论

上文第 38–50 行讲的 `piece`/`ride` 分组、错峰反转、以静态键加 `dot(move, view)` 乘拆离比例作排序键，仍然是这套方法里最值得抄的部分，本轮量化不改变它。本轮新增的是**“讲清楚”这一侧的节拍约束**：真正让一个机构看得懂的不是拆得细，而是

- 每镜只承担一个动作且控制在 4s 级（§1）；
- 推近与触发同窗（§4a），让“按下去”和“看清”是同一件事；
- 读数/指示必须跟机构同一时钟走，并且有明显可辨的加速形态（§4b 的幂律 + 末段尖刺），否则观众读不出“变化”；
- 声床恒定，事件靠画面对齐（§2、§3）。
