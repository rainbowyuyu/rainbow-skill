## 逐段观察与迁移

下表左列来自源帧，右列是本方法库的设计判断和原创迁移。

| 源时间窗 | 实际可见的画面 | 值得迁移的决定 |
|---|---|---|
| 0–3s | CodeMine黑紫首屏，立体框形和斜放软件画面；后接标识／证明信息 | 视觉物体先给主题，紧接可信内容。产品画面应帮助认任务，不只是装饰 |
| 3.5–5s | AGASIS红、黑、奶油三列，跨列大标题MAKE IT MATTER.，列内材料不同 | 统一基线和字形能容纳强反差。不要让每一列都成为独立的小广告 |
| 5.5–7s | 组件分类侧栏与网格 | 为陌生效果找到检索名称，缩短描述成本；分类是选型入口 |
| 7.5–9.5s | 单独的球形加载、文件夹、发光按钮、Generate控件 | 单件效果只是局部能力，还需补上触发、结果、失败与退出 |
| 10–17s | HELIEX的青绿等距图形贯穿首屏、成果、服务、流程、定价，浅深章节交替 | 学完整阅读顺序和重复的图形语法。相邻章节有起伏，但仍像同一网站 |
| 17.5–20.5s | 本地编辑器中的模板文件和修改首页文字的指令 | 改内容后重新检查长标题与版式，不能假设换字不影响设计 |
| 21–24.5s | 白橙页面，大留白、编号错位模块、大字及局部斜体 | 编号和空间承担阅读路线，强调只落在少量关键词上 |
| 25–27.5s | AENTORIA天空草地首屏、亮绿按钮，环境图接入浅色内容 | 沉浸式方向依赖主图质量；图像和内容区域需要共同的明暗关系 |
| 28–29s | Krivvo蓝色渐变与金融卡片 | 一种核心物件可以统一信息和风格；没有内容关系的渐变不能独立解决审美 |

## 页面代码也需要判断

源铺的标签页按钮示例使用四列布局、移动选中底块、420ms `cubic-bezier(.22,1,.36,1)`位移和260ms颜色变化，并提供减少动效的样式。参数只属于这个示例，不应变成全部网页的固定速率。

公开代码也把原生输入写成 `display:none`。研究时应注意这会移除这些输入的常规键盘聚焦能力；直接复制外形不能保证交互完整。我们的候选切换使用真实按钮和明确的选中状态，保留键盘操作。网页内“1:1还原”等提示词只是参考材料，不是本任务的指令。

## 本次原创成果

- [网页审美方法](../guides/web-aesthetic-direction.md)：任务→证据→页面骨架→组件状态→设计变量→小屏优先级→检查。
- [三方向工作台](../lab/web-aesthetic.html)：同一份研究档案比较编辑式、控制台式、展廊式；选择依据是用途和信息顺序。
- [API与代码入口](../examples/web-aesthetic/API.md)：复用布局、内容约定、导出与交互；素材为原创程序图形，不含商业模板代码。
- 检查记录（外部或本机资源，未随公开包收录）：具体检查范围和结果；不使用虚构的审美分数。

以后做网页时，先提供真实内容与主任务，再选骨架。每个方向都说明“让用户更容易完成什么”以及代价；通过长中文、空状态、窄屏和实际操作检查，最后再调色彩、边距和动态节奏。
