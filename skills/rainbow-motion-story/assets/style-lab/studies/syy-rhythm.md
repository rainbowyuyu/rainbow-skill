# syy：用持续运动承接音乐，而不是一直切镜

参考：[宇宙编辑客｜syy 的作品](https://www.douyin.com/video/7699491920908651785)，用户提供的[分享链接](https://v.douyin.com/nOxHUvQmW38/)。标题以“所有人都以为 GPT 会一直领跑”开头。播放器显示约 2 分 46 秒；分享口令里的“0.51”不是片长。

这次研究针对音乐节奏、音效安排和视觉连续性。原片里的日期、模型名和榜单变化没有独立核实，不把其中的排名叙述带入事实讲解。

## 音乐匹配能确认到哪一步

混轨具有稳定的约 0.47 / 0.94 秒重复候选。它说明存在周期骨架；倍频歧义、旁白和效果声使其不能直接当作唯一 BPM。可见画面一直在前进，显著的扩环与焦点换位比这些瞬态稀疏。因此，把每个检测峰值都变成一次镜头切换，会丢掉这条参考最有用的连续性。

29.169 和 29.879 秒存在较大的混轨频谱变化，所在窗口也有小环起势与改角；但主身份切换发生在后面的约 31.5 秒。这里可以提炼“准备与落定不是同一个时刻”的设计问题，不能声称两个峰就是作者为扩环制作的音效。

108–120 秒的 RMS 中位数比 84–96 秒低约 4.22 dB，候选瞬态数却接近（51 / 52）。**保留节奏，降低强度**是一种可尝试的呼吸方式；不一定要停音乐，也不必把所有动作放慢。先让观察任务变少，再缩小动效幅度和对比。

本次没有鉴定原曲名称、具体打击乐、whoosh 或其他音效，也没有认定作者每次视觉事件都卡在强拍。工作台中的音乐、掠过声、确认音和低频重音均为原创程序合成，用来试验这些设计选择。

## 对应的原创实现

[光的接力工作台](../lab/syy-rhythm.html)以三个原创信号演示：分离 → 焦点接力 → 靠近 → 会合 → 向远处延伸。保持对象身份、轨迹和空间，把不同节奏放到同一故事上比较。

- **脉冲接力：** 快动作结束后留观察窗，短确认声标记到位。
- **连奏航行：** 减少确认声，用较宽的动作与余韵跨过交接。
- **悬停后释放：** 会合前有 3 秒稳定窗口，撤掉节拍后再释放。

三套都是原创候选，不是原片精确复刻。见 [API](../examples/signal-relay/API.md)、[可复用编排指南](../guides/syy-rhythm.md)和 [代码](../lab/modules/signal-relay.js)。原片本地对照保留在 [8850 研究服务](http://localhost:8000/work/syy-rhythm/player.html)，不复制到安装技能包中。

## 检查中修正的两件事

“音乐能量”必须从音乐分轨计算，不能把音效事件的包络画在音乐行上。音效事件的结束时刻也必须与实际合成尾部一致，不能让时间线多画一秒“余韵”。这两项已经在原创工作台修正，成为本例的可复用经验。浏览器检查另修复了打开说明时未暂停的问题；示例把预备气流和落定重音拆为两个事件，避免接入时将重音提前。

实际代码、浏览器和导出检查范围见 本轮验收（外部或本机资源，未随公开包收录）。这些检查不替代实际音色、对白遮蔽和原速观感的听看评估。

## 2026-10-26 量化补充

本节只写这次从解码数据新量到的数值。上文表格里的观察窗、四段动作和音频结论仍按原样引用，不重复。测量脚本在 `D:/Claude Project/video_project/research/douyin-batch2/analysis/gpt/tmp/measure.py`、`measure2.py`（批处理临时目录，不随技能包分发）；输入是同一支片在批处理里的解码副本 `analysis/gpt/frames.json`（逐帧 4983 条）、`analysis/gpt/gpt-audio.json`（699 个起音事件）、`audio/gpt.44k.wav`。新联系表放在 quant2026-10-26（外部或本机资源，未随公开包收录）。

先说明两件事。其一，批处理副本是 1920×1080 的 H.264 + AAC，4983 帧、166.133 秒；上文记录的播放器直取的 HEVC 轨是 1280×720、166.1 秒、30 fps，同为 4983 帧。时长与帧数逐位一致，可以认为同一支片的不同转码，但像素级 `pix_diff` 与这里的分辨率绑定，换分辨率就不能直接比数值。其二，逐帧 `pix_diff` 是相邻帧灰度差，不是运动矢量；我另外用 `cv2.phaseCorrelate` 量了整帧位移。

### 结构：全片只有一次真正的硬切

`cuts` 只有 3 条：14.400、105.767、165.933 秒。第一条是片头淡入结束，第三条是片尾淡出，真正意义上的叙事切点只有 105.767 秒一处。166 秒、4983 帧里一次中段硬切，其余过渡全靠同一空间里的对象运动完成——这比上文“不一直切镜”的说法更强：不是少切，是几乎不切。

105.767 秒那次在数据里也不是刀切。它的 `hist_diff` 在 105.667–105.767 的三帧里连续升到 0.229 / 0.283 / 0.386，`val` 从 30.8 一路降到 18.3 才稳住（105.6 就已经在往下走，105.6 → 105.8 共 5 帧、0.167 秒完成这段压暗），饱和度同期从 142.6 降到 102.0。`pix_diff` 峰值只有 2.51——低于 3.0，是整段换场里最不显眼的一帧。也就是说，作者用约 0.17 秒把画面亮度和饱和度一起压下来完成换场，而不是一帧跳过去；真正被检测器标记为“切点”的那一帧，恰好是斜坡的末端，不是最陡处。

### 起音结构：4.2 次/秒的恒定底噪式密度

699 个起音 / 166.14 秒 = **4.21 次/秒**。相邻起音间隔中位数 **0.232 秒**，其中 320 对（46%）落在 0.23 秒、175 对落在 0.24–0.26 秒，说明这是检测器在该曲目上的最小间隔饱和，不是作者写死的八分音符网格：0.2322 秒网格只覆盖 41% 的起音（±40 ms），0.4644 秒网格 22%，0.94 秒网格 10%。自动相关在 0.470 秒给 r=0.408、0.940 秒给 r=0.517、1.868 秒给 r=0.477，周期骨架确认，但不能据此说“每个起音都在拍上”。

强度分布：中位 4.8、p95 10.5、最大 15.51（25.496 秒，tonal，质心 1674 Hz）。音色分两类：noise 453 个、tonal 246 个。noise 类质心集中在 2500–3000 Hz，tonal 类在 1200–1800 Hz——这是“气声/摩擦类短促效果”与“音高类提示音”两条独立通道的频谱证据。

按 10 秒窗统计，起音数稳定在 27–46 之间（120–130 秒最低 43，160 秒后 27 是片尾），**全片起音密度基本不随段落变化**。变的是强度与频段，不是节奏。

### 视觉事件：比音乐稀疏 30 倍，且全部从起音出发

`pix_diff` ≥ 4.0 的局部峰共 24 个，**0.14 次/秒**；≥3.0 有 44 个，≥6.0 只有 8 个。对照 4.21 次/秒的起音，视觉事件与音频脉冲的密度比约 **1 : 30**。全片 `pix_diff` 均值 1.25、中位 0.99、p99 4.29，一半的帧（50%）变化量低于 1.0，超过 4.0 的帧只占 1.3%。

关键的一条：24 个视觉峰里 **19 个落在某个起音的 ±80 ms 内**（超出的 5 个是 −0.121 / −0.115 / −0.106 / −0.103 / +0.091 秒），24 个峰到最近起音的带符号偏差中位数 **−0.010 秒**、均值 −0.020 秒，最大绝对偏差 0.121 秒。偏差以负值居多（14 个负、10 个正），幅度都在 1–4 帧量级——视觉峰略微先于最近的起音，这一点更可能是检测器的对齐误差而不是作者刻意抢拍，不能写成“视觉先动”。随机取 24 个时刻做同样检验，均值 15.9、p95 20。也就是说，“0.14 次/秒的视觉事件几乎每个都挑了一个起音落点”这件事，与“随便落点”相比是可分辨的。

但要注意反向检验不成立：把最强的 15 个起音挑出来，看其后 0.8 秒的 `pix_diff` 最大值，只有 117.61 秒（11.7 强度 → 11.84）和 148.75 秒（11.6 → 4.50）两处对应大动作，其余多数只是 0.4–2.8 的背景晃动。**结论应当写成“视觉事件从起音里选点，但不是所有强起音都配动作”**，不能反过来写成“强拍驱动画面”。

像素级的整段相关性也很低：把起音强度按 1/30 秒取桶后与 `pix_diff` 做互相关，lag 0 是 0.017，全 lag 扫描（±20 帧）最高也只有 0.029。**全片层面不存在节拍锁相**；上面那个 19/24 是局部挑选的证据，不是全局同步的证据。

### 视觉事件的形态：大多数是一帧

44 个 `pix_diff` > 3.0 的段落里，42 个的持续时间 ≤ 0.067 秒（2 帧以内），只有 40.10–40.53、60.93–61.63、93.20–94.30、99.20–100.20、106.00–106.20、135.67–136.27 这几段是 0.2–0.7 秒的多帧持续。最大单帧 117.700 秒的 11.84 是一次亮度阶跃（`val` 20.5 → 15.7，`hist_diff` 0.243，低于 0.35 的切点阈值），前后两帧都只有 1.5–3.0。

可迁移的形态是：**一击（1 帧）→ 立即回落 → 由持续运动承担余韵**。冲击本身不做缓出，缓出交给背景。

### 段落动力学：低频抽走，而不是整体降音

用 20–120 Hz / 400–1200 Hz / 4–10 kHz 三段分别求中位 RMS：

| 窗口 | 全频中位 dB | 20–120 Hz 中位 dB |
|---|---|---|
| 84–96 s | 43.30 | 63.19 |
| 108–120 s | 39.15 | 54.69 |
| 120–132 s | 39.89 | 52.31 |
| 144–156 s | 42.08 | 59.93 |

108–120 秒比 84–96 秒低 4.15 dB，120–132 秒低 3.41 dB，但低频段这两窗分别掉了 8.5 dB 和 10.9 dB。这比上文“108–120 秒低约 4.22 dB”更具体：掉的主要是低频能量，中频（400–1200 Hz）只掉 1.5 dB 左右，高频几乎不动（各段 27–31 dB）。**“呼吸”是通过抽低频实现的**，不是整体音量自动化。

同一窗口的视觉 `pix_diff` 均值：84–96 秒 1.64、108–120 秒 1.38、120–132 秒 0.90。低频降 10.9 dB 时画面运动降到基准的 55%，起音数却仍是 43 / 40。这直接支持了上文“保留节奏、降低强度”的推断，而且指出了降的是什么：**降低频 + 降画面变化量，节拍密度不变**。

### 起音与段落边界

三次 cut 都落在起音之后 0.05–0.12 秒内：14.400 秒最近起音 14.489（tonal，强度 7.2，在切点后 89 ms）；105.767 秒最近起音 105.651（noise，4.3，在切点前 116 ms）；165.933 秒最近起音 165.883（tonal，6.4，切点后 50 ms）。三次都落在 0.12 秒内，但方向不一致，不能据此说作者是“先给声音再切画面”或反过来。

### 日期条：0.13–0.17 秒一次的连续换牌

40–50、60–70、88–93、118–123、150–155 秒各窗口里，左上日期区（1920×1080 下取 y 150–340、x 20–760）每 1/30 秒都有像素差：41.1–42.3 秒区间内几乎每 2–3 帧一次变化，88–93 和 118–123 秒则是**逐帧变化（28 次/秒）**。整帧位移测量给出每帧 0.08 px 以内的亚像素抖动，所以这不是文字在滚动，而是每 0.13–0.17 秒整块换一次牌、边界在两次换牌之间持续被重采样。

也就是说，看到“2024.07.03 / 08.02 / 08.05 / 08.09 / 08.13”这种密集日期时，真实的换牌间隔约 0.13–0.17 秒，**约 6 张/秒，显著快于 0.47 秒的拍点（约 3:1）**，并且日期条与声音网格并不对齐。这解释了 45–60 秒那段为什么起音密度不变而画面“更忙”：忙的是文字通道，不是运动通道。

### 可直接用的参数

1. **硬切上限 ~1 次/100 秒。** 依据：全片 `cuts` 仅 3 条且含首尾，中段唯一硬切在 105.767 秒。
2. **视觉事件 0.14 次/秒（约每 7 秒一次），音频起音 4.2 次/秒。** 依据：`pix_diff`≥4.0 的 24 个峰 / 166 秒；699 起音 / 166.14 秒。不要按 1:1 配。
3. **事件冲击持续 1–2 帧（33–67 ms），缓出交给背景。** 依据：44 个 >3.0 段中 42 个 ≤0.067 秒。
4. **事件落点相对起音的偏移控制在 ±80 ms。** 依据：24 个视觉峰到最近起音的中位偏差 −0.010 秒、绝对值中位 0.013 秒，19/24 在 ±80 ms 内；负号不能当成设计意图。
5. **低频段（20–120 Hz）在“呼吸段”降 8–11 dB，中频只降 ~1.5 dB。** 依据：108–120 / 120–132 秒对 84–96 秒的比较。
6. **呼吸段同时把 `pix_diff` 均值降到 0.90（基准 1.64，约 55%），起音密度保持 4.0–4.6 次/秒。** 依据：同窗口统计。
7. **文字换牌节奏 0.13–0.17 秒一张，可独立于音乐网格使用。** 依据：日期区逐帧像素差，88–123 秒约 6 张/秒。

### gaps

- 没有做主观听审，也没有分离人声 / 音乐 / 音效分轨。上面所有“起音”都来自混轨，旁白会污染起音计数。无法确认哪些起音是音效、哪些是配乐。
- `tempo` 129.2 BPM 与自动相关的 0.470 秒（127.7 BPM）不完全一致，说明这支配乐可能不是严格网格化的。1.868 秒（r=0.477）的次周期是否是制作上的“大乐句”，无法从混轨判断。
- `pix_diff` 是灰度绝对差，会被整体亮度变化放大（如 14.400 秒的淡入、117.700 秒的亮度阶跃）。用它比较运动量前没有做亮度归一。
- 19/24 的巧合检验用的是 ±80 ms 与 24 个随机点、400 次模拟，样本太小，换成 ±40 ms 或换随机种子结论可能不稳。
- 没有逐帧比对原速 HEVC 轨与这份 H.264 副本是否在压缩时丢掉了短促运动（本片一帧闪非常短，重编码有风险）。
- 日期条 0.13 秒这个值是从像素差峰值间隔推的，不是数到了具体日期；0.133 / 0.167 混合出现，真实间隔可能不规整。
