# 有语气的科普旁白：逐句配音导演

本页是可迁移的导演约定，适用于中文科普的句源制作与接缝检查。保持用户已授权的个人音色，把语气变化放在问题、动作和结果上。这里的强度、重音和停顿均是**表演意图**；只有当前合成引擎明确支持的参数，才能映射为 API 控制。文字提示不能保证精确的毫秒停顿或声学变化。

## 先安排听觉任务

先写清这句要让观众发现什么，再安排声音。一个段落可以有轻快的提问、平稳的机制解释和简短的结果确认；不用每句话都抬调结尾。表达张力来自前后对照，持续大声会抹平对照。

| 句子承担的作用 | 推荐声音意图 | 与画面和音乐的交接 |
|---|---|---|
| 开场好奇 | 靠近观众，起句利落；把问题词说清，尾部轻微悬住 | 先展示可见动作，再提出问题；音乐提前让开字头 |
| 机制解释 | 稳定、中等能量；关键名词略放开，一个因果说完整 | 公式当前项稳定可读，实体同步发生动作；避免跟着节拍逐字念 |
| 意外结果 | 在确有对比的结果词上短促提亮，随后收回 | 结果已出现再确认；不用惊叫或夸大实验结论 |
| 高潮前蓄势 | 前半句推进，末尾有意识地收住；保留完整尾音 | 句子完成后音乐和动作接手，不在新术语中间断开 |
| 音乐留白 | 无旁白；无需给 TTS 发送“停顿”或空文案 | 用一个完整的动作弧展示已讲明白的结果，出口再接下一问题 |
| 浪漫收尾 | 稍舒展、温暖、仍用日常嗓音；落在具体物件与结果上 | 镜头逐渐安定，尾句留余地给环境声；不用气声或泛泛升华 |

这张表用于选意图，不要求每段集齐六种状态。科学限定词照常读清；“可能”“在这个条件下”等词不能因配音表演被吞掉。

## 每个句源保存的最小约定

以下 JSON 是**工程侧元数据示例，不是任何供应商的请求体**。`text` 只放真正要念的文字；导演说明不能混入正文被念出来。

```json
{
  "id": "mechanism-02",
  "text": "比例项看眼前的偏差，微分项盯着偏差变化有多快。",
  "voiceProfileRef": "existing-user-voice",
  "role": "mechanism",
  "direction": {
    "tone": "清楚、平稳，像面对面解释一个刚发生的动作",
    "intensity": 0.35,
    "rateIntent": "自然速度；两个术语各稍放开，不逐字顿读",
    "emphasis": ["眼前的偏差", "变化有多快"],
    "pauseIntent": [{"afterText": "偏差，", "kind": "clause-breath"}],
    "ending": "自然落定，为下一句保留连续感"
  },
  "context": {
    "previousText": "机器人刚偏出去，控制器为什么就开始往回拉？",
    "nextText": "把这两个变化放到同一张图上，就能看清它们各自做了什么。",
    "sceneAction": "偏差位置与偏差变化率分别高亮",
    "continuityGroup": "controller-mechanism"
  },
  "musicHandoff": "speech-bed",
  "pronunciationRefs": ["project-pronunciation-dictionary"],
  "review": {"listened": false, "voiceIdentityChecked": false}
}
```

- `intensity` 是工程的 0–1 导演尺度，便于比较候选；它不是音量、情感强度或采样温度的通用 API 值。不同引擎须各自映射，无法支持时明确记录。
- `rateIntent` 优先用自然语句表达。引擎支持原生语速时才设置它实际接受的范围与字段；范围以当前文档为准。合成后不为卡音乐统一减速、变调或拉长音节。
- `emphasis` 通常只选一个主重音，必要时增加一个对照点。重点来自句义，避免每个名词都重读。词表外的标记或 SSML 未验证支持前不进入请求。
- `pauseIntent` 区分从句换气、结果停留和段落交接。它给合成与剪辑提供位置意图；实际停顿按输出音频记录。需要加留白时，在完整句源之间排时间，不切入音节。
- `context` 是相邻句与场景事实。支持上下文的模型才能按它的专用字段发送；只支持全文合成时，将同一语气组按自然段合成后对齐。不得把前后句当作当前句正文重复念一遍。
- `voiceProfileRef` 始终引用同一用户音色配置。提示词描述表现方式，不添加新性别、年龄、口音或“另换一个播音员”。相邻句保持距离感与音色，情绪变化有铺垫。
- `review` 初值保持未检查。参数已发送、ASR 文字正确或响度合格，都不能自动把听审改成通过。

## 三组同文 A/B 样句

每组 A/B 的正文、声音身份和合成格式完全相同，只改变导演意图。先比较单句，再与其前后句连听。文字样例用于测试，不表示机器人实验已经发生或达成该结果；正式叙事必须与实际演示对应。

### 提问：好奇与紧迫

**共用正文（21 字，含标点）：**

> 机器人刚偏出去，控制器为什么就开始往回拉？

| 候选 | 给引擎的自然语言方向 | 听审重点 |
|---|---|---|
| A：好奇 | 保持本人日常说话的音色，带一点真切好奇。前半句说得轻快，在“为什么”上有一点提问感，“往回拉”连贯地说完，不提高嗓门。 | 问题成立，字尾完整；不念成广告口号 |
| B：现场感 | 保持同一音色，像刚看见机器人偏了一下，略加快前半句，在逗号处自然换气，把“就开始”说得更有反应感；后半句仍清楚。 | 能听出动作发生后的反应；不尖叫，不赶掉“控制器” |

### 解释：平稳与对照

**共用正文（23 字，含标点）：**

> 比例项看眼前的偏差，微分项盯着偏差变化有多快。

| 候选 | 给引擎的自然语言方向 | 听审重点 |
|---|---|---|
| A：稳定解释 | 保持本人日常讲解音色，平稳清楚。两个术语连续地读，逗号处自然换气，整句有一个完整的落点。 | 术语可懂，节奏不机械；不把每个字念开 |
| B：对照强调 | 保持同一音色和自然速度，前半句轻落在“眼前的偏差”，后半句提亮“变化有多快”，两处重音形成对照，结尾收回。 | 观众能听出两个关注量的差异；无夸张升调 |

这句中的微分项按误差变化率表述；具体工程若采用对测量值求导、滤波微分或其他实现，应同步更正文案与图示。

### 结果：确认与舒展

**共用正文（24 字，含标点）：**

> 风又推了它一下，机身晃过以后，水杯慢慢稳了下来。

| 候选 | 给引擎的自然语言方向 | 听审重点 |
|---|---|---|
| A：结果确认 | 保持本人日常音色，像看着实验结果说话，清楚地交代动作顺序。“稳了下来”自然落定，不补感叹。 | 时间关系听得懂，句子没有被读成胜利宣言 |
| B：浪漫舒展 | 保持同一音色，前半句有动作感，后半句渐渐放松，把“慢慢稳了下来”连贯、温暖地说完；用正常声音，不耳语，不拖尾。 | 能与安定下来的画面接上；音色未变，收尾不黏腻 |

## 从试音到整段

1. 从现有、已授权且实际可用的个人音色配置开始，保留参考文件或声线 ID 的出处。先产出自然基线，再对同文做表现候选，方便判断变化来自哪里。
2. 先检查词典。专业全称、字母与多音字分开保存“屏幕写法”和“合成读法”；修发音时不擅自改科学含义。核对整词连贯度，不仅核对单字。
3. 以完整意群为单位合成。通常一到数句共享一个连续情境，机制解释保持稳定，只有叙事转折才切换表演状态。引擎只能逐句生成时，保留前后文并检查每个接缝。
4. 留存原始自然句源、导演元数据和实际请求能力记录。引擎不支持某项时，报告该项没有生效，不用统一增益或音频慢放冒充情感控制。
5. 先听干声的连续段，再听 BGM 与音效混音。遇到音乐高潮，优先让完整句子结束后进入展示窗口；新知识点留在音乐已让位的解释段。
6. 替换某句后，重查它的前一句尾音、当前句与下一句字头，再更新字幕和动作锚点。不要把旧版时长当作新版合成的真实时长。

音频听审记录至少包含：漏字/错读、术语连贯度、个人音色一致性、是否有刻意腔调、重音能否帮助理解、句间情绪是否跳变、音乐是否遮住弱字。ASR 与时长/峰值测量用于发现问题；主观结果须由实际试听填写。
