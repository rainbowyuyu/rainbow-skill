# 小事儿：沿着同一个包走，模糊才有方向

这条参考片值得复用的，是**物体接力、相对运动、停下来读结果**的组合。数据片先在端点里获得身份，镜头跟它下潜、沿通道横移、到达另一端，再拉远比较。快镜头交代路径，稳定镜头交代关系；字幕和少量导航信息提供固定参照。

研究对象：[小事儿《每发一包都等确认，视频要传一个多小时》](https://v.douyin.com/KhjwCTsjiNw/)。源文件 1024×576、30 fps、480.433333 秒，首帧 PTS 为 0。源文件 SHA256：`a53ab07ce45f0bfe0c519b5c5d6dc6c0931f199485c1ff3c1815a09448fa5964`。素材路径在证据清单（外部或本机资源，未随公开包收录），本次没有复制完整原视频。

## 1. 先走通路径，再给机制命名：55–62 秒

```js

const options = {
  cameraMode: 'follow',
  blurMode: 'temporal',
  fps: 30,
  shutterAngle: 180,
```

## 可选择的代码机制

| 候选 | 适用内容 | 运动与停顿 | 状态约束 |
|---|---|---|---|
| 相对运动曝光 | 高速主体、相机追踪、机械传动 | 追踪时背景动；解释时回稳定视角 | 每个子样本重算相机与物体，HUD 后合成 |
| 同一窗口接力 | 排队、控制回路、可用资源 | 全景定位 → 推近框 → 状态改变 → 回全景 | ID 与单位不变，确认事件后再移动窗口 |

| 比例条变通道包 | 开销、部件组成、信号编码 | 读比例 → 标签退场 → 跟路径 → 看结果 | 表示切换有接力，不能制造重复物体 |
| 数量换尺度 | 容量、时长、利用率 | 原量 → 拉出尺度 → 短停 → 比较 | 数值与图形同源，尺度标签随转换更新 |

## 复现时检查什么

- **身份**：一个包在离开、通道中、到达端有没有同一个 ID；表示变换是否有明确交接。
- **因果**：窗口因确认到达而更新，不能因镜头走到下一段就提前变化。
- **阅读**：标签出现时对象已经可辨认；读关键比例和结果时保留稳定窗口。
- **运动**：跟随机位下主体与背景的屏幕速度分别计算，转弯不复用错误方向的拖影。
- **尺度**：放大不改变原数据，刻度与单位始终对应；不同表示不要误装成真实物理尺寸。
- **验证范围**：逐帧图可核对单帧模糊与相邻状态，实际播放用于发现停顿、卡顿与速率问题；两者分别记录。

原文第 6 节把 368.9–372 秒写成“模糊由相对运动决定”，属于定性判断。本节补齐可核对数值，来源分三类，逐条标注：**〔新〕**为本次从 1920×1080 原片按 30 fps 逐帧重测；**〔解码〕**取自同批 `analysis/pieces/frames.json` 与 `pieces-audio.json`；**〔原文〕**为上文已有事实。

### 复现顺序（可直接排进时间轴）

1. 静置 0.6 秒以上，让观众读到基线信息（对应 368.5–369.1 秒）。
2. 用 ease-in 加速 0.4 秒进入最深模糊，**深度只停 1 帧**。
3. 在方向翻转点（约谷值 ±33 毫秒）改运动轴，拖影从纵向换横向。
4. 1 帧台阶回焦到 0.6 基线，短暂半清（约 0.4 秒）后再次下潜——**这一“回弹再下潜”是原片区别于普通甩镜的关键**。
5. 再用 1–2 个 1 帧台阶跳到 1.28 基线全景，并在该状态停留 ≥1 秒（原片 31 帧、极差 2.0%）。
6. HUD 与字幕在模糊层之上合成，不做任何模糊；音效晚于模糊入口 0.5–0.8 秒，频段取 3–6 kHz。

### 不能断言的内容

- 不能从压缩视频反推快门角度、采样数、模糊核形状或渲染引擎。上文这句限定仍然成立，本次没有推翻它。
- 20% 残留里混有曝光变化：谷值帧均值亮度从 36.8 降到 28.5、标准差从 38.4 降到 21.6，说明画面同时变暗、变平（运动模糊把高光摊开）。**清晰度下降不等于纯模糊半径增大**，两者本测量无法分离。
- 各向异性是“剩余边缘方向”的间接推断，不等于拖影长度的直接测量；本窗口未做逐帧拖影像素长度拟合。
- 帧间光流在深度模糊帧上不可靠：369.333–369.367 的世界区中位位移为 0.00、p90 仅 0.05 像素（960 空间），这是算法在无纹理帧上失效，不是物体静止。**本段没有可用的像素位移速度值。**
- 所有时长精度为 1 帧（33.3 毫秒），不能声称“0.400 秒”精确到毫秒。
