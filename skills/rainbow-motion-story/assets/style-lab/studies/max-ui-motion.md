## 关键窗口：对象身份怎样穿过布局变化

## 关键窗口：点击之后，让结果成为下一镜的起点

24.5–26.4秒（外部或本机资源，未随公开包收录） · 26.5–27.5秒（外部或本机资源，未随公开包收录）

`+Comp` 的轻压建立操作反馈；随后可辨认的紫色片段与蓝色播放头把视线带到时间线。界面先让这一结果成立，再整体上移。按钮、片段和整个容器不必共用同一个缓动曲线：按钮响应要明确，片段移动要能跟住，结果阅读时容器应稳定。

自己的状态机可拆成 `press → transfer → commit → read → leave`。点击只触发一次提交事件；装饰高光不能提前把尚未提交的片段显示为完成。拖动时间线回看时，每个阶段从绝对时间求值，不能依赖上次播放到哪里。若用于真实产品，操作失败、取消和重复点击还需要独立状态，不能把广告中的顺畅路径当作完整交互逻辑。

“呼吸”在这个窗口表现为动作分工：局部按压较小，身份交接更明显，落定后保留阅读，再由群组移动收尾。没有必要让所有元素持续浮动。具体停留时长要按自己的文字量与信息变化测定；本研究没有恢复原片精确 easing 或速度曲线。

## 配色、文字与空间

整体以暗场托住界面，蓝色承担明显的操作和产品识别，紫色片段在关键交接处保持可辨。白色大字承担短时主叙事，进入复杂界面后文字退到相对清楚的位置。颜色、文字大小与相机距离一起变化，不能只提取一组色值就获得同样效果。

多面板有前后层次和倾角，后续的局部推近又回到具体操作。原创实现应让相机或投影、面板层级和输入目标共用几何；不要视觉上点在前面，实际高亮却来自后面。真实产品界面仍需保持命中区与可访问性，不能照搬广告里的夸张透视。

页面描述中，作者声称采用 AE 矢量重构、C4D 镜头及 PR 音效。这里将它保留为**作者的制作说明**，没有取得工程或插件实现，不能据此确认具体管线。本轮未听审，不能评价 PR 音效的实际时机或主观品质，也不能把画面波形当作听到的声音。

### 三、音频：节奏不是对齐到拍，是对齐到 onset

`tempo=136`（拍长 0.4412 秒），但把 183 个 onset 拿去拟合节拍相位，最好的相位平均误差 **0.107 秒 = 24.3% 拍长**，相当于没有相位锁定。所以"136 BPM"不能当作排版的网格用。

真正对齐的是 onset。把 `hist_diff>0.15` 的 19 帧全部列出并与最近 onset 配对，它们不是离散切点，而是**簇**：

| 帧簇 | 帧数 | 与最近 onset 的差 | 判读 |
|---|---:|---|---|
| 4.000–4.067 | 3 | +17 / −16 / −50 ms | 多帧渐变，跨 0.07 秒，不是一帧切 |
| 4.467–4.733 | 4 | −78 / +98 / +65 / −35 / −135 ms | 跨 0.27 秒，是转场过程 |
| 5.367–5.433 | 2 | −50 / +24 ms | |
| **9.233** | 1 | **−84 ms** | 单帧硬切，声音先到 |
| 10.600–10.700 | 4 | +12 / −21 / −55 / −88 ms | 含单帧硬切 10.667 |
| 12.967–13.000 | 2 | +13 / −20 ms | 峰动作，非切 |
| 32.300 / 34.700 | 各 1 | +92 / +153 ms | 弱变化，不对齐 |

读得出来的规律：**峰动作帧的偏差都在 ±21 ms 内**（10.600、10.633、12.967、13.000、4.000）；**两处单帧硬切的声音都先于画面 55–84 ms**（9.233、10.667）；而弱变化（32.30、34.70）偏差 90–150 ms，基本没有对轨。三档分明，这比"全部对齐"更像是有意为之。

切点稍晚于 onset 是合理的——声音先起，画面再切，反过来会显得画面超前。onset 间距中位数 0.185 秒，分布集中在 0.12/0.14/0.16 秒，基本是十六分音符密度的连续音型，不是每拍一个大点。24.4–27.7 秒这一窗的 onset 密度 6.36 个/秒，比全片 5.15 个/秒还密 23%，而画面是静的——**声音在动，画面在停**，这解释了为什么这段"没有大动作"却不闷。

9.10–9.38 秒 RMS 从 −16.9 dB 抬到 −5.8 dB，正好压在 9.23 的切点上；24.43 秒（切点）−8.0 dB，24.52 秒升到 −3.5 dB 后 0.2 秒内掉回 −20.1 dB。切点处有明确的短促能量峰。

### 四、可执行参数（带单位与来源窗口）

1. **单动作时长 0.067 秒（2 帧）**为默认值，只有"结果阅读"类动作可以到 0.33–0.5 秒，全片超过 1 秒的只有 2 段。来源：43 段 `pix_diff≥1.0` 的中位数。
2. **一次缓入不要超过 0.6 秒，超了就拆成两段**：按钮 24.467 秒起速度 12→8→4→2→1 px/帧，到 25.067 秒（0.60 秒、62% 行程）几乎停住；随后 25.20 秒起第二段，先 7 帧稳定 −2 px/帧（0.23 秒），末 4 帧才加速到 −4 至 −5.8。两段之间有明显低速谷。来源：`ui_btn3.py` 按钮上边缘序列，总 97 px、跨 1.13 秒。
3. **收尾时间常数按场景分三档：0.11 秒（黑场/冲击）、约 0.24 秒（UI 元素自身位移）、0.41 秒（亮场内容卡）**，最快与最慢差约 4 倍。来源：12.90、24.47、9.33 三个窗口的拟合，R² 分别 0.808/0.997/0.968；按钮的 τ 随渐近线在 0.19–0.38 浮动，按量级用。
4. **静置窗 ≥1.0 秒，且占全片约 50%**；最长两段 2.3 与 2.4 秒，分别放在中段和片尾。来源：`pix_diff<0.5` 的连续区间统计。
5. **入场不要补间**：`+Comp` 在 24.467 秒一帧内从 50×26 变成 208×67，面积 ×16.4。想要"弹出"的感觉，直接用一帧硬出现 + 随后位移，比 6 帧缩放更快也更像这个参考。来源：`ui_btn4.py` 24.20–24.60 秒。
6. **持续漂移用 0.1–0.8 px/帧（30 fps 即 3–24 px/秒）**，且保持单向；一旦超过约 1 px/帧就要走加速，不要匀速走出画。来源：25.77–27.37 秒相位相关逐帧位移。
7. **对齐用两档而不是一档**：作用于画面的"峰动作"帧对齐到 onset 的 ±20 ms；单帧硬切则让声音**提前** 55–85 ms。来源：`hist_diff>0.15` 的 19 帧配对表。注意反例——弱变化（32.30、34.70 秒）偏差 90–150 ms，说明作者并非逐帧全对齐。
8. **音频密度可比画面密度高 20–25%**：画面静止时 onset 仍可维持 6.3 个/秒。来源：24.4–27.7 秒 vs 全片 onset 密度。

### 五、不能断言的部分

- 上述"峰动作 ±21 ms / 硬切声音提前 55–84 ms"来自 `hist_diff>0.15` 的 19 帧、7 个帧簇，样本小；且 onset 检测器本身有约 ±1 帧（33 ms）的分辨率限制，"提前 55–84 ms"只比噪声大 1.7–2.5 倍，不能说作者做了逐帧手动对轨。
- τ 值是**对 `pix_diff` 曲线做指数拟合**得到的等效时间常数，不是作者使用的 easing 控制点。`pix_diff` 同时混合了位移、缩放、亮度与纹理变化，所以 τ 只能当作"这段画面多快静下来"的经验量，不能反推 cubic-bezier。按钮那条 τ 尤其不稳（0.19–0.38 秒），因为它是先到渐近线再二次抬升的两段式，用单一指数去拟合本身就有偏。
- 27.37 秒之后每帧 16–23 px 的读数来自相位相关，而该段响应值已跌到 0.395–0.570（运动模糊/大面积变化）：**这个数偏低的可能性大于偏高**，不能当作精确位移。
- 上文"约 3.2 秒有面板弯曲形变"这次没有复核；本次测量没有针对弯曲做任何几何分析。
- 按钮 208→176 px 的宽度收缩对应高度 64→54 px，宽高比从 3.25 变到 3.26——是整体缩放 0.85，不是压扁。但 25.10–25.60 秒同时在做上移，`pix_diff` 极低（0.07–0.16），这不一致：**更可能是遮罩/裁切或透视收缩而非真实缩放**，本轮无法区分，列入待查。
- 声音端没有做频谱分析，只说得出"有 onset 和 RMS 峰"，说不出是鼓点、whoosh 还是 UI 合成音。上文第 60 行"不能评价 PR 音效的实际时机或主观品质"依然成立。
- 颜色只能给到量级。按钮调色板取 24.4–25.6 秒众数得 `#2045EB`（`#1C40E3`–`#2046ED` 一簇），紫色片段在 25.7–27.6 秒的众数是 `#0C093E`、`#060428` 这类深紫，只有个别帧的亮部到 `#3E1EDA`。前者比后者可靠，因为紫块面积小、被黑色主体稀释。全部取自 H.264 解码副本，不能当原片色值。
- **本轮仍没有做完整连续观看**，所以"这段流畅不流畅"这种主观判断依然没有依据；上面所有结论都是像素与时序的统计，不替代主观审片。
