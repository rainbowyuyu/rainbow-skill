# 海洋新能源场景：水、天空、陆地与玻璃标题

用于海上风机、海岸校园和入水/出水镜头的设计与诊断。以下是可选实现路线，按当前镜头、许可和渲染预算选择，先用代表镜头验证再扩展；不能把推荐做法记成已经在成片验证的能力。目标是让水面、设备、文字和相机处在同一套光照/坐标关系里。

## V5 历史复现配方与证据边界

以下为《浙江大学·海洋新能源》第一期 V5 留存的实现参数和抽帧记录，可作为诊断起点。用户后续指出水纹、光影和模型仍粗糙，因此不能把历史“通过”当作画质已达标或全片视觉验收：

- 水面使用固定种子、多尺度 Gerstner 波与 WaterPro 3.1.1 licensed WebGL compatibility adapter 叠层；兼容层不宣称原生 FFT、SSR、WebGPU 或 CFD。适配层混合透明度约 `0.68`，泡沫使用 `foam2`/`foam4`，反射、折射、泡沫和尾流共用绝对秒数。
- 玻璃标题使用世界空间 `MeshPhysicalMaterial`，轻薄底板约 `transmission 0.22`、`roughness 0.20`，边缘高光和环境反射克制；标题与水面倒影同帧更新，字幕仍留在底部安全区。
- 陆地采用 Poly Haven CC0 `blue_lagoon` HDRI、`fir_sapling` LOD glTF 和 `grass_ground` PBR；近景树保留枝干/叶簇，中远景只用实例和雾化，固定帧检查 z-fighting 与闪烁。
- 风机近景保留导管架、浮式基础、系泊、机舱剖切、轴系、发电机、变流器和海缆；动态标注绑定轮毂/风场节点，风雾路线与旋转弧线不覆盖字幕和 Logo。
- 历史抽帧记录包含 `0/120/480/960/1800/3600/5700/7200/9000/9600/10795/11014` 与95张640×360联系表。记录抽帧不等于审美合格；固定帧不替代正常速度看片，运动审计若出现高速俯冲段必须单独标注为需复看片。

## 先把画面分成三种尺度

- **近景**：镜头前 1–20 m 的浪峰、泡沫、喷溅和风机表面高光。给近景独立的高频法线/泡沫层，景深只压背景，不能糊掉机舱接缝、叶根或标签锚点。
- **中景**：风机、平台、导管架/浮体和海缆。用真实尺寸的水线、吃水、反射和接触阴影建立重量感；同一对象的倒影、泡沫和阴影跟随同帧相机。
- **远景**：海平线、云层、陆地和校园。用低频波纹、航空透视和雾化降低细节，避免远处模型仍像近景白模。

镜头变焦时三层一起更新。任何层单独平移或缩放都会造成“水、风机、陆地不在一个世界”的感觉。

## 水面与真实互动

1. 先核对水位、单位、相机 near/far 和风机吃水深度，再生成波面。至少叠加低频主浪、中频风浪和近景细波；波长、振幅、速度按镜头尺度调，避免所有浪同相同高。
2. 反射与折射使用与水面同一绝对 `t`、同一法线和同一相机姿态。水上透明机壳/浮体要先解决深度写入与渲染顺序，再调 alpha；提高透明度不能修复倒影盖住物体的问题。
3. 设备与水发生可见关系：塔筒水线有轻微湿边；浮体周围有顺风方向的船首波与尾流；导管架杆件在水下逐渐降低对比度并带雾化；浪峰遮挡时只遮挡应被遮挡的部分。泡沫是接触/破碎的结果，不要均匀环绕每根桩。
4. 太阳高光使用粗糙度渐变、微法线和受限 sparkle；禁止整片镜面白线。需要表现“水反射文字/风机”时，使用受水面法线扰动的倒影/投影，保留标题主体清晰度。
5. WaterPro 原生、兼容适配器、Three.js Water/Water2 和固定 Gerstner 需要在 provenance 中分开写；未运行 FFT、SSR、WebGPU 或 CFD 时，不以这些名称宣传。所有波面必须帧号可重算，禁止 `Date.now()`、`Math.random()` 或累计 delta。

### 远景去纹理与结构接触（V6 增补）

- 泡沫贴图只服务近景：在相机距离约 40 m 以内保留 `foam2/foam4` 的高频细节，约 40–230 m 线性淡出，远景改用固定种子低频噪声和波峰项。不要把同一张泡沫图平铺到整片海面；它会在高机位形成棋盘格、横向带状和重复纹理。
- 桩脚、导管架腿、升压站支腿和半潜浮力柱各自注册局部接触体，接触泡沫由解析距离带和顺流尾迹产生，半径按真实柱径设置。接触泡沫应贴着水线、在下风向拉开，不能用一个大圆环代替所有支撑。
- 半潜式结构必须让三柱、封闭 pontoon、中心塔柱、压载和系泊在同一坐标系；水线以上的柱体用浅色主材、吃水/压载用深色材质，并加一条窄水线标识，保证远景仍能读出拓扑。近景再展示焊缝、检查环和锚链，避免黑色孤立圆筒的玩具感。
- 海岸道路/陆地高程需高于岸线 mask，增加窄路肩或排水边缘；固定远景相机检查道路、沙滩坡面和水面没有穿模。若只提高雾或反射强度遮住接缝，视为未修复。

## 天空、云和陆地

- 天空用物理天空或许可清楚的 HDRI 做主光，太阳方向、色温和曝光固定在镜头轨道内；地平线保留一层航空透视，避免“纯色天空+细线地平线”。云层以远景体积/贴图为主，不能在每帧随机抖动。
- 陆地采用分层材质：地形 baseColor、粗糙度、湿润暗部、道路接触阴影和海岸泡沫线。校园建筑至少有窗洞、屋顶设备、树池/路缘，白色楼块不能全部同一亮度。
- 树木用少量有许可的低/中/高 LOD 实例，树干、枝条、叶簇和风向一致；近景保留枝叶轮廓，中远景通过雾和景深降细节。草地用成簇实例和风向噪声，避免“球形树+贴地绿点”。
- 修复陆地闪烁时优先查共面、阴影图分辨率、透明排序、TAA/抖动和 z-fighting；固定相机与帧号复现后逐项关闭，而不是加一层白雾掩盖。

### 资产检索与小包策略

优先从 Poly Haven 的 API 和资产页挑选 CC0 HDRI、树木/草本 glTF 与地面 PBR。开放海域用 `puresky`；`blue_lagoon` 含岸边地物/电线，不能直接冒充纯海天。树木可选真正含枝干/叶簇的 `fir_sapling`、`searsia_lucida`，地面可选 `grass_ground`/`aerial_grass_rock`。这是检索线索，不是固定必用资产。按镜头占屏面积选择1K/2K，保存许可、原始hash、太阳方向和用途限制。

对每个 glTF 做三项轻量验证：主 `.gltf` 能读取、`include` 中的 `.bin`/纹理 URI 都存在且哈希与 API 记录一致、在目标 Three.js 版本中材质色彩空间/法线方向正确。把官方示例或预览截图做成联系表，只用于审美比较；不要把网页示例截图或带水印参考片直接合入成片。

## 风机、浮体和场景交互

- 近景风机至少包含叶片变桨/根部过渡、轮毂、机舱外壳分件、塔筒法兰、基础与海缆关系；远景实例复用同一外部几何，统一轴向和比例。
- 浮式风机使用可解释的浮体（半潜式/驳船/张力腿之一）和系泊线、压载/吃水关系；浮体的水线、浪致俯仰和系泊张力要随波面变化。四角方块或无吃水的“漂浮底座”只能作为示意，并应明确标示。
- 转子气动方向用少量粒子/雾带或流线表示，箭头尖端绑定轮毂/叶片受力点；风线颜色与热图色标分离。风机转动、风浪、影子、反射和标签共用同一绝对帧，不能出现“转子动了但影子/文字留在原地”。
- 机舱剖切先让母层连续变透明，再让发电机、轴承、变流器获得焦点；内部件保持原坐标与深度写入，镜头沿传动链移动。每个标签只指向一个部件，出画后再卸载。

## 玻璃态三维标题与字幕

- 标题优先做世界空间的轻微挤出文字，按背景需要选择透明字面或轻薄玻璃底板；不要把“玻璃态”默认变成一整块巨大透明招牌。底板按实际字面包围盒加边距，检查每行字的顶部/挤出/高光也在边界内。玻璃的模糊、边缘高光和环境反射应克制；文字与底板同一锚点、同一相机运动。
- 玻璃层不应遮住风机关键节点：根据深度和屏幕安全区自动避让叶片、塔筒、海平线与字幕；背景复杂时提高文字对比度而不是加更多字。
- 让标题与水发生一次可读的互动即可：沿水面掠过时出现柔和的折射高光/倒影，波峰只扰动底板和倒影；主字面保持稳定。结尾标题复用同一材质、曝光和运动曲线，不能突然换成平面卡片。
- 统一字体、字重、字号和字距；每个镜头只保留当前动作所需的一个标题或标签。字幕固定在底部安全区，标签跟随三维锚点并避开字幕/Logo。

## 动态标注与镜头

- 需要解释旋转、风向、波向或电能路径时，使用短线段、弧形轨迹、雾带或小粒子而不是大箭头/长文字。轨迹首尾绑定真实节点，颜色只承担一种语义（例如风向青、旋转琥珀、受力红）。
- 转场用同一锚点接力：叶尖→风线、浪峰→玻璃高光、平台边缘→下一镜头的海平线。旧结构先出屏或被前景浪遮住，新结构从可追踪位置进入；检查阴影、反射、标签和音效是否同帧改变。
- 设计焦点时保留缓慢的前进/环绕（常速）和短暂的停留，让观众读懂结构；避免每句旁白都拉到极近或急停。焦点距离绑定讲解对象的真实世界位置，平滑转移的时长由实际片段检验；只模糊非重点层，不能用景深遮住穿模、结构错误或注释。

## 场景 QA 清单

每版至少抽查片头、代表性风机近景、浮体水线、陆地/天空、玻璃标题和结尾：

1. 固定帧号重复渲染，比较 RGB/深度差异；同帧应无随机漂移、海面跳闪和树木闪烁。
2. 观察水线、泡沫、倒影、阴影和透明机舱是否与同一相机姿态对齐；查共面和 z-fighting。
3. 用缩小到手机宽度的联系表检查文字、标签、风线和热图仍可读，且没有遮挡主物体；预览中央 9:16 裁切。
4. 正常速度观看至少一个“入水→水下讲解→出水”和一个“风机→陆地”接力；静帧漂亮但运动中突然出现、消失、抖动或眩晕都算失败。
5. 对进出水点生成轻微水下低通/早反射和咕噜声；核对音频 cue 与真实水线交点，避免仅按时间点硬贴。
6. 记录采用的渲染实现、模型/贴图许可、参数、帧范围、发现和修复；示意水面、风线、泡沫或热图不得写成真实求解结果。

## V6 历史光影与声音参数（不作为最终画质结论）

- 先压住高光再加层次：ACESFilmic，基础曝光约 `.82`；半球光 `0.46`，暖色主光 `#ffe3b0 / 3.55`（约 37° 俯角），低位冷补光 `0.22`，青色轮廓光 `1.05`，HDRI 环境强度约 `.45`。白色叶片必须保留明暗渐变，不能靠整体提亮解决轮廓分离。
- 雾色略低于天空亮度（如 `#a9c7cc`，密度约 `.00021`），用于远景递进；远处风机应比近处更暗、更低对比度。改动曝光后重新检查水面反射和字幕，不要让雾变成一层白幕。
- 浮体的浅色涂层使用高粗糙度、低金属度；压载和裸露钢件使用高金属度深色材质，水线用窄琥珀环。半潜结构由三根外柱、三根有厚度的径向封闭浮筒、中心塔柱、压载和系泊共同组成；避免“黑色圆柱+细杆”。
- 接触泡沫由局部体半径驱动，近体提高 collar 对比度并带顺流尾迹；贴图只在近景启用，中远景用确定性低频噪声。固定帧确认泡沫跟柱脚、浮筒和水线相交，且没有棋盘格重复。
- 入水/出水音效采用固定种子的低频冲击、空气滑动、短混响和稀疏气泡；水下旁白低通约 `2.2–3.5 kHz`，加入 20–55 ms 的早期反射，干湿比例随相机浸没度平滑变化。旁白原始样本、处理后文件和 cue 时间必须分别留存，不能裁剪造成口型/字幕错位。
- 代表帧审看之外，至少正常速度复看一次“海面→水下→出水”和一次“浮体环绕→陆地道路”接力；重点听水线交点是否同时发生声音、低通和画面折射变化。

## V7 原生 WebGPU / WaterPro 接入与已复现问题

2026-10-14 的独立代表场景已实跑 WaterPro 3.1.1 + Three r183，Chrome报告Intel gen-12lp、后端`webgpu`；服务器探针另确认NVIDIA H100 WebGPU。探针成功不代表全片已经完成或在H100上完成渲染。

- **入口与兼容性**：WaterPro要求Three>=r181；统一`three/webgpu`，先`await renderer.init()`，再`WaterSystem.create(renderer,scene,camera,'high',{deterministic:true,seed:7,stepSize:1/60})`。r183使用`RenderPipeline`，`water.postProcessing.buildNode(pass, pass.getTextureNode('output'))`接原生水下效果；不能只调用裸`renderer.render`。旧GLSL `ShaderMaterial`和`onBeforeCompile`须迁移TSL或节点材质，不能假设自动兼容。
- **单位与波纹**：模型、水位、波长统一米。演示预设按公里海域调过，直接套入几十米构件会失真。当前代表镜头起点：FFT波级`scale384/amplitudeScale.16`、细波`36/.028`，Gerstner`amplitude.72/wavelength48`；预设不等于测得海况。`high`与`ultra`的FFT分辨率不同，改变质量档后重新导出水线与音效，不能复用旧交点。
- **3.1.1小种子限制**：原生频谱shader将`seed*100000`加到float32索引。日期形式大种子导致索引精度丢失、同心环和马赛克；本轮使用7。换版本需重新验证，不把随机伪影当真实海浪。
- **吸收与材质**：吸收是每米线性系数，显式`new Color(.075,.034,.018)`避免hex经sRGB转换后近乎透明。关闭满屏surface foam/sparkle，保留深度岸缘泡沫、真实FFT细浪、SSR。折射强度约`.022`，过大产生物体拉扯。水下深处变暗应增加局部潜水照明帮助讲解，避免全局提白破坏水上质感。
- **绝对时间**：`syncToTick(tick)`本身不运行FFT；先同步`tick-1`再`update(1/60)`。水下相机高度采样有一帧延迟，同tick再更新一次以排空延迟。禁用持久foam/wake/spray和随机particles/rain，或另做可回放的固定预滚动缓存；不能仅凭fixed seed宣称所有状态可乱序定位。
- **实时焦散陷阱**：3.1.1原生OceanFloor引用TSL实时`time`。本轮开floor重复帧有小幅像素变化；关闭原生floor后，独立场景`12s→16s→12s`像素差MAE=0/max=0。使用自有海底或将焦散改为绝对时间uniform后再启用；不把该独立测试写成全片跨GPU逐像素一致。
- **天空与水反**：将同一纯天空HDR传给`Sky({equirect,sunDirection})`及世界环境，`water.setSky(sky)`负责PMREM上传。太阳角度从HDR亮斑实测，不能另放不匹配的太阳。克制远景反射锐度，适度提高距离粗糙度避免高光闪烁。
- **音画同步与验证**：用原生`getHeightAt(x,z)`读取当前GPU帧；穿水窗口按60fps采样，远离水面允许明确标注为夹定0/1，但不得伪造波高。记录库/相机/波参数/故事hash、质量档、后端、原始交点与正常速度视听审查。WebGPU FFT、SSR、水下吸收是已运行的渲染能力，不是风机CFD、流固耦合或实测海况证据。
- **共享GPU采样器**：3.1.1 `getHeightAt`复用同一查询位置和buffer，三浮柱查询不能`Promise.all`；逐点await或一次批量提交。浮体变换后刷新反射/折射捕获，避免同帧倒影仍处于旧位置。阴影相机范围和跟随目标随高度平滑变化，不用高度阈值硬切。
- **无头渲染黑Canvas**：Linux H100上WebGPU计算成功、Remotion也可能只截到DOM。先验实际PNG；必要时将最终含水下后处理的RenderPipeline输出至持久RGBA8 RenderTarget，await像素回读后写入显示用2D Canvas，再释放帧门。核实方向、ACES/sRGB未重复、背景不黑。监测Chrome GPU PID对应的实际GPU，不能仅凭`CUDA_VISIBLE_DEVICES`证明图形进程选卡。
- **字幕跨机器一致**：按全文重建WOFF2子集；浏览器CDP核对每条实际字体，缺字或系统fallback不能留到Linux成片。绝对定位字幕显式`width:max-content;max-width:1420px`，测实际DOM宽度和行数，不能只按字数估算。短句可延长到下句前保留阅读时间，覆盖表与导出SRT一致，勿改口播采样或物理时间线。


## 从最终编码复查得到的补充

- 机舱透明度不要直接取两个章节包络的最大值：章节边缘两个包络同时下降，会让前景叶片重新变白。内部连续讲解用独立的开闭区间，保持主体内部可读，再平滑恢复外壳与叶片；透明时同时检查清漆、环境反射和透射，低opacity仍可能产生白色高光遮罩。
- 世界空间文字的入场必须检查实际屏幕位移与主视锥/反射相机。世界坐标平滑不等于屏幕平滑；百米行程塞进半秒会成为跳现。先由屏幕边界求离屏距离，再分配入出时间与完整阅读停留，必要时对少量文字网格关闭视锥剔除，并在水反捕获前刷新matrixWorld。必须看连续编码帧，数值包围盒通过不能代替像素验证。
- 道路边线按路口分段；不能把整条细长几何跨过横向道路。远景检查路面是否被LOD/深度精度吞没，近景检查线与路面高度、交叉口和建筑。
- 最终AAC用整数采样时基：48kHz可采用`asettb=1/48000,asetpts=N`与`-enc_time_base:a 1:48000`。浮点`N/SR/TB`在长片中可能产生1023/1025采样间隔；检查实际packet PTS与duration，不能降低门槛忽略问题。再核对字尾能量与音画相关性。
- 局部修复可按明确的全局帧闭区间重渲，再以帧索引替换并统一编码。保留基线、补丁输入、冻结hash和拼接表，逐一看接缝前后帧；不靠模糊或插帧掩盖几何/曝光差异。最终必须重新跑完整解码、音轨同步和帧异常检查。

## V8 经过复现的改进

- **WebGPU错帧先查截图竞态**：仅在React被动`useEffect`注册`delayRender`，可能在Remotion已释放seek锁之后才提交GPU帧。一次11点实际截帧复现了2张陈旧图。改在`useLayoutEffect`登记帧锁，串行GPU更新与回读，generation取消过时请求，独立scratch canvas完成后原子拷贝到显示canvas；同序列0错帧。生产截图前后同时验证请求帧、显示帧、原生tick和像素摘要，不能只验证ffprobe帧数。未证明旧片错帧范围时整片重渲。
- **音频换气不等于运镜停顿**：两个章节共享同一姿态时，不在短暂句间空隙两端重复插入该姿态，否则约0.22秒会被插成7帧停住。合并共享接点，按实测旁白时间连续插值；再测有限值、随机seek和静止区间。
- **真实光追的范围要说清**：可以用Blender Cycles/OptiX烘焙接触遮蔽并保持glTF节点层级；合并远景模型时保留AO使用的`uv1`，不能只带`uv`导致纹理失效。此法属于光追烘焙+WebGPU动态光影混合渲染，不能称整片路径追踪。
- **浮体按拓扑建模**：三外柱+中心柱、三角外围浮筒、径向上梁与斜撑分别核对。教学适配的尺寸和真实OpenFAST/OC4参数应区分；不把外形参考称为认证设计。实际入水轮廓、吃水、系泊和镜头可读性需一起检查。
- **草木不能只下载就算真实**：先看原始albedo是否干草/枯叶，再避免暗材质重复乘色；有色调处理另存衍生图及provenance。远处叶片需检查alphaTest、mipmap和覆盖抗锯齿，不能把近景有叶、远景秃枝留到成片。
- **文字材质优先可读**：轻挤出浅色字面+克制暗侧面可比高金属玻璃更适合海天；字形接收自身阴影可能出现黑裂纹。逐实际顶点检查进出画时刻、反射和屏幕速度，再看GPU图片。按讲解仅出现一条成果及团队短信息。
- **载荷/监测标记绑真实网格**：从叶片顶点法线取表面点，作为叶片子节点；切向力用旋转轴×径向向量确定，根中尖监测点随转动与变桨。示意压力颜色不能标成CFD实算。
- **亮天空前的字面与侧面分工**：实际GPU图里，深色物理材质会被HDR和雾抬成灰，浅色片尾大字也会融入天空。可让天空前字面采用稳定深海蓝 `MeshBasicMaterial({fog:false,toneMapped:false})`，侧面/倒角继续受光；深海背景改象牙白，水下另按吸收距离验证。先看原始分辨率和手机缩图，再固定材质，不能只凭色值断言对比够。字仍保留真实世界深度、遮挡与镜头运动，不改成覆盖画面的DOM卡片。
