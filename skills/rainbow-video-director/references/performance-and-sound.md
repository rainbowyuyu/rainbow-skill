# 语言表演与声音导演

用于旁白生硬、音色怪异、音乐盖词、音效堆满，或需要重写配音与声音提示词的任务。声音帮助观众分清发生了什么，也让宏大画面有安静的落点。提示词先描述想听到的效果，实现附录才约束实际后端参数。

## 两张谱，一条主时钟

完整分段提示词先写要说的准确句子和要听见的声音。复杂项目的声音协作可分为语言配音 VA 与音效 FX。VA 管正文、发音、情绪、自然音长和字幕；FX 管画内声、设计音、环境和音乐交接。两者都消费主契约事件，不各自调整物体动作或全片时间。

- `voice-score.json`：cue ID、标准显示稿、实际朗读稿、说话任务、表演指令、关键词、前后语境、计划窗口与语义事件。
- `sfx-directions.json`：声源及位置、实际触发事件、声音起点/同步点/尾音、音乐和旁白避让、素材与试听状态。
- `audio-fusion.md`：按语句/动作段记录听觉焦点、音乐与其他轨道交接、字幕和动作词的对应；无旁白处写观众要听清的动作或音乐乐句。

这些文件可合并进现有项目表，不强建重复数据源。局部声音提示词也可以一份Markdown交付，保留上述字段和前后文，不要求补写无关四层或运行整包验证。有既有表就补入同一来源，没有则按段落写清即可。原音乐身份、片内时间、源曲时间、真实语音采样位置分别存储。任何时长改变先报主导演，再同步受影响层。

## 说话任务先于情绪标签

先完整读懂这一段的因果。以完整语义段为录制/合成单位，段内句子只标必要的轻重与换气；不要把逐句导演谱机械变成逐句音频文件。具体方法见 [连贯配音](connected-narration.md)。每句选择一个主要任务，相邻句形成推进，不要求每句独立表演高潮。

| 任务 | 具体可听效果 | 配合画面 |
|---|---|---|
| 提问 | 起句直接，疑问词提亮，按语义轻停 | 先让现象成立，问题落在已看见的矛盾上 |
| 解释 | 一个因果说完整，术语连读，结尾落稳 | 公式与实体都给观察时间 |
| 对照 | 两个对象有轻重差异，其余词自然带过 | 同尺度、同机理，变化次序与口播相同 |
| 揭示 | 结果词短暂提亮，随后回落 | 结果确实发生后才确认 |
| 推进 | 句中逐渐集中，完整收尾后把空间交给音乐 | 动作蓄势到结果，不催促错误物理时间 |
| 收束 | 声音温暖、正常声量，句尾自然完整 | 落在具体的人、物体或结果上，保留余味 |

每句通常一个主重音，对照句最多两个。表演指令写“七千米连读；数字落稳后停半拍”，不要只写“极度震撼”。半拍是表演方向，若需准确时间，必须在真实音频产生后安排。不要把科学审查备注、镜头描述或“第46秒说完”全部塞进模型指令。背景语境保存在导演字段，只有接口确实接收的内容才声称已提交。

正文、标准字幕与读音辅助分别保留。多音字建立带整句语境的核查表；自然改句或后端支持的读音控制只能在确认正确后使用。ASR 同字不证明声调正确。不要按字拼接多种音源、压缩字尾或用换采样率制造慢速。

成稿清理按当前 `lieflat-less-ai-tone` 的真实规则处理，保持原事实、限定和来源。新的叙事重写要有用户授权；不靠添加感叹词、虚构危机和夸大数字制造情绪。

## 将导演意图落到确实可用的后端

读取当前 TTS 项目的用法与实际入口，核对用户最新的声音选择。演示、服务启动、个人音色、情绪执行与全片听审是不同状态。前一聊天说“准备部署”不等于可用；只写提示词时可记录 `pending_verification`，不必为写稿生成付费样音。

用户2026-10-31明确要求后续TTS使用原本地Qwen本人声音。按 [运行环境](runtime-environment.md) 定位已安装的Qwen配音技能及TTS项目，先读该项目的 `QWEN_NARRATION.md`。模型是既有Qwen3-TTS-0.6B Base，参考为原 `work/clone-reference.wav` 与匹配JSON，入口 `qwen_local_voice.py`；`expressive_voice.py` 默认也路由本地Qwen。Base没有已验证的instruction/emotion/speed/CFG/SSML控制；角色、重音和语速只作为编辑与听审意图，不声称已传给模型。通过自然口播、完整语义段和有限候选改善表达，以原速听审为准。只写提示词时可离线plan，不加载模型或生成样音。

只有用户明确选择Breeze时，才使用以下保留的Breeze接口说明；它不再是全局默认。

官方源码所列 Voice Direction 可同时使用参考声音、准确参考稿与自然语言 `instruction`，该 Breeze 模式默认CFG 4；Voice Clone 用于同文身份基线，不传instruction、CFG 1；Voice Design 不代表本人声音。自然语言的情绪、语速与重音意图不等于数值保证。当前官方接口没有通用 `emotion`/`speed`/SSML 字段，不把旧供应商参数套用进去。CFG 是生成控制，不能当音量或情绪强度旋钮。版本或接口更新时核对当前官方与封装。

部署未验时先完成中立的逐句表演谱；映射和正式合成等待证据。不可在没有用户选择的情况下退回云试用音色或被禁用的 Fish。本人参考和凭据不进入导演包。新后端缺少能力时保留未实现项，不能给未变化的音频贴新情绪标签。

实际制作先用有代表性的同文短样比较身份与表演：提问、数字术语、完整机理和温暖收束。先原速干声、再同响度混音。只对确实有问题的 cue 重做完整语义单位，保留原始候选和选择理由。有限次数无改善时换指令/分句方法或报告局限，不能无限重试、自动换供应商。

## 音效与视听空间

为每个声音标记 `diegetic`（画内来源）、`designed`（剪辑设计）或 `sonification`（数据听觉化）。写清观众处于哪里：舱内听到的风机与艇外水流不是一个空间；摄影机绕着静止机器转动，不意味着机器在飞。科学演示的回波声可以是可听化提示，不能冒充仪器原始录音。

动作开始、最近点、接触和完成是不同事件。声音也有起音、内部同步点与余音，使用：

`声音放置时间 = 实际事件时间 + 合理偏移 − 素材内同步时间`

没有素材时后者填 null；计划峰值不能冒充已测素材锚点。同步峰对实物事件，不按音乐强拍移动物理接触。重拍不合时调整音乐剪法、剪辑表现或删掉额外冲击声。

持续机械声读取实际工作状态，只在需要交代动作时突出。一次确认触发一次，不给每个粒子/数字/字幕字配声。声音退出写原因：停止工作、离开听域、下一个术语开始，或作为明确的声音桥延续。安静有用途；不要全片铺强嗡鸣，也不要每镜切断环境底。

分段稿与声音谱共用唯一事件清单。分段稿提到“轻点、回声、确认”时核对它是否已有cue，避免在新细则之外残留另一套声音；连续环境单独写空间段和交接，不因每秒有一行就重复触发。新的声音先登记来源和语义再同步所有合并稿。摄影机进入舱内、实体触水、听者穿过水线可能是不同事件，声场按实际视点交接。

先查现有音效库。需要新素材时使用当前 `rainbow-suno-sound-effects` 与官方契约：Suno 适合音乐性蓄势、氛围、转场候选，不能保证精确拟音或专用 text-to-SFX。精确接触可以选有许可录音或明确标注的程序设计音。TTS 的情绪指导不等于 SFX 模型。按用户指定中央库归档，工程仅引用路径/哈希/同步点；只写提示词不提交生成任务。

具体选路、检索词、候选比较、来源归档与混音顺序见 [音效选材、生成与落画面](sound-sourcing-and-mix.md)。本机已安装 `sound`，用于 Freesound 搜索与MP3预览下载；它补充具体拟音，不替代苏诺生成与当前Qwen本人旁白。选择时保留实际声源、动作次数、材质和尾音依据；热门程度不代表适合当前画面。同事件分层需写body/texture等角色，缺素材时保留null，不虚构已生成或已试听。

方法参考：`rainbow-motion-story/assets/style-lab/guides/sound-design.md`、`guides/shuffle-rhythm.md` 和 `references/music-led-edit.md`。迁移的是声音为何出现与何时退让，不能采样参考视频未获许可的音轨。

## 原音乐和语言的呼吸

保持用户选曲。源曲不够长时用可自然衔接的乐句规划，标出源曲区间和重叠；自动能量峰只筛候选，接缝须听审。逐句声量不全程激昂，音乐高潮可交给完整动作，复杂机制解释时主奏退后。

实际文件分析、局部速度、乐句选择、延展EDL与代码消费方式统一见 [随曲编排](music-adaptive-direction.md)。用户每次提供的音乐都是本片节奏依据；不要套固定120BPM、默认八秒展示或全程呼吸缩放。更换BGM要重新核对源时间与镜头/公式/字幕窗口；测量与听审分开，保留本人Qwen自然语音，音乐围绕完整语义句让位。

给句头提前让位、词间保持、轻声尾字后延迟恢复，避免逐字抽吸。优先错开高频瞬态与术语；已经与音乐击打重合的动作可不加音效。旁白、BGM、效果和环境分轨保存，整体响度达标不能证明讲解清晰。

先记录片长是硬上限还是近似目标。真实旁白更长时，保留完整发声和安全尾部，再调镜头、字幕与音乐映射；保护留白窗和物理事件如需变动，由主导演联动裁决，不能靠拉伸人声“维持原定片长”。硬上限内优先删授权范围内的冗余、调整非关键停留、重新分配讲解预算，保护最低观察时间与必要知识；不能自动加长全片或吃掉全部留白。近似目标可整体重排，但仍说明变更理由。无法同时满足时如实列出冲突与可选取舍。

## 设计与实际验收

按质量检查的具体问题逐条查看：本人声音要求是否可执行、表演是否有上下文、术语与完整句是否保护、科学事件是否同源、音效有无来源/退出、音乐是否给解释和展示分别留空间。参数齐全不表示听感通过；不要求填写分数量表。

制作阶段记录 `deployment_verified / synthesis_checked / pronunciation_checked / subjectiveListeningChecked / final_mix_listened` 等独立状态。未查用 null 或 not-checked，明确范围与文件 SHA。先干声，再声音与动作，再加入原音乐，最后检查最终编码及字幕。连续播放所有关键过渡，并看听前后至少一句；静帧与波形不能证明语言自然。听审条件缺失就保留待验，交付设计不应伪装成新音轨完成。

全片本人声音项目另检查 `all_speech_provenance_checked / single_personal_reference / foreign_speech_sources / background_vocals_checked`。新闻片、引用片、转场素材和音乐/SFX 都列入可闻语音清单；`foreign_speech_sources` 必须为空，或有本轮明确例外授权。保持同一基础音域、口音和近讲距离，情绪改变只服务句意，不在章间切换成播音员、耳语者或另一角色。此来源门槛不能代替 `voiceIdentityChecked` 的实际听审。
