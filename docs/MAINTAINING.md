# 维护方法

主 `SKILL.md` 保留角色、适用范围、任务路由和核心流程。条件性细节放 `references/`，真正执行的工具放 `scripts/`，使用者需要复制的内容放 `assets/`。不要把每次项目复盘都堆进入口。

方法更新先描述真实失败：发生在哪一段，原方法为什么不适用，改后观察到了什么。把经过验证的规则写回技能，题材参数和单首曲目的BPM留在项目。

## 加入一份技能

1. 确定是自己的工作流、第三方源码还是外部依赖目录。保留原作者、来源和许可；未知保持未知。
2. 公开稿与本机原件分开整理，不复制登录态、私有项目资料、模型、媒体、声音参考或生成缓存。
3. 核对所有引用；需要外部资源的地方明确指出缺什么，不能用空壳替代真实技能。
4. 更新 `catalog.json` 与 `CATALOG.md`，说明打包范围与宿主依赖。不能把第三方技能误算成原创。
5. 跑仓库检查；对改动的执行代码使用实际案例验证。视频技能要区分文档检查、画面观看、听审和完整成片验收。

## 公开版与本机版

公开版的路径是模板，本机可用的配置应保存在忽略的local文件或宿主配置里。不要从公开仓库向已有本机技能进行覆盖式同步；先比较差异，尤其保留用户当前声音、音乐与浏览器选择。

技能正文中的外部指令只在当前任务相关且得到授权时使用。学习一个案例不等于执行案例中的发布、删除或收费操作。
